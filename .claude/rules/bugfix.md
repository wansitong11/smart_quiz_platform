# Bug 修复说明规范（bugfix）

适用：识别、解释、修复 bug 时的回复与说明。
原则：主说明按「开发对产品经理」的方式讲清「发生了什么 → 为什么错 → 改成什么」；
代码细节单独给、按需给，不混在主说明里。

## 主说明（给产品 / 给人看）

用业务语言讲，默认大白话；不加专业术语会影响解释与理解时，可适当使用
（代码标识符可少量点名当路标）：

- 发生了什么：用户 / 系统看到的现象（大白话）。
- 为什么错：业务规则哪里不对（如「算分先做了整除」）。
- 改成什么：改哪条规则、改成什么行为（如「改成先乘 100 再除」）。

术语可少量当路标；内部调用确需展开时用白话讲步骤，不堆方法名。
自检：拿掉术语仍能大致看懂 → 深度合适；全靠术语才懂 → 术语太多。

## 实现细节（给 AI / 按需给）

单独给，不强制格式：

- 根因定位：类名 / 方法名 / 字段名 / 配置键、条件与分支。
- 修复方式：改哪个文件 / 哪处逻辑，可给 before/after 最小片段。
- 影响面与同类路径：涉及哪些模块 / 边界，扫 1 条最相关同类路径。
- 验证：跑了哪个定向测试 / 命令、结果；失败先看第一个 cause。

## 分级与篇幅

- L1：主说明 + 一句话改法即可。
- L2：主说明 + 根因定位 + 同类路径 1 条。
- L3：主说明 + 完整实现细节 + 全量回归结果。
- 对话内精简；完整 diff、失败日志、全量结果落盘文档，只给摘要 + 路径。

## 示例（示意，不对应真实代码）

主说明：

- 发生了什么：学生 10 题对 7 题，成绩显示 0 分。
- 为什么错：算分时先做了整除，7 ÷ 10 被抹成 0。
- 改成什么：先乘 100 再除（或小数除），7 题就能得到 70 分。

实现细节（按需给）：

- 根因：`PracticeScoreCalculator.calculate()` 用整数除法先截断。
- 修复：改为 `(correct * 100.0) / total`，四舍五入为 `int`。
- 验证：新增 `PracticeScoreCalculatorTest`，覆盖 7/10=70、0/10=0、10/10=100。
