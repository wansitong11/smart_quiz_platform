# RAG 检索相关性筛选：实施与验证记录

日期：2026-11-13。对应设计：`docs/design/RAG检索相关性筛选与保守改写-设计稿.md`。

## 结论边界

代码已加入保守改写与前置相关性筛选，算法实现和普通回归通过；两轮真实模型测评均发现新问题仍会混入无关资料。
因此本轮结论是“实现完成，当前分数启发式尚不能可靠解决跨资料污染”，不是运行启用完成。
筛选保持默认关闭，未将任何一轮的失败参数写入 `.env` 或替换默认值。
最终全量回归：918 个用例，870 个实际执行通过、0 失败、0 错误、48 个既有跳过。
包含“筛选后交给生产组装器补邻”的最小重放测试；新增筛选测试 14 项、配置和模板测试 4 项均通过。

两轮都执行了开发题校准和全新留出题验证：V1 为 18/18、9/12，V2 为 30/30、9/12。
两个 9/12 是小样本重复观测，不代表线上正确率。失败题三次均有必要原文，但也三次带入禁止来源。
未执行启用后的 admin 新消息验收，也未宣称当前 IDEA 进程已启用筛选；不能以单测绿或历史请求代替这些证据。

## 发生了什么 → 为什么错 → 改成什么

以前向量检索召回了一条较弱的技术资料，跨资料保底仍可能给它名额，即使数学候选分数更高；
改写又可能把数学问题扩成更泛的领域。技术片段于是进入上下文，按直接命中列为出处。

现在先检查用户权限，再按最低分和相对最高分落差筛选，保底只在剩余候选内分配；
筛完不满数量也不补回弱结果，改写筛空时仍会回退原问题。
改写模板只补明确指代，不要求因问题较短就扩写。

原文补邻不参与分数筛选：它没有独立向量分数属于正常现象。补邻、6000 token 预算、上传切分和向量数据均未改。
这仍是分数启发式，不保证所有通过的片段一定有答案，也不实现逐句引用校验。

## 复现与自动化证据

先运行固定候选的服务入口测试，旧逻辑出现预期失败：检索数学却返回资料 ID 23。
初次测试夹具缺资料名称服务，修正夹具后再次得到业务断言失败，才修改生产选择逻辑。
失败日志：`.codex-tmp/rag-relevance-red.log`。

新增用例覆盖：

- 分数过低、单库、少于 topK 不能跳过筛选；不回捞被剔除候选。
- 等于门槛保留、零落差、最大落差、并列分稳定顺序。
- null、NaN、无穷、负数、超过 1 的分数不得由 metadata 兜底变成合格分。
- 授权外的高分不抬高门槛；多份相关资料仍可共同保留。
- 改写筛空后回退原问题；已有合格命中则不多搜；改写异常或空白不会关闭筛选。
- 双路只在融合池计算一次门槛，非法分数不能在同 UUID 合并时覆盖正常值。
- 同步、普通流式、工具入口都执行筛选；工具化预检索不把拒绝片段注入回答提示词。
- 数据库补邻文档 score=null 不被二次筛选。
- 追加的最小重放使用真实日志分数和缩短的数学步骤夹具，接生产组装器补前一块。
  它不是当前真实数据库重查，不能当作实际 admin 消息验收。

开发中的失败均为新增测试夹具/断言接线问题，已修正；没有为解决它们放宽生产门槛或修改其它业务逻辑。
普通单测不调用真实模型。

## 两轮参数校准与留出结果

没有在测试里复制筛选公式。每轮只在 dev 上选择参数，不以本轮 holdout 结果重新挑选。

### 失败题具体发生了什么

V1 H4 的 Spring AI 最高分约 0.631626，而数学候选最高约 0.455015，
0.35 / 0.25 的门槛仍允许数学片段进入上下文。

V2 H3 的问题是“资料检索增强问答中，文档分割和向量化分别负责哪一步？”。
一次实际运行的直接命中如下（三次都有数学污染）：

| 资料 / chunk_index | 向量分数 |
| --- | --- |
| Spring AI / 1 | 0.624471 |
| 数学 / 28 | 0.553162 |
| 数学 / 15 | 0.523897 |
| 数学 / 34 | 0.522732 |
| 数学 / 27 | 0.520495 |
| 数学 / 35 | 0.516206 |
| 数学 / 14 | 0.514835 |
| 语文 / 1 | 0.476741 |

冻结参数 0.35 / 0.15 算出的门槛为 0.474471；这些数学分数都高于门槛，代码按设计保留它们，
之后照常参与保底和组装。最终上下文 5565 token，超预算跳过计数 4，lookupErrors=0。
因此这次不是找不到原文、补邻异常或超出 6000 token，而是“向量分数较高”不等于“能回答这个问题”。
不能通过扩大预算、过滤邻居或按资料名屏蔽数学来修复这一判断缺口。

### 已证实的改善与不能归因的部分

- 原始颜色/条纹数学问题 D1，两轮新改写 + 新筛选均三次无 Spring AI 污染，必要原文都在。
- V2 D1 即使关闭筛选，只用新改写也三次没有 Spring AI 污染，不能把改善全部归功于阈值。
- V2 D3 的一次新改写为“制作扇形统计图的四个步骤是什么”，直接命中数学块 34/35/33/30/31，
  补邻为 32/29，上下文 4872 token，四步原文齐全。34、35 均为直接命中，不能把这条记录说成“35 是补邻带回”。
- 普通单测证明无分数邻居不会被二次筛掉；本次真实测评未单独完成“仅命中 35，再补入 34”的受控重放。
  设计引用的历史受控证明仍是历史证据，不替代本次新筛选开启后的真实重放。

## 下一步建议与范围边界

不追加第三轮阈值试错，不启用任一失败参数，也不新增资料名黑名单。保留现有实现及失败测评作为可复现基线。
下一步建议是单独设计候选相关性复核/重排：向量分数先做便宜的粗筛，再判断片段是否真正提供本轮问题的证据，
而不是只换一个固定分差。需重新明确模型成本、延迟、失败回退、多资料保留规则，再经设计确认后实现；
这不在本轮已批准的“无新增模型调用”范围内，尚未擅自实现。
