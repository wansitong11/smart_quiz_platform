# RAG 检索相关性筛选与保守改写

日期：2026-11-13。状态：主体逻辑已实现、普通回归通过；两轮真实留出均为 9/12，存在无关资料污染，筛选保持关闭。
实施与验证证据见 `docs/design/RAG检索相关性筛选-验证报告.md`；本文不作为效果通过报告。

实施结论：V1 在开发题上选中 0.35 / 0.25，V2 扩充开发题后选中 0.35 / 0.15，
但两轮各有一道全新技术留出题三次混入数学片段。按 G.5 的停止规则，不追加第三轮自助调参，
不替换默认初值、不改 `.env`、不进入启用后的 admin 消息验收。后续相关性复核/重排需另行确认设计，尚未实现。

本方案承接《RAG切分语义连续性-设计稿.md》和《RAG-admin会话13-上下文关联核验.md》，只解决本轮确认的“无关资料被检索保底带入，以及改写扩大主题”问题。不重新设计切分策略。

## 一、先看使用结果

用户选择“全部资料”，问“用不同颜色或条纹把各个扇形区别开是什么意思”：

1. 不再主动把问题扩写成“数据可视化或图表制作”等更大的领域。
2. 先召回候选，然后剔除分数不够、或明显落后于本次最好候选的片段。
3. 跨资料保底只能在剩下的候选里挑选，不能因为某份资料还没出场，就把已剔除的片段捞回来。
4. 数学片段照常进入原文组装器，补入同资料、同代次的前后相邻块。上下文预算仍为 6000 token。
5. 筛选后不满原来的命中数量也可以；全部不合格则走现有无命中路径，不为了凑数塞入 Spring AI 资料。

当用户真正问 Spring AI 时，不根据资料名拦截它；它和数学资料接受同一套分数规则。真正需要两份资料作答、且两份证据都达标时，仍允许同时进入。

## 二、发生了什么，为什么要改

### 2.1 已有语义连续性能力不推倒重来

当前工作区已经有章节切分、资料名和章节路径写入、同代相邻块回填以及上下文诊断。admin 会话 13 的正常搜索工具请求已经实际补入数学片段 35；受控重放也确认只命中 35 时能够补入 34，并按原文顺序展示。

因此，“无关 Spring AI 出处”不是相邻原文读错了，也不是 Spring AI 框架把另一份资料当成数学邻居。它在进入补邻之前就已经被作为直接命中选中了。

### 2.2 两个会放大问题的现有规则

第一，改写提示词要求给过短、过泛的问题补充语义。原问题已有“扇形、颜色或条纹”，实际改写却新增“数据可视化或图表制作”，扩大了检索主题。

第二，现有跨资料选择会先给候选资料保留名额，然后按分数补齐。这个过程缺少额外相关性门槛。受控测试已经证明：即使九个数学候选都比一个 Spring AI 候选高，后者仍可能通过保底进入最终八条。

原请求完整的 24 条候选没有保存，不能声称已还原其准确全局名次，也不能把所有影响归因于保底一个因素。可以确定的是：该无关片段被召回、被选入、进入了模型上下文，最后又按直接命中生成出处。

### 2.3 不是修改 Spring AI 库

本次优化放在本项目已有查询服务内：向量库负责召回，本项目负责决定哪些候选有资格进入上下文。不开新模型、不修改依赖、不为数学或 Spring AI 写专用黑白名单。

| 类型 | 本轮决定 |

不增加事务，不把模型或向量调用移进数据库事务；不改 Redis Stream 或上传异步状态。新增筛选在内存中完成，不额外调用模型或数据库。

## 四、规则与处理步骤

### 4.1 改写只补指代，不补想象的背景

目的：让“制作它”能找到“制作扇形统计图”，但不把已有明确主题的问题扩成更宽的技术领域。

执行规则：

1. 能独立理解的问题尽量原样保留；短不是扩写的理由，例如“圆心角”“OAuth2”不扩写。
2. 有明确对话背景时，只替换本轮缺失的指代对象和必要省略。例如上轮在讲扇形统计图，本轮“制作它的四个步骤”，补成“制作扇形统计图的四个步骤”。
3. 历史里没有唯一可确认的对象，就保留原问题，不让改写模型猜测领域。
4. 保留原问题的限定、否定、数字、单位、专有名词，不把例外条件省掉；不能拿助手此前的猜测当成资料事实补入。
5. 改写调用失败或返回空白时，沿用现有原问题回退。不增加第二次改写模型调用。

实现上替换现有提示词，不改模型选择方式；仍通过已有客户端调用一次。该规则是提示词约束，不声称它能从算法上证明每次改写都语义等价；用真实模型重复测试覆盖这一风险。

### 4.2 先检查范围，再计算相关性门槛

先取得用户当前可访问、已经完成向量化的资料范围，再从召回结果中过滤越权来源。相关性门槛只能参考授权范围内的候选，不能让一条越权的高分片段抬高门槛、挤掉用户自己的资料。

保留现有空范围行为：没有可访问资料时返回空结果，绝不能把空 ID 列表当成不限范围。

### 4.3 候选必须同时过两道门槛

向量分数不是正确率。这里使用它做便宜、可解释的启发式筛选，不能把“通过门槛”称为“已证明与问题语义相关”。

对一次候选池，取授权范围内、分数有效候选的最高分。每个候选同时满足以下条件才保留：

- 不低于固定的最低分数。
- 与本池最高分的差距，不超过允许的最大落差。

例如使用**待验证初值**最低分 0.40、最大落差 0.20，最高分为 0.6824，则本池实际门槛为 0.4824。原日志中的 Spring AI 片段约为 0.4117，会被剔除；列出的七个数学片段最低约为 0.4926，会保留。

这只是对已记录分数的算术说明，不是新改写上线后的效果承诺。改写变化会带来新的候选和新分数，必须重新测。

固定最低分用于避免“全池都很差但彼此接近，所以全部通过”；相对落差用于避免“虽然超过很宽松的固定线，但比主要证据弱很多”。两个条件缺一不可。

边界规则：等于门槛时保留；不四舍五入后比较。不满八条也不补弱片段；只有一个候选或只有一份资料时照样筛选。没有有效分数的直接候选不获得保底资格。

### 4.4 筛完再保底，保底不再意味着无条件出场

将通过门槛的候选按分数降序交给现有跨资料均衡逻辑。每份资料的保底数量保持现值，但只对合格候选有效：只有一条合格就最多给一条，没有合格则不给名额。

跨资料均衡不是每份资料的数量上限，也不保证所有合格资料都一定能出场；最终仍受总名额限制。相关性筛选不会引入按题目类型另选资料的规则。

### 4.5 原问题回退与双路融合

默认仍是“先查改写，改写没有有效命中再查原问题”，不自动开启双路检索。

- 改写召回有结果，但筛完为空：视为没有有效命中，继续原问题回退。
- 改写筛完还有结果：按原逻辑采用这一路，不额外查询原问题。
- 两路都为空：进入现有无命中分支，不回捞被剔除候选。
- 显式开启双路融合时：两路先按向量 UUID 去重、同一块保留较高有效分数，再对融合池计算一次门槛，最后保底。不能先分别筛选再合并，否则会出现两个不同的最高分基准。

不同 query 的余弦分数未必完全可比；此处沿用当前最大分融合约定，不把本次变更包装成新的融合算法。双路默认关闭保持不变。

### 4.6 补邻、预算与出处

筛选只针对向量检索的直接候选，不对原文邻居运行分数筛选。邻居从数据库按同资料、同代次、相邻序号读取，没有独立相似度分数是正常情况；如果也要求它过分数门槛，会把本来要补的语义连续性再次破坏。

筛选后的直接命中才进入现有组装器；组装器依旧检查权限、代次、预算、去重并恢复原文顺序。仍不截断正文，不扩大预算，也不保证每个被召回的邻居都能装入。

出处沿用现有保留命中收集规则。被筛掉的片段不能进入新的直接命中和出处集合；但不会删除历史消息已经保存的出处，也不会保证保留下来的每份资料都被答案逐句使用。句级引用验证属于另一个问题。

工具可能在一次回答中多次检索，各自使用自身池的门槛；本次不对多次工具结果做额外全局重排。

## 五、如何验证，不靠“回答看起来对”

分三层验证，分别回答不同问题：

1. **固定候选测试**：给定明确分数，检查规则是否在所有入口生效，弱候选是否不再被保底拉回。它证明实现正确，不证明模型质量。
2. **冻结候选对照**：同一批真实召回分别套旧、新选择规则，隔离“筛选本身”的影响；同时独立对照旧、新改写，避免把两项收益混在一起。
3. **真实问答验收**：使用正常登录的 admin 会话、真实模型和全部资料范围，看最终上下文、补邻和新消息出处。不能只看答案文本或一条最高分。

必须覆盖以下业务：

| 场景 | 期望 |
| --- | --- |
| 原来的扇形颜色/条纹问题，全部资料 | 数学证据存在，Spring AI 片段不进入本轮上下文和新出处 |
| 追问“制作它的四个步骤” | 对象还原为扇形统计图，步骤 1–4 的原文证据齐全 |
| 折线统计图时间间距 | 原文间距规则保留；不以此题必须补入片段 35 作为答案正确性的条件 |
| 真正的 Spring AI 检索/嵌入问题 | Spring AI 资料可以正常进入，不被按名字屏蔽 |
| 两份资料共同描述同一主题 | 两份证据达标时都保留，不被误改成“单资料模式” |
| 条件和结论分处两块 | 一块作为直接命中，另一块仍能通过现有补邻进入 |
| 含关键词但知识库没有答案 | 不把含同词当成有答案；明确区分“筛选无命中”与“有相关片段但无所问事实” |
| 短词、数字、否定、接口名 | 不因保守改写丢失检索词或限定 |

超出知识库的问题可能仍与已有片段相似。本方案不保证全部库外问题都零命中，更不替代回答模型的证据判断；报告要分别记录检索结果和最终是否编造答案。

## 六、参数与发布策略

初值定为最低分 0.40、最大落差 0.20，作为可运行的候选配置，不宣称已经校准。Java 与 YAML 使用同一初值，筛选默认开关为 **false**。开发验收时显式开启；只有通过附录 G 的校准与留出集门禁，才在当前环境 `.env` 中设为 true。

不把未经验证的筛选默认开启给所有环境。验收交付应同时包含“功能已实现”和“本地实际运行已开启并验证”的证据；不能只添加一个默认关闭的开关就宣称用户问题已解决。

新增三个配置：启用筛选、最低分、最大落差。修改后重启后端，前端和资料均不用重建。若门槛过严，可能损失真实证据；不能用偷偷取消筛选、补入弱结果来掩盖，应按校准流程选择参数并重测。

紧急回退将筛选开关设为 false 后重启，恢复旧候选选择。保守改写独立保留；若也需回退改写，关闭现有改写开关即可走原问题，而不是恢复扩写提示词。

## B. 配置、校验与生命周期

`KnowledgeBaseQueryProperties` 继续使用 `@ConfigurationProperties(prefix = "app.ai.rag")` 和 `@Validated`。在 `private Search search = new Search()` 上补 `@Valid`，`Search.relevance` 上加 `@Valid` 和 `@NotNull`。不要顺便给其它存量配置增加新限制。

在 `Search` 中加入 `private Relevance relevance = new Relevance();`；`Relevance` 是带 Lombok `@Data` 的 `public static class`，与现有嵌套配置同级。新增代码按 2 空格缩进。

| 完整键 | Java 字段 | 类型 | Java / YAML 默认值 | 环境变量 | 校验 |
| --- | --- | --- | --- | --- | --- |
| `app.ai.rag.search.relevance.enabled` | `enabled` | boolean | false | `APP_AI_RAG_RELEVANCE_ENABLED` | 无额外校验 |

## C. 分数合同与核心方法

本模块收到的是 Spring AI `Document`，向量直接候选只使用 `Document.getScore()`。允许有限的 [0,1] 值；null、NaN、正负无穷、负数、超过 1 都视为无效分数。不从 metadata 的 `distance` 或 `score` 猜测相似度，不修改现有用于展示的 `extractScore` 方法。

当前 pgvector COSINE 召回线为非负；如果未来接入其它分数域，应先修改适配合同和测试，不能在查询服务中把距离偷当相似度。本合同不适用于数据库补邻返回的无分数文档。

新增以下方法，不新增组件。筛选方法和选择方法为包级，供同包测试直接验证；分数检查私有静态。

```java
private static boolean hasValidRelevanceScore(Document document)
List<Document> filterRelevantCandidates(List<Document> candidates)
List<Document> selectCandidateDocuments(List<Document> candidates, int topK)
```

`hasValidRelevanceScore` 输入一个候选，输出上述分数合同是否成立；无 I/O、无副作用。`document == null` 返回 false。

`filterRelevantCandidates` 输入已经过范围授权的候选，输出符合本池门槛的稳定降序列表。仅本方法记录筛选统计，无模型和数据库调用。算法完整规定为：

1. null 或空列表返回 `List.of()`。
2. 筛选关闭时返回原候选列表，保持旧排序、旧空分数处理和旧数量，不做额外整理。
3. 筛选开启时，排除无效分数；稳定按 `scoreDescendingNullsLast` 降序排序。
4. 没有有效候选时返回空；`topScore` 和 `effectiveMinScore` 记录为 null。
5. 有有效候选时：`effectiveMinScore = Math.max(relevanceMinScore, topScore - relevanceMaxScoreDrop)`。
6. 保留 `document.getScore() >= effectiveMinScore`，不加 epsilon，不格式化小数再比较。
7. 输入中重复 UUID 不由本方法负责合并；单路沿用向量库 UUID 唯一合同，双路由融合负责去重。
8. 开启时每次调用只写一条 INFO 统计：`enabled=true, candidates, invalidScores, topScore, effectiveMinScore, passed, rejected`。`rejected = candidates - passed`，包含无效分数。统计不含问题正文、片段正文、UUID 或密钥；不新增动态 Micrometer 标签和持久化列。

`selectCandidateDocuments` 输入授权候选和原有 topK，返回 `balanceByKnowledgeBase(filterRelevantCandidates(candidates), topK)`。topK 使用现有正数档位，不由此方法改档；不新增截断正文、补足数量、二次搜索或按资料名筛选。

`balanceByKnowledgeBase` 算法和包级签名保持原样。更新其说明：保底仅作用于传入的合格候选，而不是承诺范围内每份资料必定出场。

## D. 接入顺序与所有分支

### D.1 默认单路和原问题回退

在 `retrieveRelevantDocs` 中，保持 `authorizeScope`、空范围返回、query 遍历、`attemptedQueries` 和 `similaritySearch` 不变。在现有 `allowedIds` 过滤之后，将 `balanceByKnowledgeBase(candidatesDocs, topK)` 替换为 `selectCandidateDocuments(candidatesDocs, topK)`。

因此少于 topK、只有一份资料时也会先执行筛选，不能把筛选藏在均衡函数的多资料分支内。所选结果为空则继续下一 query，非空则按原路径返回并记录命中指标。向量服务异常仍沿现有异常处理传播，不因新增筛选吞异常或重试。

### D.2 双路融合

`retrieveAndMerge` 保持每路召回参数和授权过滤，接着增加：筛选开启时，先用 `hasValidRelevanceScore` 排除非法分数，再进入 `merged.merge(doc.getId(), doc, higherScore)`；关闭时不增加排除。

这个提前步骤只处理非法分数，不计算绝对或相对门槛，防止 NaN 或无穷在同 UUID 合并时覆盖正常分数。同分保留先到的改写路结果。融合 map 沿用 `LinkedHashMap<String, Document>`，已有稳定降序排序保留。

在最终 `balanceByKnowledgeBase(sorted, topK)` 位置替换为 `selectCandidateDocuments(sorted, topK)`。最高分只从融合后的授权有效候选取一次；全空返回空，不再开启第三次检索。原有两路 hit 指标继续表示授权后、筛选前的召回数，merged 指标表示最终选择数，不更换指标含义。

融合前非法分数不会出现在最终筛选统计的 `invalidScores` 中，因此在融合完成日志补充一个聚合 `invalidScoreHits` 数量；单路由筛选日志记录即可。不能把两个值相加解释为最终唯一 UUID 数。

### D.3 组装和回答状态

| 筛选/组装情况 | 行为 |
| --- | --- |
| 空白问题、无可访问范围 | 沿用入口原有返回，不查全库 |
| 改写筛空，原问题有合格结果 | 使用原问题结果；尝试列表包含两路 |
| 两路均无合格结果 | 沿用各入口现有无命中返回；工具返回 `KnowledgeSearchResult.empty()`；`retrieveOnly` 为 `NO_RESULT` |
| 合格结果进入组装器，返回 READY | 沿用已有 directHits / neighbors / text，只有保留命中参与出处 |
| 组装器 NO_HITS 或 TOO_LONG | 沿用该入口已有无命中或上下文过长分支，不回捞已筛掉结果 |
| 邻居读取失败 | 沿用组装器现有降级和 lookupErrors，不新增恢复策略 |
| 原文组装策略关闭 | 筛选仍生效；后续沿用旧正文拼接 |
| 筛选关闭 | 恢复此前候选选择，补邻开关不随之改变 |

工具化问答的“预检索为空”并不表示整次 Agent 必须马上结束，它仍遵循已有工具路由；本轮只保证所有后续搜索也经过筛选，不改变工具次数和拒答策略。

并发安全：新增字段为构造快照，筛选仅创建请求内集合；不修改 Document、输入列表、共享配置或会话范围。无新增数据库写入、事务、锁、重试和异步线程。
