# RAG 语义连续性验证报告

日期：2026-11-12。结论：**实现可供检查，但效果验收未通过，新策略保持默认关闭**。

## 实施范围

新上传或手动重新向量化的短篇、结构简单资料可使用章节切分和相邻原文回填；历史知识库不批量重建。Markdown 识别标题，其他格式不猜标题；复杂表格、OCR 纠错及关键词检索不在本次范围。片段正文保存在 `vector_store.content`；资料名、章节路径进入嵌入输入并记录在 metadata，原文件仍存对象存储。只有开启 `APP_AI_RAG_SECTION_NEIGHBOR_ENABLED=true` 才对新资料使用新策略；当前默认 `false`。

## 对照方法

固定合成 48 题：条件/例外、指代、普通事实、资料外问题各 12 题，每题两组各运行三次，共 288 次。两组分别建立隔离 PostgreSQL 测评库和对象存储桶，Redis 使用 14 号库，基线关闭开关，新方案开启开关。相同样本、fixture、提示词和检索参数；题目及原文由 `ContinuityEvalCorpus.java` 确定性生成，生产切分器测试验证两类跨边界锚点确位于相邻块。当前尚非设计要求的独立 UTF-8 fixture 与 JSONL，属于待完成交付项。

报告记录的默认 provider 为 DashScope，聊天模型配置标识 `qwen3.5-122b-a10b`、embedding 标识 `text-embedding-v3`；未另抓取服务端逐次返回的模型标识。改写关闭，目标块大小 800；各运行报告包含完整实际上下文、回答、直接/邻居 ID、耗时、operationId。完整证据是回答上下文同时包含该题全部锚点，不等于答案正确。两组测评无环境级错误。

## 自动回归

最终后端 T3 回归使用 JDK 25、离线 Gradle、初始化占位凭据及本地 PostgreSQL 临时表运行：897 例、失败 0、错误 0、跳过 45。45 项为原有禁用或待重写测试：语音面试相关 44 项及 Provider 测试 1 项；本次没有新增跳过。上一次全量出现的 1 个失败是新增测试断言未兼容 Windows 的 CRLF，已修正，定向及最终全量通过。前端未改动，未运行前端构建。事务集成测试使用真实 PostgreSQL 和 Spring 事务代理，但知识库快照 Repository 是 mock，不能证明与真实 JPA 联合提交/回滚。

| 指代：完整证据 | 36/36，100% | 36/36，100% | 提升 0，未达至少 25 个百分点 |

每次独立重复的条件证据分别是旧方案 11/12、11/12、11/12，新方案 12/12、12/12、12/12；指代和事实两组每次均 12/12。**未达到设计中条件和指代各提高 25 个百分点的门槛**，不得因结果修改阈值或只挑最佳重复。

助手按目标材料核查条件题，旧方案 18/36 次回答错误，涉及 7 个题；新方案 0/36 次出现目标材料错误。例如 `condition-01`，基线将易碎玻璃杯应补的“外箱照片”错答为“接头近照”，新方案回答正确。这是有限样本上的观察，不替代证据门槛或人工忠实度审核。指代题新方案主体核对正确，但部分回答对原文未给出的比例分母作额外推断，例如 `reference-03` 第三次及 `reference-08` 第一次、第三次，不能直接判定完全忠实。人工逐题、逐次审核条件、主体、例外和拒答尚未完成。

报告中的 `predictedReject` 实际只反映 `NO_RESULT`，不能识别模型生成的自然语言拒答，因此其混淆矩阵不是人工拒答率；此处拒答数字来自助手查看回答，不冒充人工审核。无法获取真实 provider usage 和全程账单，记为不可得；成本账本输入 token 可能是估算值，不能当作真实使用量。
