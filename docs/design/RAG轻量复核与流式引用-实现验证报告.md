# RAG 轻量复核与流式引用：实现与验证

日期：2026-11-13。实施依据为同目录《RAG轻量复核与流式引用-设计稿.md》，用户已明确批准实现。
当前工作区尚未提交、尚未部署。本文区分代码、自动回归、真实模型及运行启用，不互相冒充。

## 一、发生了什么，改成什么

原来只要向量搜索命中，就把资料交给回答模型，并将所有命中自动汇总为出处。
因此问 Spring AI 时，数学和语文即使没有用于回答，也会出现在末尾的链接中。

现在先按原规则补好必要邻居，再由一次短模型调用选择能支持本题的完整证据窗口。
第二次模型调用仍逐字流式回答；结束后只根据回答里有效的证据编号生成出处。
没有有效编号就不展示出处并提示；错误编号不会被猜成其它编号，也不会退回所有命中。

这没有改上传、文档切分、数据库结构或历史消息，也没有清库或重建向量。
复核默认关闭，运行配置还没有自动切换。

## 二、已经落地的行为

- 窗口共享原文、按单元保留，必要邻居不被拆掉；复核后不再查邻居，也不递归连成整篇。
- 资料名、章节路径、原文编号、证据关系一起计入 6000 token；跨工具累计预算受同一上限约束。
- 每个请求有独立编号和缓存，默认至多两批新复核；命中缓存不多扣批次，不重复提供整段原文。
- 搜索可换关键词，复核仍针对本轮明确问题；工具不能新建会话绕开批次数。
- 跨线程使用入口捕获的归属与显式管理员全库事实，恢复已有安全和计费上下文，不从 null 扩权。
- 短复核单次、无工具/记忆/思考；默认 15 秒、256 输出 token。失败中断，不把未复核资料交回模型。
- 同步、普通流、工具预检索、工具追加搜索和只检索测评共用复核入口。
- 只统计本轮有效引用覆盖的去重原文，包含必要邻居；代码中的编号不计出处。
- 没有资料证据仍允许工具化历史问答；关闭出处时仍复核，但不强制引用和提示。
- 复核失败即使被 SDK 转成工具文字，原会话失败标记仍拦住后续分片和无工具重答。

## 五、启用与交付边界

当前 `.env` 没有写入 `APP_AI_RAG_REVIEW_ENABLED`，按 `application.yml` 默认值仍为 false。
不需要新的模型密钥：provider 留空复用项目现有档位路由、数据库 Provider 和密钥配置。
开启方式及所有默认值见设计稿附录 K；无需前端参数或历史库迁移。

首次严格真实门禁存在三次格式失败与一条缺失原文题；明确编号协议回归仍有一次错误编号被拦截，
因此不替用户自动开启运行开关。代码与保护分支完成，但当前模型仍不能保证每次都遵守引用编号协议。
这与“代码能否运行”和“自动回归是否通过”是不同结论，关闭也不代表旧误引风险已经在线修复。
正常 IDEA 重启后的 admin 新消息验证尚未执行，不用只读离线结果冒充用户真实登录验收。

本轮最后一次独立真实测评任务共两项：内存/无答案/历史场景测试通过，严格引用协议回归测试失败。
这是模型输出质量门禁，不是普通全量回归的失败；失败已登记到 `docs/待优化事项.md` 第四节第 7 项，
保留开关 false 和原始失败证据，没有新增默认回归失败或跳过。
最终没有启动前后端服务或 Docker Desktop，也没有提交代码；临时 Q 盘映射已移除。
