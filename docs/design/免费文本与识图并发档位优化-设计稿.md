# 免费文本与识图并发档位优化-设计稿

> 状态：已实现（编译、定向单测通过；全量回归 850 例中 18 失败、45 跳过，
> 失败均为既有 KnowledgeBase OwnerScope 基线）
> 日期：2026-11-06
> 范围：`common/ai`（Provider 路由与模型名）、`modules/aicost`（免费 / Provider 并发闸门）、
> `modules/resume`（试卷识图与解析配置）、`application.yml`、价格种子
> 实测依据：`app/logs/paper-flow.log` 的 `paperId=59`（解析阶段排队）与 `paperId=60`
> （4 页扫描 PDF 中 3 页在同一毫秒发起视觉调用，其中 2 页最终 429 失败）
> 关联文档：`docs/改造说明.md`、`docs/待优化事项.md`、
> `docs/design/免费模型失败收敛与并发档位-设计稿.md`、

## Problem Statement

免费档原来把文本默认指向 `glm-free`（GLM-4.7-Flash），该模型免费额度下大约只有 1 并发，
试卷解析和切题经常只能排队执行。识图默认是 `glm-vl-free`（GLM-4.6V-Flash），免费档同样只有
约 1 并发，但识图单页耗时长、P95 抖动大，拿不到更高的免费并发时，单纯把页任务线程数调大不会更快，
只会把请求同时推到上游后触发 429。

同时，日志暴露了两个容易误判的问题：

1. 页日志里的 `PAGE_RECOGNIZE_BEGIN model=...` 取的是“全局默认识图模型”，不是当前用户实际绑定的
   模型。管理员看到 `Qwen3-VL`，实际调用可能是 `glm-vl-free`，也可能因为用户绑定不可用回退到了
   付费 Provider，无法直接从日志判断。
2. 免费并发闸门只保护“零价格模型”。一旦用户实际走到付费识图 Provider（例如 `siliconflow-vl`），
   页任务仍能 3 个同时打到上游；`paperId=60` 就是这样在第 1 页成功后，第 2、3 页同时返回 429。

本设计解决三件事：免费文本提高可并发上限、免费 / 付费识图都按 Provider 隔离限流、
日志展示实际路由。不改试卷导入接口、不改答案键 DTO、不新增平行重试框架。

## Solution

1. **免费文本切到 `siliconflow-free / Qwen/Qwen3-8B`**：实测该免费模型可承受 8 个结构化调用并发，
   比 GLM-4.7-Flash 的约 1 并发更适合承担切题、解析、批改和问答。
2. **免费识图暂不换模型**：目前没有经过本项目实测、同时满足 OpenAI 兼容、结构化输出稳定和更高免费
   并发的视觉模型；GLM-4.6V-Flash 继续作为默认免费识图，Provider 许可固定为 1。候选的 PaddleOCR-VL
   偏 OCR，是否兼容当前 chat + 结构化输出链路仍需单独验证，本期不冒险切换。
3. **新增付费 Provider 并发闸门**：免费闸门只看“是否零价格”，新闸门只看“该 Provider 是否显式配置
   并发上限”。`siliconflow-vl` 识图先设为 1，页任务仍可并行准备图片、排队等许可，但不会同时打上游。
4. **解析批大小与冷却调整**：免费文本解析默认 4 题一批，固定每批冷却从 1 秒降为 0；429 由共享冷却和
   有界重试处理，不再让每个批次固定多等 1 秒。付费文本仍使用原有批大小。
5. **日志记录实际路由**：新增“当前用户实际识图 Provider / 模型名”读取，页识别和图形题答案键日志都记录
   实际值，不再拿全局默认值冒充实际调用。

# 正文（业务视角）

## 改造点 A：免费文本换到更高并发的 Qwen3-8B

- 目的：免费文本档不再被 GLM-4.7-Flash 的约 1 并发卡住，让切题、解析和批改能并行推进。
- 触发：平台启动时，`siliconflow-free` Provider 存在、已启用且 Key 非空，`free-models.auto-activate`
  为真，系统把全局默认文本模型切到 `Qwen/Qwen3-8B`。
- 规则与步骤：免费文本仍按“实际 Provider + 模型 + 模态”查价格，零价格才进入免费闸门；
  `siliconflow-free` 的文本许可单独配置为 8，Embedding 许可仍为 1。GLM 文本 Provider 保留为可绑定
  备选，许可仍为 1。
- 结果：免费文本可以从串行变成最多 8 个在途请求；解析批大小也从 2 提到 4，正常 8 题试卷从 4 批降到
  2 批，再叠加并行，整体等待明显缩短。
- 边界与异常：用户显式绑定的模型优先于全局默认。`stonee` 如果仍绑定 `glm-free`，不会因为全局默认
  改成 Qwen3-8B 就自动迁移；需要管理员在“模型分配”里改绑，不能静默改用户数据。
- 可改点：默认免费文本 Provider 用 `app.ai.free-models.text-provider` 配置；
  `siliconflow-free` 的文本许可用 `app.ai.free-model-concurrency.provider-permits.siliconflow-free.text-permits`
  配置。

## 改造点 B：免费识图保持 GLM，并把并发固定在 1

- 目的：在没有验证过更高免费并发的视觉模型之前，先保证识图成功率，而不是用更大线程数换更多 429。
- 触发：当前用户实际识图 Provider 为 `glm-vl-free`，且价格表判定为零价格。
- 规则与步骤：GLM 识图的 Provider 许可固定为 1；页任务仍按 `app.paper.recognition.pool-size` 提交，
  但视觉调用会在许可处排队。前一页结束后，下一张图才开始真正请求上游。
- 结果：免费识图从“3 页同时打上游、2 页 429”变成“逐页调用、整体可完成”，代价是总耗时随页数增长。
- 边界与异常：如果以后找到并验证了更高并发的免费视觉模型，只需新增 Provider 和价格记录并调高许可，
  不需要改页任务代码。
- 可改点：`glm-vl-free` 的视觉许可用
  `app.ai.free-model-concurrency.provider-permits.glm-vl-free.vision-permits` 配置。

## 改造点 C：付费识图也加 Provider 并发上限

- 目的：避免用户实际走到付费视觉 Provider 时绕过免费闸门，3 个页任务同时请求后触发厂商侧 429。
- 触发：任意 Chat / 流式 Chat / Embedding 调用经过统一计量 Advisor，且该 Provider 在
  `app.ai.provider-concurrency.providers` 中配置了对应模态的许可。
- 规则与步骤：先取 Provider 许可，再取免费许可（如果该模型也是免费），最后才发请求；
  调用结束按相反顺序释放。未配置的 Provider 拿到无操作许可，原并发不变。配置了 Provider 许可的模型，
  遇到 429 后会进入同一个共享冷却，其他页任务不会立刻继续撞击。
- 结果：`siliconflow-vl` 默认只允许 1 个识图请求在途；多个页任务仍可以并行下载图片、做校验和等待，
  但真正发往厂商的请求被串行化。
- 边界与异常：Provider 许可只限制并发，不替代上游 RPM / 账号余额 / 内容安全限制；如果厂商按分钟限流，
  共享冷却和现有重试仍会兜底。
- 可改点：Provider 级许可在 `app.ai.provider-concurrency.providers.<provider>.<modality>-permits`；
  关闭整个 Provider 闸门用 `app.ai.provider-concurrency.enabled=false`。

## 改造点 D：解析批大小与冷却

- 目的：减少免费解析的批次数和无效等待，同时保留长 JSON 截断保护。
- 触发：解析阶段判断当前文本模型为免费模型。
- 规则与步骤：免费文本默认每批 4 题；每批前的固定冷却默认改为 0。批大小只影响解析，不影响答案键、
  结构切题或批改。429 仍由统一重试、共享冷却和缺失解析补跑处理。
- 结果：8 道题的解析基础请求从 8 次降到 2 次；没有 429 时不再额外固定等待。
- 边界与异常：批越大越容易产生长 JSON 截断；4 是当前 Qwen3-8B 的保守上限，真实样本若出现截断，
  应回调到 3 或 2，而不是继续增大。
- 可改点：`app.ai.free-model-concurrency.analysis-batch-size`、
  `app.paper.answer.analysis-free-model-cooldown`。

## 改造点 E：日志展示实际 Provider / 模型

- 目的：排查 429 时能直接看到“这次到底用了哪个 Provider”，不再被全局默认值误导。
- 触发：页识别开始、图形题答案键批次开始。
- 规则与步骤：从当前调用上下文解析用户绑定，得到实际识图 Provider 和模型名；日志同时打印两者。
  模型名仍会写入页记录，保持原有落库字段不变。
- 结果：后续日志可以直接区分 `glm-vl-free`、`siliconflow-vl` 或其它绑定，429 归因不再靠猜。
- 边界与异常：系统任务没有用户上下文时，仍然回退全局默认识图 Provider，这是预期行为。
- 可改点：日志字段固定，无需配置。

## 改造点 F：bbox 像素坐标兜底

- 目的：部分视觉模型返回的是页面像素坐标而不是 0~1 归一化坐标，原逻辑会把它当成越界坐标，
  导致裁图位置错误或资源归属失败。
- 触发：页几何解析 bbox 时，坐标明显大于归一化范围。
- 规则与步骤：先按原有归一化逻辑处理；如果四个坐标明显落在页面像素范围，则按页面宽高换算成
  0~1 坐标，再做轻微越界收敛。正常归一化 bbox 的行为不变。
- 结果：同一套识别 Prompt 可以兼容两类模型输出，减少因换模型导致的裁图失败。
- 边界与异常：坐标既不像归一化、也不像合法像素范围时仍按非法几何处理，不猜测修正。
- 可改点：判定阈值在 `PageGeometry` 内固定；如后续模型坐标口径变化，再单独抽配置。

## Testing Decisions

- 测外部行为：免费 Provider 许可覆盖默认值、付费 Provider 许可独立生效、未配置 Provider 不受影响、
  用户识图绑定解析出实际模型名。
- 并发测试使用虚拟线程与 `CountDownLatch`，只验证“第二个请求会等待、释放后继续”，不测信号量实现细节。
- 本次改动落在 `common/ai` 与 `modules/aicost`，按 T3 收尾：定向测试通过后跑全量
  `./gradlew :app:test --no-daemon`，只保留尾部输出。
- 既有 KnowledgeBase `OwnerScope` 失败属于历史基线，不与本轮新增失败混在一起。

## Out of Scope

- 不自动修改用户已有的模型绑定；`stonee` 从 `glm-free` 迁到 `siliconflow-free` 需要管理员操作。
- 不切换 Embedding 模型，避免 pgvector 历史向量空间不一致。
- 不引入新的视觉模型或 OCR 框架；PaddleOCR-VL 等候选需单独做真实样本验收。
- 不把免费闸门和 Provider 闸门合并成一个新框架，继续复用统一调用 Advisor。

# 附录（零猜测实现）

## A：免费模型默认值

- `app/src/main/java/interview/guide/common/config/LlmProviderProperties.java`
  - `FreeModels.textProvider` 默认值：`siliconflow-free`。
  - `FreeModels.visionProvider` 默认值：`glm-vl-free`。
- `app/src/main/resources/application.yml`
  - `app.ai.free-models.text-provider` 默认值：`siliconflow-free`。
  - `app.ai.free-models.vision-provider` 默认值：`glm-vl-free`。
  - `app.ai.providers.siliconflow-free.model` 默认值：`Qwen/Qwen3-8B`。
  - `app.ai.provider-extra-body.siliconflow-free.enable_thinking`：`false`。
- `app/src/main/resources/prices/ai-model-prices.yml`
  - 新增 `provider=siliconflow-free`、`model=Qwen/Qwen3-8B`、`modality=TEXT` 的零价格记录。

## B：免费 Provider 级许可

- 配置类：`app/src/main/java/interview/guide/modules/aicost/service/FreeModelConcurrencyProperties.java`
  - 字段 `Map<String, ProviderPermits> providerPermits`。
  - 内部类 `ProviderPermits` 提供 `textPermits / visionPermits / embeddingPermits / audioPermits`。
- 判定类：`FreeModelConcurrencyGate`
  - `configuredPermits(providerId, modality)`：先取模态默认值，再用 Provider 覆盖。
  - 许可 key 为 `providerId + modality`，值为公平 `Semaphore`。
- `application.yml` 默认值：
  - `siliconflow-free.text-permits=8`
  - `siliconflow-free.embedding-permits=1`
  - `glm-free.text-permits=1`
  - `glm-vl-free.vision-permits=1`

## C：付费 Provider 并发闸门

- 新增 `app/src/main/java/interview/guide/modules/aicost/service/ProviderConcurrencyProperties.java`
  - 前缀：`app.ai.provider-concurrency`。
  - 字段：`boolean enabled`、`Map<String, ProviderLimits> providers`。
  - `ProviderLimits` 字段：`textPermits / visionPermits / embeddingPermits / audioPermits`。
- 新增 `ProviderConcurrencyGate`
  - `boolean isConfigured(String providerId, String modality)`：配置存在且允许数大于 0 时为真。
  - `Permit acquire(String providerId, String modality)`：未配置返回 `Permit.noop()`；
    配置时按 `providerId + modality` 创建公平信号量并阻塞获取。
  - 中断时恢复中断标记并抛 `BusinessException(ErrorCode.AI_RATE_LIMIT_EXCEEDED, ...)`。
- `AiCallRecorder`
  - 同步 Chat、流式 Chat、Embedding 的 `call` / `embed` 均先取 `ProviderConcurrencyGate.Permit`，
    再取 `FreeModelConcurrencyGate.Permit`。
  - `throttle = free || providerConcurrencyGate.isConfigured(providerId, modality)`；
    `throttle` 为真时调用 `AiRateLimitThrottle.awaitOpen`，失败时 `noteFailure`。
- `application.yml`：

```yaml
app:
  ai:
    provider-concurrency:
      enabled: true
      providers:
        siliconflow-vl:
          vision-permits: 1
```

## D：解析批大小与冷却

- `FreeModelConcurrencyProperties.analysisBatchSize` 默认值：`4`。
- `application.yml`：`app.ai.free-model-concurrency.analysis-batch-size` 默认 `4`。
- `PaperAnswerExecutorProperties.analysisFreeModelCooldown` 默认值：`Duration.ZERO`。
- `application.yml`：`app.paper.answer.analysis-free-model-cooldown` 默认 `0s`。
- 原有 `app.paper.answer.analysis-batch-size` 仍只用于付费文本。

## E：实际识图模型名

- `LlmProviderRegistry` 新增：

```java
public String getCurrentUserVisionModelName() {
    String id = resolveVisionProviderIdForCurrentUser();
    if (isBlank(id)) {
        return null;
    }
    return loadProviderOrThrow(id).model();
}
```

- `PaperRecognitionService#recognizePage`：
  - `providerId = llmProviderRegistry.getCurrentUserVisionProviderId()`。
  - `model = llmProviderRegistry.getCurrentUserVisionModelName()`。
  - `PAGE_RECOGNIZE_BEGIN` 同时输出 `provider` 和 `model`。
- `AnswerKeyPreparationService#executeVisualBatch` 的图形题日志同样输出实际 Provider 与模型名。

## F：bbox 像素兜底

- 文件：`app/src/main/java/interview/guide/modules/resume/service/PageGeometry.java`。
- 规则：正常范围按归一化坐标处理；坐标明显大于 1 时，使用页面宽高做像素到归一化换算；
  换算后再执行原有的越界收敛。
- 测试：`PageGeometryTest` 增加像素 bbox 用例。
