## Problem Statement

免费模型接入后，解析阶段的缺失没有归零。`paperId=58` 这次 8 道文字题全部拆成单题批次：

1. 基础请求就是 8 次；
2. 第 3、4 题触发上游 `429`，各重试一次，请求数被放大到 10 次；
3. `PAPER_EXTRACTION` 默认每分钟最多 10 次，第 7 题的请求随后被本地闸门直接拒绝，错误是“AI 请求过于频繁”。

根因有两层，且互相放大：

- **本地**：解析阶段的单题批把请求数放大，`AiUsageGate` 的 10 RPM 上限在“重试 + 并发”下很容易打满；`PaperAnalysisPacer` 先检查、再调用，存在检查后窗口变化的竞态。
- **上游**：免费模型是共享池，短窗口内连续调用会返回 `429`。当前只在单次调用内部退避，多个 worker 之间没有共享的冷却状态，第二个 worker 仍会紧接着撞上去。

本设计只解决“免费模型解析缺失”这一条链路，不改变切题对外接口，不新增平行重试框架，不把总重试次数继续调大。

# 正文（业务视角）

## 改造点 A：免费模型解析恢复小批

- 目的：把免费模型解析的基础请求数降下来，给 429 重试和本地每分钟额度留出余量。
- 触发：试卷进入解析阶段，且当前文本模型被判定为免费模型。
- 规则与步骤：免费文本模型按每批 2 题拆分，不再每批 1 题。8 道题从 8 次基础调用降到 4 次；付费模型仍按原有批大小，不受影响。
- 结果：同分钟内的基础请求更少，撞满本地 10 RPM 的概率显著下降；单次输出仍是 2 题，不会回到长 JSON 截断问题。
- 边界与异常：只改免费文本模型的解析批大小，不改答案键、结构切题、批改等其他阶段的批大小。
- 可改点：免费解析批大小在 `app.ai.free-model-concurrency.analysis-batch-size`，默认 2。

## 改造点 B：失败题二次补跑

- 目的：正常批次仍可能因上游 429 或本地闸门失败，全部批次结束后只对“仍然没有解析”的题补一次，不反复重试。
- 触发：解析正常批次全部跑完、合并结果后，仍存在 `解析未生成` 的题。
- 规则与步骤：先挑出仍然缺解析的题；按每批 1 题、最多补跑 4 次、总等待不超过 60 秒的顺序补跑一轮。补跑成功立即写回结果；补跑后仍缺的题保留“解析未生成”，由用户手动重新生成。超过补跑预算的题不再调用模型。
- 结果：能救回大部分瞬时失败，且补跑有明确上限，不会为了凑齐 8 题无限调用。
- 边界与异常：每道缺题只补一次，不循环；补跑期间持续心跳，避免 Stream 任务被误判卡死；单个在途调用不被打断，只在下一次提交前检查总预算。
- 可改点：补跑次数上限和总等待时长分别走 `app.paper.answer.analysis-recovery-max-calls` 与 `app.paper.answer.analysis-recovery-max-wait`。

## 改造点 C：共享的上游 429 冷却

- 目的：一个 worker 遇到 429 后，让同一模型的其他 worker 在冷却结束前不要继续发起，避免多个 worker 连续撞上游限流。
- 触发：免费模型的同步文本调用失败，且失败被判定为限流（上游 429 或本地限流语义）。
- 规则与步骤：在真正发起模型请求前，先查当前 provider + 模型 + 模态是否处于冷却期，是就等到冷却结束；调用失败时，把这次限流的等待时长记到共享状态。有上游 `Retry-After` 就用它，没有就按 10 秒基础加随机抖动等待，单次最多 30 秒。
- 结果：解析、答案键等所有走统一调用链的免费文本请求，都会在同一个冷却点上排队，不再各自为战。
- 边界与异常：只对免费模型生效，付费模型不进入冷却；冷却状态是进程内共享，多实例部署的全局冷却仍记在待优化清单，不在本期处理。
- 可改点：基础等待、抖动、单次上限在 `app.ai.rate-limit-throttle.*`。

## 改造点 D：本地闸门把“还要等多久”交给调用方

- 目的：本地每分钟额度打满时，调用方知道要等多久再重试，而不是用固定的 5 秒退避去碰运气。
- 触发：模型调用在进入请求前被本地 `RPM / TPM / 并发` 闸门拒绝。
- 规则与步骤：闸门拒绝时抛出一个携带“建议等待毫秒数”的限流异常；统一重试入口读取这个时长后再等待重试。每分钟额度用满时，等待时长就是窗口剩余毫秒数；其余情况为 0，沿用原有退避。
- 结果：第 7 题这类“被本地闸门拒绝”的请求会在窗口恢复后重试，而不是两次短退避后直接判失败。
- 边界与异常：管理员仍绕过本地闸门，行为不变；该异常仍是业务异常，最终对用户只显示安全的限流文案。
- 可改点：等待时长由闸门内部按窗口剩余时间计算，不新增外部配置。

## 改造点 E：解析调度抽成独立模块

- 目的：把“拆批、提交、背压、收结果、补跑”从答案键服务里拿出来，让正常批和补跑复用同一套调度，测试面集中在模块接缝上。
- 触发：解析正常批和缺失补跑都要提交任务到有界执行器。
- 规则与步骤：新增解析调度模块，接口只暴露“批量调度”和“顺序补跑”两个方法；调用方传“怎么执行一批”和“失败怎么兜底”，模块负责排队、拒绝降级、等待结果和心跳。答案键服务只保留“调模型生成解析”和“失败时标记缺失”。
- 结果：答案键服务不再直接操作执行器，解析相关的排队与失败收敛逻辑集中在一处。
- 边界与异常：调度模块不感知模型与 Prompt，只做任务调度；业务结果仍由答案键服务拼装。
- 可改点：正常批并发仍由 `app.paper.answer.pool-size` 控制，补跑是顺序提交。

## 改造点 F：补跑可观测

- 目的：日志里能区分“正常批失败”和“补跑失败”，复盘限流时不用再靠猜。
- 触发：进入补跑计划、开始补跑、补跑结束、因预算跳过，以及解析批检测到限流。
- 规则与步骤：在 paper-flow 专用日志通道新增一组 `ANSWER_ANALYSIS_RECOVERY_*` 事件，并在解析批失败时追加 `ANSWER_ANALYSIS_RATE_LIMIT_THROTTLE`、正常批内有题缺失时追加 `ANSWER_ANALYSIS_BATCH_MISSING`。
- 结果：一次切题的解析流程可以在日志里完整还原“计划 → 正常批 → 缺题 → 补跑 → 最终缺题数”。
- 边界与异常：模型原始回包仍只走 `ANSWER_ANALYSIS_MODEL_RESPONSE`，不新增原始回包通道。
- 可改点：事件名在附录固定，不在运行时配置。

## Testing Decisions

- 只测外部行为：补跑计划只包含缺题、补跑按 1 题/批且受预算与截止时间约束、限流异常携带等待时长、共享冷却在 429 后阻塞后续调用、正常批拒绝后能重投。
- 睡眠抽成可覆盖方法，测试用子类把睡眠置空并记录调用，避免真实等待拖慢单测。
- 本次改动落在 `common/ai` 与 `modules/aicost`（公共 / 并发 / AI 调用）及 `modules/resume`（解析调度），按 T3 收尾：定向测试通过后跑全量 `./gradlew :app:test --no-daemon`，输出只看尾部 `Select-Object -Last 60`。

- 不把 `structured-max-attempts` 继续调大。
- 不把共享冷却做成 Redis 全局键；多实例全局配额已登记为待优化事项。

```java
import interview.guide.common.exception.BusinessException;
import interview.guide.common.exception.ErrorCode;

public class AiRateLimitExceededException extends BusinessException {

  private final long retryAfterMs;

  public AiRateLimitExceededException(String message, long retryAfterMs) {
    super(ErrorCode.AI_RATE_LIMIT_EXCEEDED, message);
    this.retryAfterMs = Math.max(0, retryAfterMs);
  }

  public long retryAfterMs() {
    return retryAfterMs;
  }
}
```

```java
import jakarta.validation.constraints.Min;
import lombok.Getter;
import lombok.Setter;
import org.springframework.boot.context.properties.ConfigurationProperties;
import org.springframework.stereotype.Component;
import org.springframework.validation.annotation.Validated;

@Component
@Validated
@ConfigurationProperties(prefix = "app.ai.rate-limit-throttle")
@Getter
@Setter
public class AiRateLimitThrottleProperties {
  private boolean enabled = true;

  @Min(0) private long fallbackJitterMs = 2_000;
```

新增 `app/src/main/java/interview/guide/common/ai/AiRateLimitThrottle.java`：

```java
package interview.guide.common.ai;

import interview.guide.common.exception.BusinessException;
import interview.guide.common.exception.ErrorCode;
import java.util.Locale;
import java.util.concurrent.ConcurrentHashMap;
import java.util.concurrent.ThreadLocalRandom;
import org.springframework.stereotype.Component;

@Component
public class AiRateLimitThrottle {

  private final AiRateLimitThrottleProperties properties;
  private final ConcurrentHashMap<Key, Long> throttleUntil = new ConcurrentHashMap<>();

  public AiRateLimitThrottle(AiRateLimitThrottleProperties properties) {
    this.properties = properties;
  }

  public void noteFailure(String providerId, String model, String modality, Throwable error) {
    if (!properties.isEnabled() || error == null
        || !RetryableFailureClassifier.isRateLimitFailure(error)) {
      return;
    }
    long retryAfter = RetryableFailureClassifier.retryAfterMillis(error);
    long delay = retryAfter > 0 ? retryAfter : fallbackDelay();
    delay = Math.min(delay, Math.max(0, properties.getMaxWaitMs()));
    throttleUntil.merge(
        key(providerId, model, modality),
        System.currentTimeMillis() + delay,
        Math::max);
  }

  public void awaitOpen(String providerId, String model, String modality) {
    if (!properties.isEnabled()) {
      return;
    }
    Long until = throttleUntil.get(key(providerId, model, modality));
    if (until == null) {
      return;
    }
    long waitMs = until - System.currentTimeMillis();
    if (waitMs <= 0) {
      throttleUntil.remove(key(providerId, model, modality), until);
      return;
    }
    try {
      sleep(waitMs);
    } catch (InterruptedException e) {
      Thread.currentThread().interrupt();
      throw new BusinessException(ErrorCode.AI_RATE_LIMIT_EXCEEDED,
          "等待模型冷却被中断，请稍后重试", e);
    }
  }

  protected void sleep(long millis) throws InterruptedException {
    Thread.sleep(millis);
  }

  private long fallbackDelay() {
    long jitter = properties.getFallbackJitterMs() <= 0
        ? 0
        : ThreadLocalRandom.current().nextLong(properties.getFallbackJitterMs() + 1);
    return Math.max(0, properties.getFallbackBaseMs()) + jitter;
  }

  private Key key(String providerId, String model, String modality) {
    return new Key(normalize(providerId), normalize(model), normalizeModality(modality));
  }

  private String normalize(String value) {
    return value == null ? "" : value.trim();
  }

  private String normalizeModality(String value) {
    return value == null ? "" : value.trim().toUpperCase(Locale.ROOT);
  }

  private record Key(String providerId, String model, String modality) {
  }
}
```

```java
boolean acquired = acquire(context);

    freeModelConcurrencyGate.acquireIfFree(providerId, model, modality);
try {

  }

    recordSuccess(context, providerId, model, modality, start, response);
    return response;

      rateLimitThrottle.noteFailure(providerId, model, modality, e);
    }
    recordFailure(context, providerId, model, modality, start, e);

  }
}
```

```java
package interview.guide.modules.resume.service;

import interview.guide.common.async.BoundedExecutor;
import interview.guide.common.async.ExecutorRejectedException;
import interview.guide.common.exception.BusinessException;
import interview.guide.common.exception.ErrorCode;
import interview.guide.modules.resume.log.PaperFlowLog;
import java.util.ArrayList;
import java.util.List;
import java.util.concurrent.Callable;
import java.util.concurrent.ExecutionException;
import java.util.concurrent.Future;
import java.util.function.BiFunction;
import java.util.function.Function;
import org.springframework.beans.factory.annotation.Qualifier;
import org.springframework.stereotype.Component;

@Component
public class AnalysisBatchScheduler {

  private static final int MAX_EMPTY_SUBMIT_ROUNDS = 50;
  private static final long BACKPRESSURE_SLEEP_MS = 200L;

  private final BoundedExecutor executor;

  public AnalysisBatchScheduler(
      @Qualifier("paperAnswerExecutor") BoundedExecutor executor) {
    this.executor = executor;
  }

  public <B, R> List<R> runBatches(
      List<B> batches,
      Function<B, Callable<R>> taskFactory,
      BiFunction<B, Throwable, R> failureHandler,
      Runnable heartbeat) {
    if (batches == null || batches.isEmpty()) {
      return List.of();
    }
    List<R> results = new ArrayList<>(batches.size());
    int submitted = 0;
    int emptyRounds = 0;
    while (submitted < batches.size()) {
      List<Future<R>> futures = new ArrayList<>();
      List<B> roundBatches = new ArrayList<>();
      while (submitted < batches.size()) {
        B batch = batches.get(submitted);
        try {
          futures.add(executor.submit(taskFactory.apply(batch)));
          roundBatches.add(batch);
          submitted++;
        } catch (ExecutorRejectedException e) {
          PaperFlowLog.warn("ANSWER_ANALYSIS_SUBMIT_REJECTED executor={}, submitted={}, "
                  + "active={}, queue={}",
              executor.name(), submitted, executor.activeCount(), executor.queueSize());
          break;
        }
      }
      if (futures.isEmpty()) {
        if (executor.isShutdown() || emptyRounds >= MAX_EMPTY_SUBMIT_ROUNDS) {
          BusinessException exhausted = new BusinessException(
              ErrorCode.PAPER_EXTRACTION_FAILED, "解析批次等待执行器超时，已保留标准答案");
          for (; submitted < batches.size(); submitted++) {
            results.add(failureHandler.apply(batches.get(submitted), exhausted));
            runHeartbeat(heartbeat);
          }
          break;
        }
        emptyRounds++;
        sleepBackpressure();
        continue;
      }
      emptyRounds = 0;
      for (int i = 0; i < futures.size(); i++) {
        results.add(await(futures.get(i), roundBatches.get(i), failureHandler));
        runHeartbeat(heartbeat);
      }
    }
    return results;
  }

  public <B, R> List<R> runRecovery(
      List<B> batches,
      Function<B, Callable<R>> taskFactory,
      BiFunction<B, Throwable, R> failureHandler,
      Runnable heartbeat,
      long deadlineEpochMs) {
    if (batches == null || batches.isEmpty()) {
      return List.of();
    }
    List<R> results = new ArrayList<>(batches.size());
    for (int i = 0; i < batches.size(); i++) {
      B batch = batches.get(i);
      if (System.currentTimeMillis() >= deadlineEpochMs) {
        BusinessException timeout = new BusinessException(
            ErrorCode.PAPER_EXTRACTION_FAILED, "解析补跑等待预算耗尽");
        for (int j = i; j < batches.size(); j++) {
          results.add(failureHandler.apply(batches.get(j), timeout));
          runHeartbeat(heartbeat);
        }
        break;
      }
      Future<R> future;
      try {
        future = executor.submit(taskFactory.apply(batch));
      } catch (ExecutorRejectedException e) {
        results.add(failureHandler.apply(batch, e));
        runHeartbeat(heartbeat);
        continue;
      }
      results.add(await(future, batch, failureHandler));
      runHeartbeat(heartbeat);
    }
    return results;
  }

  private <B, R> R await(Future<R> future, B batch,
                         BiFunction<B, Throwable, R> failureHandler) {
    try {
      return future.get();
    } catch (InterruptedException e) {
      Thread.currentThread().interrupt();
      throw new BusinessException(ErrorCode.PAPER_EXTRACTION_FAILED,
          "题目解析等待被中断，请稍后重试", e);
    } catch (ExecutionException e) {
      Throwable cause = e.getCause() == null ? e : e.getCause();
      return failureHandler.apply(batch, cause);
    }
  }

  private void runHeartbeat(Runnable heartbeat) {
    if (heartbeat != null) {
      heartbeat.run();
    }
  }

  private void sleepBackpressure() {
    try {
      Thread.sleep(BACKPRESSURE_SLEEP_MS);
    } catch (InterruptedException e) {
      Thread.currentThread().interrupt();
      throw new BusinessException(ErrorCode.PAPER_EXTRACTION_FAILED,
          "解析批次等待执行器被中断，请稍后重试", e);
    }
  }
}
```

```java
private void recoverMissingAnalyses(
    Long paperId,
    List<AnalysisInput> missing,
    Map<Integer, AnswerKeyDTO> keys,
    List<String> warnings,
    Runnable heartbeat,
    boolean freeTextModel) {
  int maxCalls = Math.max(0, answerProperties.getAnalysisRecoveryMaxCalls());
  List<AnalysisInput> targets = missing.stream().limit(maxCalls).toList();
  int skipped = missing.size() - targets.size();
  long deadline = System.currentTimeMillis()
      + answerProperties.getAnalysisRecoveryMaxWait().toMillis();
  PaperFlowLog.event("ANSWER_ANALYSIS_RECOVERY_PLAN paperId={}, missing={}, targets={}, "
          + "skipped={}, deadlineMs={}",
      paperId, missing.size(), targets.size(), skipped, deadline);
  if (targets.isEmpty()) {
    if (skipped > 0) {
      warnings.add(analysisRecoverySkippedWarning(skipped));
    }
    return;
  }
  PaperFlowLog.event("ANSWER_ANALYSIS_RECOVERY_BEGIN paperId={}, targets={}",
      paperId, targets.size());
  Map<Integer, AnswerKeyDTO> snapshot = Map.copyOf(keys);
  List<List<AnalysisInput>> recoveryBatches = analysisBatches(targets, 1);
  List<AnalysisBatchResult> recoveryResults = analysisBatchScheduler.runRecovery(
      recoveryBatches,
      batch -> () -> executeAnalysisBatch(paperId, batch, snapshot, freeTextModel),
      (batch, error) -> failedAnalysisBatch(batch, error),
      heartbeat,
      deadline);
  mergeAnalysisResults(recoveryResults, keys, warnings);
  if (skipped > 0) {
    warnings.add(analysisRecoverySkippedWarning(skipped));
  }
  long remaining = countMissing(keys, targets);
  PaperFlowLog.event("ANSWER_ANALYSIS_RECOVERY_END paperId={}, targets={}, remainingMissing={}",
      paperId, targets.size(), remaining);
}
```

5. 新增辅助方法：

```java
private boolean isMissingAnalysis(AnswerKeyDTO key) {
  return key == null
      || !hasText(key.analysis())
      || key.analysis().contains("解析未生成");
}

private long countMissing(Map<Integer, AnswerKeyDTO> keys, List<AnalysisInput> inputs) {
  return inputs.stream()
      .filter(input -> isMissingAnalysis(keys.get(input.source().question().questionIndex())))
      .count();
}

private String analysisRecoverySkippedWarning(int skipped) {
  return "解析补跑预算用尽，另有 " + skipped + " 道题未生成解析，可手动重新生成";
}
```

### 状态与分支

- 正常批与补跑都通过 `executeAnalysisBatch` 生成结果；补跑用当前 `keys` 快照渲染已确认答案。
- `missing.size() <= analysisRecoveryMaxCalls`：全部进入补跑；否则只补前 `analysisRecoveryMaxCalls` 个，其余记为 skipped。
- `deadlineEpochMs` 只在 `runRecovery` 每次提交前检查，单次在途模型调用不被打断。
- 补跑后仍缺的题由 `failedAnalysisBatch` 写回“解析未生成”，并产生 `ANSWER_ANALYSIS_QUESTION_FAILED`。
