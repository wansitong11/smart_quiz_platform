# 共享资料权限设计稿（所有人可用，只有管理员可维护）

> 状态：**已实现并实测**。需求：共享知识库只能管理员改分类 / 删除 / 重新向量化；普通用户在知识库管理页对共享资料不做任何操作，只能下载。

## 一、目标权限矩阵

| 操作 | 自己的私有资料 | 共享资料：普通用户 | 共享资料：管理员（含非创建者） | 别人的私有资料 |
| --- | --- | --- | --- | --- |
| 列表 / 详情 / 下载 / 检索 / 基于它开考 | ✅ | ✅ | ✅ | ❌（「查看全部」时可见，见下） |
| 改分类 | ✅ | ❌ 404 | ✅（本次新增） | ❌ |
| 重新向量化 | ✅ | ❌ 404 | ✅（本次新增） | ❌ |
| 删除 | ✅ | ❌ 404 | ✅（本次新增） | ❌ |
| 题库：出题 / 编辑 / 删除 / 启停 | ✅ | ❌ 404 | ✅（本次新增） | ❌ |

一句话：**共享资料＝"所有人可用、只有管理员可维护"；私有资料维持"只有归属人"**。越权统一 404（不暴露存在性）。

## 二、改造前的三个问题

1. **管理页对共享资料照渲染写操作**：普通用户的列表里能看到共享资料（列表口径＝自己的＋共享），分类下拉/重新向量化/删除按钮都在，点了才 404。
2. **管理员默认管不了别人的共享资料**：所有写路径走的是 `findByIdOwned`（只看归属人），共享资料归属创建它的那个管理员，换一个管理员（或同一管理员在「只看我的」模式下）一样 404；只有切到 `?scope=all`（校验整体放开）才能管——语义绕，而且那个开关本意是"看"。
3. **考核页/题库页同样漏**：卡片上的「生成题目」、题库页的 生成/编辑/删除/启停，对共享资料也照渲染；题库页还会轮询生成状态，那个接口用的是"只看归属人"，普通用户打开共享资料题库页会静默拿不到状态。

## 三、后端设计

1. **`OwnerScope` 增加显式判定**（刻意不看 `scope`）：
   - 可维护＝ 归属人本人，或（共享资料 且 `ROLE_ADMIN`）；
   - `?scope=all` 只影响"能看多少"，不再给写权限——顺带清掉了待优化事项里"切到查看全部就能改删别人私有资料"的问题。
2. **`KnowledgeBaseRepository.findByIdManageable(id, ownerId, admin)`**：把判定下推到 SQL，写路径统一用它。
3. **新增 `KnowledgeBaseAccessService`**：`requireManageable(id)` / `requireReadable(id)` 两个入口，各 Service 不再各写一遍判定（写错一处就是越权口子）。
4. **改动点（请求线程的写路径）**：`KnowledgeBaseListService.updateCategory`、`KnowledgeBaseDeleteService`、`KnowledgeBaseUploadService.revectorize` ＋ `KnowledgeBasePersistenceService.updateVectorStatusToPending`（同一路径的后续状态更新，不改会"过了第一道门、卡在第二道门"）、`KnowledgeBaseQuestionService.getKnowledgeBase` / `getOwnedQuestion`；另把 `QuestionGenerationStateService.getStatus` 改成**可读**口径（共享资料普通用户也能看生成状态）。
5. **异步/后台路径一律不加权限判定**：状态机方法、出题落库、向量化消费者与恢复调度器继续按 id 直查——后台线程没有登录上下文，加了判定会把任务全判成"找不到"（上一轮切题失败就是踩了这个坑）。

## 四、前端设计

1. `frontend/src/utils/knowledgeBasePermission.ts`：`canManageKnowledgeBase(kb, user)`，与后端同一套规则，只负责不渲染注定失败的入口。
2. **知识库管理页**：不可维护的行——分类列改成只读文本，删除与重新向量化按钮不渲染，**下载始终可用**，并显示「共享资料仅管理员可管理」提示。
3. **知识库考核首页卡片**：不可维护时隐藏「生成题目」，保留「开始测验」和「管理题库」（进去只读浏览）。
4. **题库页**：不可维护时隐藏 生成/重新生成/手动新增/批量操作/编辑/删除/启停，隐藏勾选框（没法批量），页头提示"共享资料的题库仅供查看（可下载、可开始测验），维护请找管理员"。

## 五、实测（`scripts/verify-shared-kb-permission.ps1`）

三个账号真跑：管理员 A（创建共享资料）、管理员 B（**非创建者**）、普通用户 C。

- 普通用户 C 对共享资料：列表/详情/题库/题库方向/生成状态/开考容量 → **200**；改分类/重新向量化/出题/手动新增题目/删除 → **全部 404**，且核对共享资料**没被删掉**；
- 管理员 B（非创建者、且**不切** scope=all）：改分类 / 出题 / 手动新增题目 / 重新向量化 → **全部 200**；
- 回归：C 改自己私有资料 200；B 改 C 的私有资料 404（连 `?scope=all` 也是 404）；B 在 `?scope=all` 下改共享资料 200。

`./gradlew :app:compileJava` 与 `pnpm run build` 均通过。
