# 图形题答案键与批改 · 设计稿

> 状态：核心链路已实现（2026-10-26）；继续用数学、语文和托福阅读真实样本回归
> 关联：`docs/design/复杂试卷识别与结构化-设计稿.md`
> 目标样本：`docs/test-papers/复杂试卷类型/从立体图形到平面图形.pdf`

## 0. 已确认决策（2026-10-22）

| # | 决策 |
| --- | --- |
| 1 | 答案键只作为后端判分依据，**普通校对页不展示答案**；保留内部人工维护能力，不接入学生流程 |
| 2 | 作图题先支持**文字描述作答**，不做在线画布/照片上传 |
| 3 | 低置信度阈值 = **60** |
| 4 | 纯文字题走 plain chat；含图题走视觉模型，**按题分流**，同页可批量 |
| 5 | 预生成答案的选择题/数值填空题，批改时走现有确定性链路，不再调用视觉模型 |
| 6 | 只有依赖图形判断的主观题，批改时才把题目图 + 学生描述交给视觉模型 |
| 7 | 低置信度在上交后的**批改结果**中提示，不在校对页暴露答案或答案置信度 |

### 0.1 结论

不要把「每道题批改时都发图片」作为默认方案，而是把「生成答案键」和「批改学生作答」拆开：

1. **生成答案键**：结构化完成后，题目按纯文字 / 含图分成两路。纯文字题走 plain chat；含图题按页分组走视觉模型，
   一次性生成 `参考答案 + 正确选项 + 图形摘要 + 解析 + 评分点 + 置信度`。
2. **答案键内部校对**：答案键只供后端判分，普通校对页不展示参考答案、选项正误、解析、图形摘要或置信度。
   AI 仍正常生成答案键；置信度低于 **60** 时记录 `lowConfidence=true`，在交卷后的批改结果中提示，不提前暴露原因。
3. **批改作答**：
   - 选择题、可确定比较的填空题：用预生成答案键走现有 `ObjectiveAnswerGrader`，**不再调用视觉模型**；
   - 纯文字 / 主要依赖文字材料的主观题：走现有 `UnifiedEvaluationService`，图形摘要作为评分依据注入，不发图；
   - 真正依赖图形判断的主观题：把题目图、图形摘要、参考答案和学生的文字描述交给视觉模型判断；
   - 选择题 / 数值填空题已有候选答案时正常判分，即使置信度低也只在报告中提示；
   - 只有答案键为空或“暂缺”时，才标记待人工复核；
   - 主观题答案键置信度低：正常给出模型评分，但批改结果显示「判分仅供参考」；
   - 视觉批改失败或模型明确表示无法判断：标记「需人工复核」，**不能静默给 0 分**。

答案生成是模型调用阶段的硬约束：每道题的 `referenceAnswer` 必须非空；选择题的
`selectedOptions` 必须与 `referenceAnswer` 一致。低置信度允许，但缺答案会携带具体
`questionIndex` 重试，最多 3 次；仍缺失时本次分析失败，不能写入“暂缺”后继续。

答案键统一存放在试卷结构快照中；练习会话仍把当前版本快照进 `practice_sessions.paper_json`，
因此后续修改答案键不会篡改已经交卷的历史记录。

## 1. 现状与根因

### 1.1 客观题判分本身没有问题

`ObjectiveAnswerGrader` 的选择题判分是：

```
学生选择的字母集合 == referenceAnswer 的字母集合
```

只要参考答案正确，A/B/C/D 的图形选项不需要在批改时再看图。

### 1.2 问题在答案键

当前 `referenceAnswer` / `analysis` 来自结构化阶段，而结构化模型**只看到转写文本**：

- Q1–Q3 的选项是展开图，文本只有 `A B C D`；
- 模型没有看到四张图，只能猜答案；
- `ObjectiveAnswerGrader` 再准确，也是在比对一个错误的答案键。

### 1.3 主观题同样缺图

- 几何题、看图填空、看图说明：文本模型看不到图；
- 作图题（Q4、Q8 的“在图中补充”）：当前先让学生用文字描述设计，提交后由视觉模型结合原题图判断是否满足约束。
  暂不支持在线画板和学生作答照片上传。

## 2. 三种可选方案

| 方案 | 做法 | 优点 | 缺点 |
| --- | --- | --- | --- |
| A. 每次批改都发图 | 每道题批改时把原页/题图 + 学生答案发给视觉模型 | 实现直接，主观题也能看图 | 每题都付图片 token；同一页多题重复发图；慢 |
| B. 视觉答案键 + 文本批改 | 切题后一次性用视觉模型生成答案键和图摘要；批改走现有文本链路 | 成本低、判分稳定；客观题零模型调用 | 不能评判学生手工作图 |
| **C. B + 条件多模态（推荐）** | 答案键仍一次性生成；只有“必须看图判断”的主观题才多模态批改；作图题先接收文字描述 | 成本与准确性平衡；不增加画板复杂度 | 需要给题目增加视觉标记，并处理视觉批改失败后的人工兜底 |

**推荐 C。**

## 3. 数据模型

`InterviewQuestionDTO` 只增加以下字段，已有的 `referenceAnswer`、`analysis`、`keyPoints`、
`scoringRubric` 继续作为答案键正文，避免同一份数据存两遍：

```java
String visualContext;          // 视觉模型生成的图形、材料或选项摘要
String answerKeySource;        // TEXT / VISION / MANUAL
Integer answerKeyConfidence;   // 0-100；低于 60 时仅在批改结果中提示
boolean requiresVisualGrading; // 批改时必须结合原图判断
```

已有字段直接复用：

- `QuestionOption.assetId`：图形选项资源；
- `PaperNode.meta.assetIds`：题干图 / 材料表格；
- `sourcePageFrom/sourcePageTo`：原页定位。

不增加 `requiresManualReview` 这种题目级永久标记：人工复核是“批改结果”的一种状态，
视觉批改失败时写到报告里，而不是提前断定某道题永远只能人工改。

答案键的持久化容器为：

```java
public record PaperStructureSnapshot(
    int schemaVersion,
    int revision,
    BlockTreeDTO blocks,
    Map<Integer, AnswerKeyDTO> answerKeys
) {
  public static final int CURRENT_SCHEMA_VERSION = 3;
}

public record AnswerKeyDTO(
    int questionIndex,
    String referenceAnswer,
    Map<String, Boolean> optionCorrectness,
    String analysis,
    List<String> keyPoints,
    String scoringRubric,
    String figureSummary,
    boolean requiresVisualGrading,
    int confidence,
    String source,            // TEXT / VISION / MANUAL
    List<AnswerCandidate> candidates,
    String resolutionStatus,  // CONSENSUS / MAJORITY / CONFLICT / SINGLE
    Integer consistencyScore
) {}
```

`practice_papers.structure_json` 由只存 `BlockTreeDTO` 改为存 `PaperStructureSnapshot`；
`structure_hash` 仍然只表示“页文本指纹”。因此：

- 页文本变化会自然让整个快照失效；
- 内部人工维护答案键只改快照中的 `answerKeys`，不会错误地让结构模型重跑；
- 新练习从最新快照生成，历史 `practice_sessions.paper_json` 保持不变。

## 4. 流程

### 4.1 识别与结构化（现有）

```
页图 → 文本 + assets（选项图 / 题干图 / 表格）
     → 行号块树 → QUESTION / MATERIAL / OPTION
```

### 4.2 新增：答案键准备（结构化后、开始作答前）

选择题答案键采用一致性组合流程：

1. 主求解：不读取已有答案，独立生成答案候选。
2. 独立复核：使用新上下文重新求解，结果不与主求解共享。
3. 冲突裁决：仅当两次结果不同，才对该题发起第三次求解。
4. 一致性裁决：由 `AnswerConsistencyResolver` 生成最终答案和
   `CONSENSUS / MAJORITY / CONFLICT / SINGLE` 状态。
5. 解析生成：只解释裁决后的答案，不再读取候选冲突。

答案主求解和独立复核使用 non-thinking plain ChatClient；只有两轮冲突时，才按单题使用
reasoning ChatClient 做第三次裁决。整批 8 题直接开启 thinking 曾稳定在 60 秒边界超时，
因此禁止重新采用整批思考。解析客户端始终关闭思考。选择题同时返回 `derivedResult`（选项映射前的计算结果）
与 `selectedOptions`，后端按 `derivedResult` 匹配唯一选项；两者冲突时以计算结果为准。

正常情况下，一份 8 题纯文字选择题需要“主求解 1 次 + 独立复核 1 次 + 解析 8 次”；
解析按单题生成，避免每题约 500 字时长 JSON 被截断或单次输出超过 60 秒。
单题解析失败时使用正确答案、考点和评分规则生成确定性兜底。
若存在冲突，最多再增加一次冲突裁决调用。当前还有一项待优化风险：主求解和复核都是
non-thinking，如果两者错误一致，会形成假共识而不触发 reasoning；处理方案见待优化事项 1.4。

答案键准备接在 `PaperStructureService.build()` 之后、创建正式练习会话之前，
继续复用现有 `paper:extract` 异步任务，不新增第二套长任务。

先做确定性分流，不把所有题一起发给视觉模型：

- `optionType=IMAGE`；
- `meta.assetIds` 或 `option.assetId` 非空；
- 题干含“如图 / 图中 / 图(1) / 展开图 / 数轴 / 网格 / 图表”等视觉提示；
- 上述条件都不满足 → 纯文字题。

纯文字题走 `LlmProviderRegistry.getPlainChatClient()`，可以按 10~20 题一批；
含图题按 `sourcePageFrom` 分组，同一页尽量一次生成，单次最多发送 10 张图片。
超过 10 张时按题继续拆分，不能把跨页题强行塞进某一组。

输入：

```text
题干文本
选项文本（如有）
选项图 / 题干图（按顺序）
材料图（从父级 MATERIAL 继承）
原页图（题干图缺失或需要整体上下文时兜底）
```

输出：

```json
{
  "referenceAnswer": "C",
  "optionCorrectness": {"A": false, "B": false, "C": true, "D": false},
  "analysis": "C 的展开图折叠后……",
  "figureSummary": "A 是……；B 是……；C 是……；D 是……",
  "requiresVisualGrading": false,
  "confidence": 86
}
```

落库：

- 覆盖/补全 `referenceAnswer`、`analysis`；
- 写 `visualContext = figureSummary`；
- 写 `answerKeySource=VISION`、`confidence`；
- 答案键只保存在内部结构快照和练习快照中，学生侧结构接口不返回这些字段；
- 置信度低于 **60** 时记录 `lowConfidence=true`，交卷后写入对应题目的批改结果；
- 低置信度不阻塞开始作答；已有候选答案时正常判分并标记“判分仅供参考”；
- 如果后续通过内部维护入口修正答案键，写 `answerKeySource=MANUAL`、`answerKeyConfidence=100`。

`requiresVisualGrading` 不能只信模型自报，后端还要做确定性覆盖：

- 选择题和有纯数值答案的填空题：强制 `false`；
- 题干含“画出 / 补全 / 涂色 / 连接 / 在图中标出”等作图动作：强制 `true`；
- 其余含图主观题：采用视觉模型给出的值，并结合题型做保守判断。

### 4.3 批改分流

```
选择题 + 完整答案键
  → ObjectiveAnswerGrader 字母比对（现有，不调用模型）

可确定比较的数值 / 短填空
  → ObjectiveAnswerGrader（现有，不调用模型）

纯文字主观题，或已有充分图形摘要的阅读 / 简答 / 写作
  → 文本批改 Prompt 增加 visualContext（复用 UnifiedEvaluationService）

requiresVisualGrading = true
  → 多模态批改：题目图 + 材料图 + visualContext + 学生文字描述

视觉批改失败 / 模型判断信息不足
  → 报告标记「需人工复核」，不自动给分，也不能把失败当作 0 分

答案键置信度 < 60
  → 不阻断判分；报告标记「低置信度答案依据」，提示用户注意判分可能不准确
```

### 4.4 作图题

本版采用“先文字描述”的作答方式：

1. 前端对作图题显示普通输入框，提示“请用文字说明你会如何补充、连接或涂色”；
2. 学生提交后，`requiresVisualGrading=true` 的题把原题图与文字描述一起交给视觉模型；
3. 模型只判断描述是否满足图形约束和评分点，不评价文字表达水平；
4. 视觉调用失败或模型返回 `needsManualReview=true` 时，报告显示“需人工复核”，不能静默给 0 分。

在线画板和学生拍照上传不在本版范围。

### 4.5 答案键版本与历史会话

- `PaperStructureSnapshot.revision` 每修改一次答案键就加 1；
- 内部维护答案键后，当前 PAPER 会话如果尚未开始且没有任何作答，直接刷新它的 `paper_json`；
- 会话已经开始或已交卷时不修改它，保证历史报告可追溯；
- 下一次开始作答时，从 `practice_papers.structure_json` 的最新快照重新生成题目树，不能简单复制上一次会话；
- 历史会话保存的是当时的完整 `paper_json`，因此即使后续答案键变化，历史批改仍保持原样。
- 用户点击“开始作答”时还会检查组内确定性题目的答案键；只有答案键为空或“暂缺”时才自动触发
  重新分析。置信度低于 60 但已有候选答案时允许进入作答，并在批改结果中标记低置信度。

## 6. 成本

| 阶段 | 调用量 |
| --- | --- |
| 纯文字答案键 | 按题量分批，通常 1~2 次 plain chat |
| 视觉答案键 | 只对含图题；同页尽量批量，单次最多 10 张图片 |
| 选择题批改 | 0 次模型调用 |
| 文本主观题 | 现有文本批改 + 少量图摘要 token |
| 视觉主观题 | 仅 `requiresVisualGrading=true` 且学生有文字作答的题 |

答案键生成一次后可缓存到 `paper_json` / 结构缓存，重新批改不重复调用。

## 7. 校对页与答案可见性

普通用户侧的“结构校对”只用于确认题目是否被正确拆分，不展示答案相关内容：

- 显示题目、选项、材料、图片和层级；
- **不展示**参考答案、正确答案选项、解析、图形摘要、答案来源和答案键置信度；
- 不展示“AI 置信度 56”之类的提示，避免用户从中反推出答案或知道哪道题更容易猜；
- 作图题仍显示「请用文字描述如何作图」，但不显示参考答案；
- 答案键准备状态只通过“试卷整理完成 / 处理中 / 失败”表达，不暴露内部字段。

隐藏不能只靠前端条件渲染。提交作答前涉及的普通接口，包括结构预览、试卷详情和练习会话，
都必须在后端 DTO 转换时移除答案键字段，避免用户在浏览器 Network 面板里直接看到答案：

- `referenceAnswer`
- `analysis`
- `keyPoints`
- `scoringRubric`
- `visualContext`
- `answerKeySource`
- `answerKeyConfidence`
- `requiresVisualGrading`

完整答案键只保留在 `practice_papers.structure_json`、`practice_sessions.paper_json` 这两个内部存储快照中。

低置信度提示统一放在交卷后的批改结果页：

> 本题答案依据由 AI 生成，置信度较低（56%），当前判分仅供参考，建议结合原题自行复核。

该提示仅说明“答案依据不可靠”，不展示正确答案，也不解释哪个选项可能正确。

内部维护能力（管理员 / 开发排障）可以修改答案键，但必须使用独立接口，不能复用学生端结构预览接口，
也不能把 `referenceAnswer`、`analysis`、`answerKeyConfidence` 放进普通 `StructurePreviewDTO`。

## 8. 失败与降级

| 情况 | 处理 |
| --- | --- |
| 纯文字答案键调用失败 | 保留结构模型给出的初稿；标记 `answerKeySource=TEXT` 并写 warning |
| 视觉答案键调用失败 | 先重试；仍失败则保留文字初稿并标为低置信度，交卷后提示判分依据可能不准确 |
| 置信度低（`< 60`） | 保留候选答案并正常判分，报告标记 `lowConfidence=true`；不能把低置信度当成无答案 |
| 视觉主观题批改失败 | 不重发整卷；报告标记「需人工复核」，不自动给 0 分 |
| 学生未写作答 | 不调用视觉模型，按未作答处理 |
| 图片资源缺失 | 用该题所在整页原图兜底；整页图也缺失时才转人工复核 |
| 语义结果不完整 | 缺题号或选项键时降低置信度并写 warning，不能静默丢弃题目 |

## 9. 实施范围

新增：

- `AnswerKeyPreparationService`：纯文字 / 含图题分流，按页批量生成答案键；
- `PaperAnswerKeyService`：答案键快照读取、内部人工维护与 revision 控制；
- `VisualQuestionEvaluationService`：依赖图形的主观题批改；
- `paper-answer-key-system.st`、`paper-answer-key-user.st`；
- `paper-visual-question-evaluation-system.st`、`paper-visual-question-evaluation-user.st`。

修改：

- `PaperStructureService`：`structure_json` 改为 `PaperStructureSnapshot`，组装树时应用答案键；
- `PaperExtractionStreamConsumer`：结构完成后先准备答案键，再创建练习会话；

## 10. 验收

1. 数学卷 Q1–Q3 的答案键由视觉模型生成；确认后字母判分正确，批改阶段视觉调用次数为 0；
2. 纯文字试卷只调用 plain chat，视觉调用次数为 0；
3. 混合试卷中，同一页的含图题尽量合并为一次视觉调用，单次附件不超过 10 张；
4. Q4 接受文字描述；提交后视觉模型结合原题图评分，不按作文表达能力评分；
5. 视觉批改失败时报告显示「需人工复核」，不会静默给 0 分；
6. Q6/Q7 的文本批改能引用 `visualContext`；
7. 普通校对页和普通结构预览接口都不包含答案、解析、图形摘要和答案置信度；
8. 置信度 59 的选择题/数值填空题在已有候选答案时正常判分，并出现低置信度提示；
9. 内部修改答案键后新练习使用新版本，已交卷历史保持不变；
10. 重新进入同一份已校对试卷，不重复调用答案键模型；
11. 缺图时回退到整页原图；整页图也缺失时才转人工复核。

private PaperStructureSnapshot loadSnapshot(PracticePaperEntity paper, String sourceHash) {

### 11.4 纯文字题与含图题分流

不能只看题干里有没有“如图”，还要把父级 MATERIAL 的图片资源算进来。否则阅读材料、神话卡片、
表格资源下面的小题会被误判为纯文字题。

```java
private record QuestionSource(
    InterviewQuestionDTO question,
    List<String> inheritedAssetIds
) {}

private record ModelImage(String assetId, String role) {}

private boolean needsVision(QuestionSource source) {
  InterviewQuestionDTO q = source.question();
  boolean hasOptionImage = q.options() != null
      && q.options().stream().anyMatch(option -> hasText(option.assetId()));
  boolean hasVisualHint = VISUAL_HINT_PATTERN.matcher(q.question()).find();
  return hasOptionImage || !source.inheritedAssetIds().isEmpty() || hasVisualHint;
}

private List<ModelImage> modelImagesOf(Long paperId, QuestionSource source) {
  List<ModelImage> images = new ArrayList<>();
  boolean hasOptionTiles = source.question().options() != null
      && source.question().options().stream().anyMatch(option -> hasText(option.assetId()));

  // 已切好的图形选项优先：每个选项各一张，按 A/B/C/D 标注。
  if (source.question().options() != null) {
    source.question().options().stream()
        .filter(option -> hasText(option.assetId()))
        .sorted(Comparator.comparing(QuestionOption::key))
        .forEach(option -> images.add(new ModelImage(
            option.assetId(), "QUESTION_" + source.question().questionIndex()
                + "_OPTION_" + option.key())));
  }

  // 题干图、材料表格等非选项资源。
  source.inheritedAssetIds().stream()
      .filter(assetId -> images.stream().noneMatch(image -> image.assetId().equals(assetId)))
      .filter(assetId -> !hasOptionTiles || !isOptionAsset(paperId, assetId))
      .forEach(assetId -> images.add(new ModelImage(
          assetId, "QUESTION_" + source.question().questionIndex() + "_CONTEXT")));
  return images;
}

private boolean isOptionAsset(Long paperId, String assetId) {
  return assetService.find(paperId, assetId)
      .map(asset -> asset.getKind() != null && asset.getKind().startsWith("OPTION_"))
      .orElse(false);
}

private static final Pattern VISUAL_HINT_PATTERN = Pattern.compile(
    "如图|图中|下图|上图|展开图|数轴|网格|统计图|图表|示意图|补全图形"
);
```

`PaperTree` 增加一个只读方法，按题目路径汇总 QUESTION 与父级 MATERIAL 的 `meta.assetIds`：

```java
public List<String> assetIdsOf(int questionIndex) {
  return assetIdsOnPath(root, questionIndex, new ArrayList<>());
}
```

### 11.5 答案键准备服务

纯文字用 plain chat，含图题按页码分组。模型调用全部完成后再集中落快照，避免事务中调用外部服务。

```java
@Service
@RequiredArgsConstructor
public class AnswerKeyPreparationService {

  public record PreparedAnswerKeys(
      Map<Integer, AnswerKeyDTO> answerKeys,
      List<String> warnings
  ) {}

  private final LlmProviderRegistry providerRegistry;
  private final StructuredOutputInvoker invoker;
  private final PaperAssetService assetService;
  private final PaperAnswerKeyService answerKeyService;

  public PreparedAnswerKeys prepare(
      Long paperId,
      PaperStructureService.BuiltStructure structure
  ) {
    List<QuestionSource> sources = collectQuestionSources(structure.paperTree());
    Map<Boolean, List<QuestionSource>> split = sources.stream()
        .collect(Collectors.partitioningBy(this::needsVision));

    List<AnswerKeyDTO> keys = new ArrayList<>();
    List<String> warnings = new ArrayList<>();
    keys.addAll(prepareText(split.get(false)));

    Map<Integer, List<QuestionSource>> byPage = split.get(true).stream()
        .collect(Collectors.groupingBy(
            source -> Optional.ofNullable(source.question().sourcePageFrom()).orElse(0),
            LinkedHashMap::new,
            Collectors.toList()
        ));
    byPage.values().forEach(batch -> keys.addAll(prepareVisual(paperId, batch)));

    Map<Integer, AnswerKeyDTO> byQuestion = keys.stream()
        .collect(Collectors.toMap(AnswerKeyDTO::questionIndex, Function.identity()));
    answerKeyService.savePrepared(paperId, byQuestion);
    return new PreparedAnswerKeys(byQuestion, warnings);
  }
}
```

说明：

- 答案主求解/复核每批最多 10 题；解析生成按单题调用 `getPlainChatClient()`，
  失败后用已确认答案和考点生成兜底解析；
- `prepareVisual` 按页分组；一页图片超过 10 张时，再按题拆批；
- `AnswerKeyDTO` 必须带 `questionIndex`，否则无法把批量结果准确回填；
- 返回结果缺题时写 warning 并降低对应题置信度，不能静默丢题。

### 11.6 视觉答案键调用

视觉客户端使用独立的 `getDefaultVisionChatClient()`；它没有 Memory、Tools、SafeGuard，
不会把问答上下文或面试场景配置带进试卷分析。

```java
private List<AnswerKeyDTO> prepareVisual(Long paperId, List<QuestionSource> questions) {
  List<Media> media = new ArrayList<>();
  StringBuilder userPrompt = new StringBuilder("请为以下含图题生成答案键。\n");

  for (int i = 0; i < questions.size(); i++) {
    QuestionSource source = questions.get(i);
    userPrompt.append("\n题目 ").append(source.question().questionIndex()).append("：")
        .append(source.question().question()).append('\n');
    appendOptions(userPrompt, source.question().options());

    for (ModelImage image : modelImagesOf(paperId, source)) {
      PaperAssetEntity asset = assetService.find(paperId, image.assetId())
          .orElseThrow(() -> new BusinessException(ErrorCode.NOT_FOUND, "题目图片不存在"));
      media.add(new Media(
          MimeTypeUtils.IMAGE_JPEG,
          new ByteArrayResource(assetService.download(asset), image.role() + ".jpg")
      ));
      userPrompt.append("图片顺序 ").append(media.size())
          .append("：").append(image.role()).append('\n');
    }
  }

  AnswerKeyBatchDTO batch = invoker.invoke(
      providerRegistry.getDefaultVisionChatClient(),
      systemPrompt + "\n\n" + outputConverter.getFormat(),
      userPrompt.toString(),
      media,
      outputConverter,
      ErrorCode.PAPER_EXTRACTION_FAILED,
      "图形题答案键生成失败：",
      "试卷答案键-页" + questions.get(0).question().sourcePageFrom(),
      log
  );
  return validateAndNormalize(batch.answerKeys(), questions);
}
```

当没有可用的题干裁剪图时，用 `paper_pages.image_key` 下载整页图兜底。
每个 `Media` 在 Prompt 中都要有稳定的文字编号，模型返回的选项才可核验。

#### 11.6.1 ABCD 图片的传递规则

选项图片按识别粒度决定，不强制“四个选项必须四张图”：

| 识别结果 | 传给模型的图片 | Prompt 标记 |
| --- | --- | --- |
| A/B/C/D 独立 `OPTION_ITEM` 可用 | 优先发送 4 张独立图片，便于模型逐项比较 | `Q1_OPTION_A`、`Q1_OPTION_B`、`Q1_OPTION_C`、`Q1_OPTION_D` |
| 只有无法切分的 `OPTION_ROW` | 1 张包含 ABCD 的整行图片 | `Q1_OPTION_ROW_A_TO_D` |
| 题干有图 | 除选项图外追加题干图 | `Q1_CONTEXT` |
| 阅读材料、表格、推荐卡有图 | 追加父级 MATERIAL 的图片 | `Q1_CONTEXT` |
| 找不到题干图和选项图，但题干有“如图”等提示 | 使用该页原图 | `Q1_PAGE_2` 或 `Q2_PAGE_2` |

同一页发送多道题时必须保持稳定顺序，例如：

```text
图片顺序 1：Q1_OPTION_A
图片顺序 2：Q1_OPTION_B
图片顺序 3：Q1_OPTION_C
图片顺序 4：Q1_OPTION_D
图片顺序 5：Q2_OPTION_A
图片顺序 6：Q2_OPTION_B
...
```

实现约束：

- `QuestionOption.assetId` 的独立选项图可用时优先逐项发送；
- 没有独立选项图时才回退整行 `OPTION_ROW`；
- 已有选项/题干/材料裁图时不再重复附带整页图；整页图仅在裁图缺失时兜底；
- 同一张图同时出现在题目资源和父级材料资源中时按 `assetId` 去重；
- 当前线上稳定性优先：一次视觉请求只生成一道含图题，避免单页多题请求超时；
- 单次最多 10 张；超过时回退整页图或继续拆分；
- 一整行 ABCD 无法切分时，不需要为了形式拆成四张，提示模型“一张图从左到右依次包含 A/B/C/D”即可；
- 返回结果按 `questionIndex` 合并，不能仅依赖模型返回顺序。
- 视觉模型给 `OPTION_ROW` 的 bbox 可能向下带入下一题；识别层先按 `1x4` / `2x2`
  限制最大高宽比，切分器再做一次纵向收紧，旧的选项 tile 必须覆盖更新而不是复用。

```java
@Transactional(rollbackFor = Exception.class)
public AnswerKeyDTO updateManually(
    Long paperId,
    int questionIndex,
    UpdateAnswerKeyRequest request
) {
  PracticePaperEntity paper = resumeRepository.findByIdForUpdate(paperId)
      .orElseThrow(() -> new BusinessException(ErrorCode.NOT_FOUND));

  PaperStructureSnapshot snapshot = loadSnapshot(paper, paper.getStructureHash());
  if (snapshot.revision() != request.expectedRevision()) {
    throw new BusinessException(ErrorCode.BAD_REQUEST, "答案键已被其他操作修改，请刷新后重试");
  }

  AnswerKeyDTO old = snapshot.answerKeys().get(questionIndex);
  AnswerKeyDTO updated = new AnswerKeyDTO(
      questionIndex,
      normalizeChoiceAnswer(request.referenceAnswer()),
      correctnessOf(request.referenceAnswer()),
      request.analysis(),
      request.keyPoints(),
      null,
      old.figureSummary(),
      old.requiresVisualGrading(),
      100,
      "MANUAL",
      old.candidates(),
      "SINGLE",
      100
  );

  Map<Integer, AnswerKeyDTO> answerKeys = new LinkedHashMap<>(snapshot.answerKeys());
  answerKeys.put(questionIndex, updated);
  PaperStructureSnapshot next = new PaperStructureSnapshot(
      snapshot.schemaVersion(), snapshot.revision() + 1, snapshot.blocks(), answerKeys);
  paper.setStructureJson(objectMapper.writeValueAsString(next));
  resumeRepository.save(paper);
  return updated;
}
```

实现时还需：

- 外层增加管理员权限校验；普通用户接口不暴露该路由；
- `expectedRevision` 使用快照 revision，防止两个页面互相覆盖；
- 如果当前 PAPER 会话尚未开始且没有任何 `practice_answers`，同步刷新它的 `paper_json`；
- 会话已经开始或已交卷时不改历史快照，修改只影响下一次作答；
- 人工修改后 `source=MANUAL`、`confidence=100`，可重新进入确定性判分链路。

### 11.9 批改分流与低置信度标记

只有非空且不是“暂缺”的答案键才参与确定性判分；置信度低不阻止判分：

```java
for (InterviewQuestionDTO question : questions) {
  Optional<ObjectiveAnswerGrader.Grade> objective =
      objectiveAnswerGrader.grade(question);
  if (objective.isPresent()) {
    objectiveGrades.put(question.questionIndex(), objective.get());
    if (question.answerKeyConfidence() != null
        && question.answerKeyConfidence() < 60) {
      lowConfidenceQuestions.put(
          question.questionIndex(), question.answerKeyConfidence());
    }
  } else if (question.requiresVisualGrading()) {
    visualSubjectiveQuestions.add(question);
  } else {
    textSubjectiveQuestions.add(question);
  }
}
```

低置信度只影响报告展示，不改变题目的内部答案可见性：

- 普通结构预览、试卷详情和作答页不返回 `answerKeyConfidence`；
- 答案键不可用的客观题返回 `MANUAL_REVIEW`，不参与自动总分；
- 不展示正确选项，只提示“本题的 AI 答案依据置信度较低，判分仅供参考”；
- 如果内部人工维护答案键，下一次新练习使用修正后的答案键。

### 11.11 视觉主观题批改

只有 `requiresVisualGrading=true` 的题进入此服务。输入包含题目原文、材料原文、图形摘要、
参考答案和学生的文字描述；Prompt 明确要求判断“文字描述是否满足图形约束”，而不是评价文采。

```java
public VisualGradeDTO grade(

    return VisualGradeDTO.unanswered();
  }

  List<Media> media = assetIds.stream()
      .map(assetId -> loadAsset(paperId, assetId))
      .toList();

      参考答案：%s
      评分要点：%s

          nullToEmpty(question.referenceAnswer()),
          question.keyPoints() == null ? "" : String.join("；", question.keyPoints()),
          answer
      );

  return invoker.invoke(
      providerRegistry.getDefaultVisionChatClient(),
      visualEvaluationSystemPrompt + "\n\n" + visualGradeConverter.getFormat(),
      userPrompt,
      media,
      visualGradeConverter,
      ErrorCode.INTERVIEW_EVALUATION_FAILED,
      "图形主观题批改失败：",
      "图形题批改-" + question.questionIndex(),
      log
  );
}
```

视觉模型返回：

```json
{
  "score": 75,
  "feedback": "阴影区域正确，但未说明另一条对称轴。",
  "needsManualReview": false,
  "confidence": 82
}
```

若 `needsManualReview=true`，报告不能显示成普通 0 分。

### 11.12 报告状态与分数口径

建议给 `QuestionEvaluation` 增加：

```java
public enum ScoreStatus {
  AUTO,                 // 确定性判分
  TEXT_MODEL,           // 文本模型批改
  VISION_MODEL,         // 视觉模型批改
  MANUAL_REVIEW         // 视觉批改失败或模型无法判断
}

public record QuestionEvaluation(
    // ...原有字段
    ScoreStatus scoreStatus,
    boolean lowConfidence,
    Integer answerKeyConfidence,
    String scoreMessage
) {}
```

分数规则：

- `lowConfidence=true` 的题目仍正常计分，但显示醒目的“判分仅供参考”提示；
- `MANUAL_REVIEW` 不参与自动总分计算；
- `MANUAL_REVIEW` 时 `practice_answers.auto_scored=false`，卷面得分显示“待人工评分”，不要展示 `0/5`；
- 低置信度提示可以展示置信度数字，但不能附带正确答案或图形选项的正误信息；
- 其余题仍按当前“得分率 × 卷面分”计算，保持现有报告口径。

### 11.13 前端展示与作答

结构校对页只展示题目结构，不请求也不渲染答案键字段：

```tsx
<PaperTreeView
  tree={structure.nodes}
  mode="STRUCTURE_REVIEW"
  showAnswerKey={false}
/>
```

作答页对作图类主观题显示文字输入框。`requiresVisualGrading` 只用于后端批改分流，不返回前端：

```tsx
<textarea
  placeholder="请用文字说明你会如何补充、连接、涂色或构造图形"
  value={answer}
  onChange={event => onAnswerChange(question.questionIndex, event.target.value)}
/>
<p>提交后将由 AI 结合原题图判断你的文字描述是否满足图形要求。</p>
```

低置信度提示只出现在交卷后的批改结果中：

```tsx
{detail.lowConfidence && (
  <div className="rounded border border-amber-200 bg-amber-50 px-3 py-2 text-amber-800">
    本题答案依据由 AI 生成，置信度较低
    {detail.answerKeyConfidence != null && `（${detail.answerKeyConfidence}%）`}，
    当前判分仅供参考，建议结合原题自行复核。
  </div>
)}
```

该提示不展示正确答案、解析或选项正误。

### 11.14 Prompt 约束

答案键 Prompt 必须明确：

1. 先看图再作答，不能只根据 A/B/C/D 不含正文的文本猜测；
2. 选择题输出每个选项的 `optionCorrectness`，正确项集合必须与 `referenceAnswer` 一致；
3. 主观题输出可执行的评分要点，不能只写“答案正确”；
4. 图形看不清、资源不完整或无法确定时降低 `confidence`，不得硬猜；
5. 作图类题设置 `requiresVisualGrading=true`，批改时必须结合学生描述与原图判断；
6. `analysis` 是学生可见最终解析，通常 200~500 个中文字符、最长约 500，内容完整优先；
   简单题可简洁作答；代码层硬限制为 520 字符；
7. `figureSummary` 最多 120 字符，`keyPoints` 最多 4 条且单条最多 50 字符，最终评语最多 900 字符；
8. 禁止输出试算草稿、自我纠错、内心独白或“等等/不对/让我重新算/逆向推演”等过程性表达；
9. 不输出 Markdown 代码块或额外解释，只返回 `StructuredOutputInvoker` 要求的 JSON。
