# 复杂试卷识别与结构化 · 设计稿

> 状态：核心链路已实现；DOCX / 英语完形待样本验证
> 关联：`docs/design/图片试卷识别-设计稿.md`、`docs/改造说明.md`
> 范围：语文 / 数学 / 英语试卷；输入支持 PDF（文字层 / 扫描）、JPG/PNG、DOCX（含图片）、DOC

## 0. 结论

这次不再在现有"正则切题"上继续打补丁，而是把链路统一成三层：

```
输入适配  →  Document（Page：文本行 + 资源 assets）
识别      →  带行号的文本 + assets（图片/表格）+ 行内标记
结构化    →  模型标块类型，后端按行号确定性建树
```

四个已确认的问题分别落在：

| 问题 | 落点 |
| --- | --- |
| 第一页内容丢失 | 页源判定（文本可信度 + 图像覆盖率），不再只看字符数 |
| 阅读材料 / 层级丢失 | 行号块分类 + 确定性建树，替换 `PaperStructureDetector` 的正则骨架 |
| 加点字丢失 | `{{字}}` 行内标记 + 前端 `text-emphasis: dot` |
| 图形选项 / 题干图 | 页面级 assets + 选项图切分，判分仍是 A/B/C/D |

新增的两种输入形态：

| 输入 | 处理方式 |
| --- | --- |
| 纯图片（JPG/PNG，多张） | 每张 = 一页，走视觉模型；按上传顺序合并为一份试卷 |
| DOCX（带图片） | **不渲染成图片**，用 POI 解析段落顺序 + 内嵌图片，文本与图片都是精确的，不走视觉模型 |

## 1. 现状与根因（均来自实测）

### 1.1 第一页内容丢失

`四年级（上）语文第四单元名校真题卷.pdf` 第 1 页只有 49 个字符的文字层：

```
四年级上册语文名校真题卷
（第四单元测试卷）
时间：90分钟 满分：100分
第1页,共8页
```

当前规则"有效字符 ≥30 就算 TEXT"，于是整页跳过了视觉识别，1、2 题和材料全部丢失。

### 1.2 阅读材料与层级丢失

同一份卷子第 4 页的转写里，"（一）盘古开天地（节选）"是完整存在的，但切题结果的
`paper_json` 只有一个 `"全卷"` 节点，没有材料、没有小节。

原因是 `PaperStructureDetector` 只认：

- 一级标题：`一、` / `二．`
- 二级标题：`（一）` / `(二)`

而这份卷子用的是：

| 原文 | 是否匹配 |
| --- | --- |
| `三 句子荟萃馆。（6分）` | 否（没有 `、`） |
| `⑥ 阅读体验厅。(28.5分)` | 否（带圈数字） |
| `第二部分  阅读与探究(28.5分)` | 否（"部分"不是中文数字 + 顿号） |
| `七 妙笔生花苑。（25分）` | 否 |

一个大题都没识别到 → 退化成"整卷一个 section" → 材料抽取逻辑不生效。

### 1.3 加点字没有表示

第 2 页题干"加点的关联词语"，但选项里的 `尽管……但`、`不仅……而且` 在转写文本里
没有任何标记。纯文本没有"字下加点"的语义。

### 1.4 图形选项

`从立体图形到平面图形.pdf`：单页、纯图片（文字层 2 字符、1 个图像对象）、8 道题。
其中 1–3 题的 A/B/C/D 四个选项都是展开图，Q6–Q8 题干带几何图，Q8 还有 (1)(2) 子问。
纯文本转写只能得到题干，选项完全缺失。

### 1.5 Word 当前会丢图

`DocumentParseService` 使用 Tika 且显式关闭了嵌入文档解析，DOCX 里的图片不会被提取，
也没有"图片在段落中的位置"信息。

## 2. 统一文档模型

### 2.1 结构

```
Document
 ├─ Page 1
 │   ├─ lines:  Line[]      // lineNo 从 1 开始，全卷连续
 │   └─ assets: Asset[]     // 图片、表格、选项图、题干图
 └─ Page N
```

```java
record DocLine(int lineNo, int pageNo, String text) {}

record DocAsset(
    String id,            // a1, a2...
    AssetKind kind,       // FIGURE / TABLE / OPTION_ROW / OPTION_ITEM / EQUATION
    AssetRole role,       // STEM / OPTIONS / MATERIAL / DECORATION
    String storageKey,    // 图片在 S3 的 key；表格可为空
    Rect rect,            // 页面内归一化坐标，扫描页/PDF 页使用；DOCX 可为空
    String anchorText,    // 资源锚定的文本片段，用于挂到结构节点
    String layout,        // 1x4 / 2x2 / 1x1，仅 OPTION_ROW 使用
    int optionCount,      // OPTION_ROW 的选项数（A/B/C/D = 4），由视觉模型或结构模型给出
    List<String> labels,  // 选项字母顺序，如 [A,B,C,D]
    String source         // PDF_IMAGE / VLM / DOCX_INLINE / DOCX_TABLE
) {}

record Rect(double x, double y, double w, double h) {} // 0~1
```

**核心原则：文本和资源分开。**

- 文本负责题干、选项文字、材料正文；
- 资源负责图形选项、题干图、表格截图；
- 结构树通过 `lineNo` 定位文本，通过 `assetId` 挂资源。

这样"图形选项"不会污染行号体系，`{{加点}}` 也不会影响资源定位。

### 2.2 页码语义

| 输入 | pageNo 含义 | 能否"查看原页" |
| --- | --- | --- |
| PDF | 物理页 | 能（渲染页图） |
| JPG/PNG | 每张图 = 一页 | 能（就是原图） |
| DOCX | **逻辑页**：按显式分页符切；没有分页符时按内容长度切（默认 40 行/页） | 不能；改为展示该页的文本与资源 |
| DOC | 逻辑页（同 DOCX），且图片不可靠 | 不能 |

DOCX 没有固定分页，这一点必须在 UI 上说清楚：题目卡片上的"第 N 页"是逻辑页，
用于定位和分组，不是 Word 的打印页码。

## 3. 输入适配

### 3.1 路由矩阵

| 输入 | 文本来源 | 资源来源 | 是否调用视觉模型 |
| --- | --- | --- | --- |
| 数字版 PDF（文字层可信） | PDFBox 逐行抽取 | PDFBox 图片 XObject + 位置矩阵 | 否 |
| 扫描 PDF | 页面渲染后视觉模型转写 | 视觉模型返回 bbox | 是（逐页） |
| JPG / PNG | 视觉模型 | 视觉模型返回 bbox | 是（每张） |
| DOCX（文字 + 内嵌图） | POI 段落文本 | POI 内嵌图片（精确字节 + 段落顺序） | 否 |
| DOCX（整页是图片） | 视觉模型 | 视觉模型返回 bbox | 是（按图） |
| DOC | POI/HWPF 文本 | 不可靠，缺图时给 warning | 否 |
| TXT / MD / RTF | Tika | 无 | 否 |

### 3.2 PDF：文字层与图片分开取

- 文本：`PDFTextStripper` 逐页、逐行抽取，行号连续编号；
- 图片：用 `PDFStreamEngine` 子类遍历内容流，在 `drawImage` 回调里取
  `getGraphicsState().getCurrentTransformationMatrix()`，换算成页面归一化矩形
  （只遍历 `PDResources` 的 XObject 拿不到显示位置）；
- 这些图片天然就是 `FIGURE` / `STEM` / `OPTIONS` 的候选资源，不需要模型猜位置。

只有文字层不可信（见 §4）时才整页渲染走视觉模型。

### 3.3 纯图片

- 每张图 = 一页；EXIF 方向摆正、长边 ≤2000px、JPEG 0.85；
- 一次最多 10 张，按上传顺序合并为同一份试卷；
- 视觉模型对每页返回：文本（保留题号/选项/分值）+ assets（bbox）+ 行内标记。

### 3.4 DOCX：用 POI，不要渲染

使用 `XWPFDocument` 顺序遍历：

1. 段落 → 文本行；段内换行（`w:br`）拆成多行；
2. `XWPFRun.getEmbeddedPictures()` → 图片字节、所在段落、段内顺序；
3. 表格 → 转成 Markdown 行；表格单元格里的图片作为该表格行的资源；
4. 页眉页脚忽略；
5. 显式分页符（`w:br type=page` / `lastRenderedPageBreak`）切逻辑页；没有分页符时按 40 行切。

这样 DOCX 的图片**有精确的字节和顺序**，比扫描页的 bbox 可靠得多：

- 一个段落里连续出现 4 张图 → 直接得到一个 `OPTION_ROW`，`layout=1x4`；
- 一张图独立成段 → `FIGURE + STEM`；
- 图片在表格里 → 资源挂在表格行上。

**整页是图片的 DOCX**：如果一个逻辑页里只有一张近似整页大小的图片、文本行极少，
把这张图当作扫描页，交给视觉模型。

**公式/艺术字**：OMML 公式和 Word 图形 POI 拿不到可靠文本。处理方式：

- 检测到 `m:oMath` 或 `wps:*` 时，在该行标 `hasUnsupportedMath`；
- 若部署环境有 LibreOffice，可选"DOCX → PDF"再走 PDF 链路；
- 没有转换能力时给 warning，不静默丢内容。

**旧版 .doc**：HWPF 文本可用，图片位置不可靠；默认按文本处理并提示
"旧版 .doc 的图片可能缺失，建议另存为 .docx 或 PDF"。

## 4. 页源判定（解决第一页丢失）

对 PDF 每页计算四个信号：

| 信号 | 说明 |
| --- | --- |
| 有效字符数 | 汉字/字母/数字，不含空白 |
| 题号行数 | 行首 `1.` `2、` 等 |
| 页眉页脚占比 | 命中页眉页脚正则的行数 / 总行数 |
| 图像覆盖率 | 页面内图片 XObject 面积 / 页面面积 |

判定：

```
图像覆盖率 > 0.5 且 有效字符 < 150        → IMAGE
有效字符 < 120 且 题号行数 = 0            → IMAGE
页眉页脚占比 > 0.8                        → IMAGE
否则                                      → TEXT
```

补充两条：

1. **TEXT 页同样要抽 assets**。数字版 PDF 的插图是独立图片对象，不能因为"文字够多"
   就不取图。
2. 用户在预览页始终可以点"用识图重做此页"，覆盖自动判定。

普通 DOCX 按 TEXT 处理（文本是权威来源），资源按 §3.4 取；
整页只有图片的 DOCX 按 §3.4 转成 IMAGE，纯图片永远是 IMAGE。

## 5. 识别阶段

### 5.1 视觉模型输出（扫描页 / 图片页）

```json
{
  "pageNo": 1,
  "text": "1. 下列是正方体展开图的是（ ）\n2. 2026 广东广州期末……",
  "assets": [
    {
      "kind": "OPTION_ROW",
      "role": "OPTIONS",
      "anchorText": "1. 下列是正方体展开图的是",
      "bbox": [0.05, 0.20, 0.95, 0.30],
      "layout": "1x4"
    },
    {
      "kind": "FIGURE",
      "role": "STEM",
      "anchorText": "6. [2026 辽宁锦州期中]",
      "bbox": [0.10, 0.42, 0.55, 0.55]
    }
  ],
  "hasFigure": true,
  "notes": ""
}
```

约束：

- `text` 必须按行输出，行内不要插换行；
- `anchorText` 必须是 `text` 中真实出现的一行（或其前缀），后端用它找行号；
- `bbox` 是归一化坐标，允许粗；后端会做二次修正；
- 没有把握的资源可以不返回，但要在 `notes` 里说明。

### 5.2 行内标记规范

| 原卷样式 | 标记 | 前端渲染 |
| --- | --- | --- |
| 字下加点 | `{{字}}` | `text-emphasis: dot; text-emphasis-position: under` |
| 下划线 | `[[u:文字]]` | 实线下划线 |
| 波浪线 | `[[w:文字]]` | 波浪下划线 |
| 无法辨认 | `[无法辨认]` | 灰色占位 |

识图 prompt 明确要求：

- 只标"印刷体上的标记"，手写批注不标；
- 看不到是否加点时不要猜，写 `[无法辨认]`；
- 标记必须原样保留在文本里。

结构化阶段**只返回行号、不回写文本**，所以标记天然保留，不会在切题时被模型改写。

## 6. 结构化阶段（替换正则骨架）

### 6.1 输入

带行号的整卷文本（跨页合并后，行号连续）：

```
L0001 第一部分 积累与运用
L0002 一、看拼音写词语
L0003 ...
L0120 （一）盘古开天地（节选）
L0121 盘古倒下以后，他的身体发生了巨大的变化……
```

### 6.2 输出

```json
{
  "nodes": [
    {"type":"PART","startLine":1,"endLine":60},
    {"type":"SECTION","startLine":61,"endLine":95},
    {"type":"MATERIAL","startLine":120,"endLine":128},
    {"type":"QUESTION","startLine":129,"endLine":136,
     "questionType":"SINGLE_CHOICE","fullScore":3,
     "assetRefs":["a1"]}
  ]
}
```

节点类型：

| 类型 | 用途 |
| --- | --- |
| `PART` | 第一部分 / Part I |
| `SECTION` | 一、 / 三 / ⑥ /（一） |
| `MATERIAL` | 阅读材料、语段、表格、听力原文 |
| `QUESTION` | 独立题目 |
| `SUB_QUESTION` | (1)(2) 这类子问（有独立分值时） |
| `BLANK` | 材料内部的空（完形、七选五、语法填空） |
| `FIGURE` | 图形，只记资源，不识别内容 |
| `INSTRUCTION` | 整卷说明、注意事项 |
| `ANSWER_KEY` | 卷末答案，用于回填参考答案，不作为题目 |

### 6.3 建树规则（确定性）

1. 按 `startLine/endLine` 从原文切片，文本零改写；
2. `PART` 为一级；`SECTION` 挂在最近的前一个 `PART` 下；`MATERIAL` 挂在当前 `SECTION` 下；
3. 两道 `MATERIAL` 之间的 `QUESTION/SUB_QUESTION/BLANK` 归前一个 `MATERIAL`；
   第一个材料之前的题归当前 `SECTION`；
4. `OPTION_ROW / FIGURE` 按 `anchorText` 落到行，再挂到该行所属的 `QUESTION` / `MATERIAL`；
5. `questionIndex` 按树的深度优先顺序编号，与现有 `PaperTree` 完全兼容。

### 6.4 分块与合并

- 每 2–3 页（或 ≤3000 字）一次调用；
- 块尾若 MATERIAL 未结束，标 `continuesToNext`，下一块以 `continuedMaterial` 开头时合并；
- 合并只做"相邻同类型拼接"，不重排。

### 6.5 校验（不通过就重问）

| 校验 | 处理 |
| --- | --- |
| 行覆盖连续，无缺口/重叠 | 指出具体行号，只重做该段 |
| 层级不跳级（1→3 非法） | 重问该块 |
| 每个 QUESTION 有父节点 | 重问；仍失败则挂"未归类"并 warning |
| 每个 MATERIAL 后至少 1 题 | 标"孤立材料" |
| 每个 asset 恰好被一个节点引用 | 未挂载资源在校对页标红 |
| `optionType=IMAGE` 的题至少 2 个选项资源 | 降级为"选项见图" |
| 题数/总分与行首题号数、卷面标注总分对比 | 差异过大只 warning，不自动改 |

### 6.6 回退

同一块连续两次校验失败：

1. 回退到"行首题号 + 标题正则"的旧解析；
2. 在校对页明确提示"本块使用了降级解析，请重点核对"；
3. 不静默丢内容。

## 7. 图形选项

### 7.1 选项模型

```java
record QuestionOption(
    String key,        // A/B/C/D
    String text,       // 文字选项，可空
    String assetId     // 图片选项，可空
) {}
```

判分不变：正确答案仍是字母，`ObjectiveAnswerGrader` 不受影响。

### 7.2 资源来源

| 输入 | 选项图来源 |
| --- | --- |
| DOCX | POI 内嵌图片，按段内顺序直接对应 A/B/C/D |
| 数字版 PDF | 图片 XObject + 位置矩阵，按 x 坐标排序 |
| 扫描页 / 图片 | 视觉模型给 `OPTION_ROW` bbox，后端再切分 |

### 7.3 切分

bbox 只负责"框住整条选项带"，**具体切线由图像本身决定**，不靠模型报坐标：

1. 按 bbox 裁出选项带，转灰度；
2. 计算**墨迹投影**：每一列的黑像素数量 `ink[x]`；
3. 对投影做平滑（宽度约 `bandWidth / (N*8)`），消除孤立噪点；
4. 找局部极小值作为候选"空白沟"：排除左右各 5% 的边距，只保留宽度 ≥ `bandWidth/(N*4)`、
   深度 ≤ 中位数 20% 的沟；
5. 从候选沟里选 N-1 条，使切出的 N 块宽度最接近"等宽"（选项通常是等分的），
   同时要求每块墨迹占比 ≥ 1%、宽度在平均值的 0.6~1.6 倍之间；
6. 选不出 N-1 条合法沟 → 尝试等宽切分（`bandWidth/N`）→ 仍不合理则整条带一张图。

```
ink[x]  ██████      ██████      ██████      ██████
            谷1          谷2          谷3
        A             B             C             D
```

补充规则：

- **bbox 只框选项行**：框进题干会污染列投影（实测会把切线切到题干文字里）。
  发现上方有连续文字行时，先用横向投影把文字行裁掉；漏掉最右选项说明 bbox 不完整，
  直接降级为整条带 + 人工拖线。
- **2×2 布局**：先按行投影切成两行，再对每行做列切分；
- **带边框的选项**（每个选项一个方框）：先做形态学处理去掉长竖线，再做投影，
  避免边框把"空白沟"填满；
- **拍照倾斜**：先按投影方差做小角度纠偏（±5°），纠偏失败则降级；
- **文字+图形混排选项**：切分只看位置，每块可以同时包含文字和图形。

切分结果写回 `DocAsset.cutOffsets`（归一化切线，长度 N-1）。校对页允许拖动这
N-1 条切线并保存——自动切不准时，人工两秒就能修正，比整条带降级更好用。

#### 7.3.1 四个选项是同一张大图

这在 DOCX 里很常见：老师把 A/B/C/D 四张图拼成一张图片插入。文件结构上只有
**一个图片对象**，但切分逻辑不依赖图片对象个数——它作用在像素上，和扫描页完全一样。

处理步骤：

1. 该图片直接标成 `OPTION_ROW`，`optionCount`/`labels` 由视觉模型或结构模型给出
   （模型能看到图上的 A/B/C/D）；
2. 对图片本身做双向投影：先试"垂直切 N 份"（1×N），再试"先横切两行、再各切 N/2 份"
   （2×2 / 2×3），选切分质量最高的布局；
3. 如果图片带表格线/边框：先检测长横线、长竖线，按单元格切，再把边框从裁片里去掉；
4. 如果这张大图还包含题干（整道题就是一张图）：让视觉模型给出"选项区"的子 bbox，
   先裁出选项区再投影；拿不到子 bbox 时，整图作为题干图，选项用 A/B/C/D 按钮；
5. 切不动（图形相贴、手写涂画、阴影严重）→ 整图 + A/B/C/D 按钮 + 放大查看。

存储上仍然只存**原图 + cutOffsets**，读时按偏移裁剪，不重复编码。

### 7.4 降级

| 情况 | 展示 |
| --- | --- |
| 切分成功 | 四个独立图片选项，点图选中 |
| 切分失败 | 整条选项带一张图 + A/B/C/D 四个按钮 |
| 没有 bbox | "选项见图" + 查看原页 |

### 7.5 题干图与材料图

- 题干图：挂在 QUESTION 上，题干下方内嵌显示；
- 材料图：挂在 MATERIAL 上，随材料展示；
- 子问题（(1)(2)）共用父题的图，不重复存。

## 8. 数据模型与接口

### 8.1 表

新增 `paper_assets`：

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| paper_id / page_id | 归属 |
| asset_key | 业务 ID（a1/a2），树里引用 |
| kind / role / layout | 资源类型 |
| storage_key | S3 key（表格可为空） |
| rect_json | 归一化坐标 |
| anchor_line | 锚定行号 |
| width / height | 像素尺寸 |

`paper_pages` 增加 `assets_json`（页级快照）与 `logical_page`（DOCX 用）。

### 8.2 DTO

- `PaperRecognitionDTO.PaperPageDTO` 增加 `assets[]`；
- `InterviewQuestionDTO.QuestionOption` 增加 `assetId`；
- `PaperNode.meta` 增加 `assetIds`；
- `ResumeDetailDTO` 增加 `sourceType`（PDF_SCAN / PDF_TEXT / IMAGE / DOCX / DOC）。

### 8.3 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/papers/upload` | 接收 pdf/docx/doc/jpg/png，1~10 个 |
| GET | `/api/papers/{id}/recognition` | 页 + 文本 + assets + 结构预览 |
| GET | `/api/papers/{id}/assets/{assetKey}` | 取资源（带归属校验） |
| GET | `/api/papers/{id}/pages/{n}/image?crop=` | 原页/裁剪 |
| PUT | `/api/papers/{id}/pages/{n}` | 改文字 |
| PUT | `/api/papers/{id}/tree` | 校对阶段人工调整层级（可选） |
| POST | `/api/papers/{id}/recognition/confirm` | 确认并切题 |

上传限制：

- 单份 ≤10 页 / ≤10 个文件；
- 单张图片 / PDF / DOCX ≤50MB（multipart 请求整批上限 200MB）；
- DOCX 解析失败或含不支持的公式时，允许"仅文本"继续并给 warning。

## 9. 前端

### 9.1 校对页

```
左：页/资源缩略图（页图、DOCX 图片、表格）
中：可编辑文本（行号可选显示）
右：结构树预览（PART → SECTION → MATERIAL → QUESTION）
底：确认并切题
```

结构树预览是这次新增的关键：用户确认前就能看到"盘古材料下面挂了 4 道题"，
而不是切完才发现材料没了。

### 9.2 渲染

- `{{字}}` → 加点样式；`[[u:]]` / `[[w:]]` → 下划线/波浪线；
- 图片选项 → 图片卡片 + 字母角标，点击选中；
- 题干图 → 题干下方内嵌，可放大；
- DOCX 无页图 → 显示"逻辑页 N"，资源单独展示。

## 10. 成本与性能

| 输入 | 识别成本 | 结构化成本 |
| --- | --- | --- |
| 数字版 PDF | 0 次视觉调用 | 1 次/2–3 页 |

## 11. 验收用例

1. `四年级（上）语文第四单元名校真题卷.pdf`：第 1 页不再丢；3 个 PART、2 个 MATERIAL、
   约 25 题；`（一）盘古开天地` 作为 MATERIAL，下面挂 4 题。
2. `从立体图形到平面图形.pdf`：1–3 题的 A/B/C/D 是可点击的图片选项；
   Q6–Q8 题干图可查看；Q8 的 (1)(2) 是两个 SUB_QUESTION。
3. 带图片的 DOCX：段落顺序、图片顺序与 Word 一致；图片选项直接可用。
4. 整页是图片的 DOCX：自动转视觉识别。
5. 英语完形：MATERIAL 内 1–15 个 BLANK，选项与空号对应。
6. 纯图片 8 张：合并为一份 8 页试卷，页码与上传顺序一致。
7. 视觉模型超时：该页 FAILED，其它页继续；重试后恢复。
8. 越权访问 assets / 页图 / 结构树：404。

## 12. 风险与降级

| 风险 | 降级 |
| --- | --- |
| 视觉模型 bbox 不准 | 整条选项带一张图；仍可作答 |
| 结构模型漏块 | 行覆盖校验指出缺口，重问；再失败走旧解析并提示 |
| DOCX 公式/图形不支持 | 标 warning，建议转 PDF；不静默丢 |
| 旧版 .doc 图片缺失 | 仅文本 + warning |
| 模型把材料改写 | 树阶段只回行号，文本从原文切片，从机制上避免 |

## 13. 实施顺序

1. **输入适配与页面模型**：`DocumentParser` 接口 + PDF/DOCX/图片三种实现；
   `paper_assets` 表与资源接口。
2. **页源判定**：文本可信度 + 图像覆盖率，修复第一页这类问题。
3. **行号结构树**：块分类 schema、建树、校验、结构预览；替换 `PaperStructureDetector`。
4. **图形选项**：assets 挂载、选项切分、前端图片选项。
5. **行内标记**：识图 prompt、前端渲染。

第 3 步是主体，第 1、2 步可以独立上线；第 4、5 步依赖第 3 步的节点模型。
