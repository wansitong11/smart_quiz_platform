# 模拟测验模块改造方案（原「模拟面试」）

> 目标：把面向求职的「模拟面试」改造成面向高中生的「模拟测验」——按学科选知识点出题、整卷作答、一次交卷批改。
> 同时把「语音面试」从前端下线（后端保留代码，不启用）。
> 关联文档：`docs/智能刷题平台-改造清单.md`、`docs/改造说明.md`、`docs/design/试卷作答与题型交互-设计稿.md`。

## 0. 结论摘要

### 0.1 实现状态（2026-10-12）

| 项 | 状态 | 落地位置 |
| --- | --- | --- |
| P0-1 组卷（按学科/知识点/难度/题量出卷，含阅读原文） | ✅ 已实现 | `modules/quiz/service/QuizPaperService.java` + `prompts/quiz-paper-generation-*.st` |
| P0-2 `/api/quiz/**` 接口 | ✅ 已实现 | `modules/quiz/controller/QuizController.java` |

| P0-4 导航/路由改名 | ✅ 已实现 | `Layout.tsx` 导航改为「模拟测验 / 错题本 / 测验记录」 |

实测（本地真实模型调用）：语文 · 现代文阅读 · 5 题组卷 **26 秒**，产出「752 字原文 + 单选/多选/简答各若干」，整卷 28 分；
交卷后主观题走 `UnifiedEvaluationService` 批改（13 秒），报告出卷面分与分段得分；
错题本聚合出 5 道错题（含错误次数、我的答案、参考答案、解析）；错题重练 **0.8 秒**（不调模型）；再测一次 **23 秒**出新卷。

一句话方案：**不要再给模拟面试单独造一套问答 UI，直接复用「试卷分析」那条链路已经做完的整卷作答能力。**

```
现在的试卷分析链路（已实现）：
  上传试卷 → AI 切题 → PaperTree(PAPER→SECTION→MATERIAL/QUESTION)
           → 题型驱动作答控件 → 一次交卷 → 客观题本地判分 + 主观题 LLM 批改 → 报告/PDF

模拟面试现状（要改）：
  选学科/难度/题量 → AI 出题 → 聊天式一问一答（InterviewChatPanel）→ 逐题批改

改造后的模拟测验：
  选学科 + 知识点 + 难度 + 题量 → AI 组卷（产出 PaperTree）
  → 与试卷分析**完全同一套**作答与批改链路 → 报告
```

理由有三条：

1. **能力已经完全可复用**。`PaperNode` 已经支持 `MATERIAL`（阅读原文）节点，`InterviewQuestionDTO` 已经支持 7 种题型、选项、分值、参考答案、解析；`QuestionAnswerInput` 已经实现单选/多选/填空/文本四种控件；`ObjectiveAnswerGrader` 已经做客观题确定性判分。这些正是你要求的能力。
2. **两条产品线本来是重复的**。`docs/改造说明.md` 的 P1 待办里就写着「两条产品线收敛：把知识库面试的资料出题并入试卷分析那套整卷作答与报告」。
3. **改造量小**。会话表 `practice_sessions` 已经有 `paper_json`（存放 PaperTree）、`skill_id`、`difficulty`、`total_questions`、`overall_score`、`evaluate_status` 等字段——**不需要新建表**。

| 知识库面试 `/knowledgebase-interview` | 资料出题 → 并入模拟测验 | 出题来源之一，不再单独一条产品线 |
| 口语练习（无独立入口） | **前端全部下线** | 见第 7 节 |

导航（`Layout.tsx` 的 navGroup）从三组收敛为：

```
练习   试卷分析 / 模拟测验 / 测验记录 / 学习计划
资料   资料库 / 问答助手
系统   设置
```

### 2.2 一次测验的生命周期

```
组卷配置(学科+知识点+难度+题量+题型偏好)
   ↓ POST 创建会话，status=CREATED，异步出题
PENDING（组卷中，前端显示"正在出题"）
   ↓ 出题完成，写入 paper_json
ANSWERED? 不用中间态：CREATED → 直接可作答（paper_json 就绪）
   ↓ POST 整卷交卷（一次提交全部答案）
GRADING（异步批改：客观题本地判分 + 主观题 LLM）
   ↓
COMPLETED（报告：卷面分、分段得分、知识点掌握、逐题解析）
```

状态字段复用现有 `SessionStatus` + `evaluateStatus`/`evaluateError`，与试卷分析完全一致。

## 3. 组卷策略（核心设计）

### 3.1 输入参数

| 参数 | 取值 | 备注 |
| --- | --- | --- |
| 学科 | `chinese` / `math` / `english` | 复用 `skills/` 目录 |
| 知识板块 | 学科下 `categories` 多选 | 语文 5 项、数学 6 项、英语 5 项，见 `skill.meta.yml` |
| 难度 | 基础 / 中等 / 综合 | 沿用 `junior/mid/senior` 取值，只改展示文案 |
| 题量 | 5~30 | 默认 10 |
| 题型偏好 | 自动 / 仅客观题 / 主观题为主 | 新增 |
| 出题来源 | 学科知识点（默认）/ 指定资料库 / 错题重练 | 新增（P1） |

### 3.2 输出结构

组卷直接产出 **PaperTree**，而不是扁平题目列表：

```
PAPER 语文 · 现代文阅读专项测验（20 分 / 建议 20 分钟）
├── SECTION 现代文阅读（12 分）
│   ├── MATERIAL 材料一原文……            ← 阅读题必须带原文
│   ├── QUESTION 1 单选（3 分）
│   ├── QUESTION 2 简答（5 分）
│   └── QUESTION 3 简答（4 分）
└── SECTION 语言文字运用（8 分）
    ├── QUESTION 4 填空（4 分）
    └── QUESTION 5 单选（4 分）
```

`SECTION` 按**知识板块**划分（而不是按题型），这样报告里能直接给出"分段得分 + 板块掌握度"，
与试卷分析的 `sectionScores` 完全一致。

### 3.3 各学科默认题型配比

| 学科 | 默认题型配比（题量 10） | 必须支持的形态 |
| --- | --- | --- |
| 语文 | 单选 3 / 简答 4 / 填空 2 / 写作 1 | 现代文阅读（材料 + 多题）、古诗文阅读（材料 + 多题）、作文 |
| 数学 | 单选 5 / 填空 2 / 解答 3 | 纯公式题干、分步解答题 |
| 英语 | 单选 4 / 完形 2 / 语法填空 2 / 阅读 1 组 / 写作 1 | 完形填空（一篇材料 + 多个编号空）、阅读理解（A/B/C/D 四选一） |

配比可按知识点动态调整：`WRITING`、`READING` 这类 `ALWAYS_ONE` 板块每次必出 1 题（`priority: ALWAYS_ONE` 已有语义）。

### 3.4 出题 Prompt 改造

把 `interview-question-skill-{system,user}.st` 改造成 `quiz-paper-generation-{system,user}.st`，关键约束：

1. **必须输出结构化字段**（这是与现在最大的差异，现在只输出"问题 + 考察点"）：

```json
{
  "paperTitle": "语文 · 现代文阅读专项测验",
  "sections": [
    {
      "title": "现代文阅读",
      "knowledgeCategory": "MODERN_READING",
      "material": { "title": "材料一", "content": "原文……" },
      "questions": [
        {
          "questionType": "SINGLE_CHOICE",
          "stem": "下列对材料内容的理解，正确的一项是",
          "options": [{ "key": "A", "text": "……" }],
          "fullScore": 3,
          "referenceAnswer": "C",
          "analysis": "解析……",
          "knowledgePoints": ["筛选并整合信息"]
        }
      ]
    }
  ]
}
```

2. **题型必须落在枚举内**：`SINGLE_CHOICE` / `MULTI_CHOICE` / `FILL_BLANK` / `SHORT_ANSWER` / `READING` / `WRITING` / `OTHER`（复用 `试卷作答与题型交互-设计稿` 里已经定好的规范）。
3. **分值必须给**：整卷总分 = 各题分值之和，后端按 `PaperTree.recalculate()` 汇总，模型给的建议值只作参考。
4. **选项必须是 `{key,text}` 对象数组**，key 用 A/B/C/D；模型返回字符串数组时后端按 A/B/C/D 补齐（切题链路已有这段兜底逻辑，直接复用）。
5. **答案规范**：单选 `"C"`、多选 `"BD"`、填空为文本、简答/作文给评分要点（`keyPoints` + `scoringRubric`）。
6. **去重**：把该学科/知识点最近 N 次的题干传入 Prompt（复用 `HistoricalQuestion` 机制），要求"不得重复以下题目"。

### 3.5 组卷的容量与降级

- 题量硬校验复用 `components/knowledgebaseInterview/interviewCapacity.ts` 的思路（前端 + 后端都校验）；
- 单个知识点题量不足时，按 `priority` 从同板块其它知识点补；
- **组卷失败的分级降级**：结构化输出解析失败 → 重试（`StructuredOutputInvoker` 已有）→ 仍失败则减少题量重试一次 → 最终失败给出可读原因（复用本轮新增的 `AiErrorMessages`）。

## 4. 题型 × 作答控件 × 学科映射

| 题型 | 作答控件 | 语文 | 数学 | 英语 |
| --- | --- | --- | --- | --- |
| `SINGLE_CHOICE` | 选项卡片（radio），点选即选 | 现代文/古诗文选择题 | 选择题 | 阅读理解、单选 |
| `MULTI_CHOICE` | 选项卡片（checkbox），支持部分分 | 少用 | 多选 | 少用 |
| `FILL_BLANK` | 单行/多行输入框；多个空用 `____` 占位并编号 | 名篇名句默写 | 填空 | 语法填空 |
| `SHORT_ANSWER` | 多行文本框 + 字数统计 + 评分要点提示 | 简答题 | 解答题（分步作答） | 短答 |
| `READING` | **材料原文常驻上方 + 子题在下方**（MATERIAL 节点） | 现代文/文言文阅读 | — | 阅读理解 |
| `WRITING` | 多行文本框 + 字数统计 + 计时提示 | 作文（≥800 字） | — | 书面表达（≥100 词） |
| `OTHER` | 退化为多行文本 | 兜底 | 兜底 | 兜底 |

### 4.1 阅读题的三种形态（重点）

阅读题的价值在于**原文必须和题目在一起**，实现上全部映射到 `MATERIAL` + `QUESTION` 组合：

1. **单材料多题**（语文现代文）：一个 `MATERIAL` + N 个 `QUESTION`，原文在题目上方可折叠/粘性；
2. **多材料对比**（语文实用类、英语阅读 A/B/C/D）：`SECTION` 下并列多个 `MATERIAL`，题目放在最后；
3. **完形填空**（英语）：`MATERIAL`（带编号空格的原文）+ N 个 `FILL_BLANK`/`SINGLE_CHOICE` 子题，**选项挂在各自的子题上**（不复用整块选项，避免歧义）。

交互要求：

- 原文区域在作答时**默认展开**，滚动时不遮挡当前题目（sticky 头部或分栏）；
- 交卷后报告里原文同样展示，并在解析中标出与该题相关的段落（P1：AI 给出 `evidence` 字段）。

### 4.2 客观题与主观题的判分分工

```
交卷
 ├── 客观题（SINGLE_CHOICE / MULTI_CHOICE / FILL_BLANK 且答案确定）
 │     → ObjectiveAnswerGrader 本地判分，auto_scored=true，不调模型
 └── 主观题（SHORT_ANSWER / WRITING / 开放填空）
       → UnifiedEvaluationService 分批 LLM 批改（按分值加权 + 汇总）
```

这条链路在试卷分析里已经跑通（实测：8 道选择题零模型调用、批改 4 秒），模拟测验直接复用即可。

## 10. 风险与已知坑（本会话已经踩过的，务必注意）

| 风险 | 说明 | 对策 |
| --- | --- | --- |
| **单次 AI 调用超过 60 秒会被重置** | Spring AI 的 OkHttp 客户端硬编码 `pingInterval=1 分钟`，长非流式调用会被重置并重试 3 次（约 181 秒后失败） | 组卷用**非推理模型** + 关闭 `enable_thinking`（已配置）；题量分批；P1 可改流式 |
| 出题耗时 | 一次组卷可能 10~30 秒 | 走异步（Redis Stream）+ 前端轮询状态，复用现有 `question_gen_status` 机制 |
| 题型/选项格式漂移 | 模型可能返回字符串数组或漏 `questionType` | 复用切题链路的兜底（补 A/B/C/D 标签、非法题型改写并记 warning） |
| 阅读材料过长 | 材料 + 题目容易超 token 预算 | 单题材料上限 + 超长截断 + 分批；`APP_PAPER_EXTRACTION_*` 那组参数可复用 |
| Provider 模型以数据库为准 | `.env` 的 `AI_MODEL` 只在库为空时生效 | 切换模型走「设置 → 模型 Provider」，或改库后重启 |
| SSE 异步派发 | 流式接口在 ASYNC/ERROR 派发阶段会丢认证上下文（已修） | 沿用现有 `JwtAuthenticationFilter` 的 async 处理，不要再写只跑 REQUEST 的过滤器 |
| 老数据兼容 | 已完成的面试会话没有 `paper_json` 的题型字段 | 报告渲染保持"无题型退化为文本"，与 `QuestionAnswerInput` 的降级一致 |
