# 模拟测验考试科目化 · 设计稿

> 状态：已实现
> 日期：2026-10-27
> 范围：把当前「语数英」模拟测验重构为「考试 → 科目 → 考点」的个人考证备考结构，
> 并支持用户自定义科目、题目类型与默认分值。
> 关联：`docs/改造说明.md`、`docs/design/模拟测验模块改造方案.md`。

## 0. 目标与非目标

### 0.1 目标

- 内置多组考证/能力测评科目，按考试分组展示。
- 用户可自定义科目：名称、所属考试、考点、允许题型、每题型默认分、建议时长、大纲文本。
- 新增「判断题」与「案例分析」两种题型。
- 沿用现有 `PaperTree` 整卷作答、判分、报告链路，不另建答题 UI。

### 0.2 非目标（本期不做）

- 生成题的答案一致性复核（与上传试卷的答案键假共识风险合并单独处理）。
- 异步组卷（保持同步创建 + 前端加载态）。
- 资料库出题并入测验、逐考点绑定参考资料。
- 考试层完整 CRUD（系统考试固定 + 内置「其他/自定义」桶）。
- 考点级题型覆盖、逐考点分值。
- 内部命名与表名迁移（`skill` / `interview` 暂不改名）。

## 1. 领域模型与既定决策

| 决策 | 结论 |
| --- | --- |
| 层级 | 考试 → 科目 → 考点（考点平铺、可排序） |
| 难度 | 沿用 `junior/mid/senior`，展示为 基础/中等/进阶 |
| 考试 | 系统内置；自定义科目可挂到系统考试或「其他/自定义」桶 |
| 自定义科目归属 | 仅本人可见，数据带 `owner_id` 与 `is_system`，分享留待后续 |
| 自定义科目配置 | 名称、说明、所属考试、考点、题型+默认分、建议时长（仅展示）、整科大纲文本 |
| 创建入口 | QuizHub 弹层；「我的科目」分组带编辑/删除 |
| 复制内置科目 | 支持「复制为我的科目」 |
| 删除 | 软删除 + 组卷参数快照，历史报告照常 |
| 知识来源 | 用户考点 + 大纲文本注入 prompt；资料库绑定留待后续 |
| 路由 | 保留 `/quiz*`，只改可见文案与导航 |

### 1.1 默认清单

| 考试 | 科目 | 允许题型（默认分） |
| --- | --- | --- |
| 中小学教师资格（小学） | 综合素质（小学） | 单选(2)、案例分析(14)、写作(50) |
| 中小学教师资格（小学） | 教育教学知识与能力（小学） | 单选(2)、简答(10)、案例分析(20)、写作(40) |
| 初级会计 | 初级会计实务 | 单选(2)、多选(2)、判断(1) |
| 初级会计 | 经济法基础 | 单选(2)、多选(2)、判断(1) |
| 计算机专业能力（后端方向） | 数据结构与算法 | 简答(10)、单选(2)、判断(2) |
| 计算机专业能力（后端方向） | 计算机网络 | 简答(10)、单选(2)、判断(2) |
| 计算机专业能力（后端方向） | 操作系统 | 简答(10)、单选(2)、判断(2) |
| 计算机专业能力（后端方向） | 数据库 | 简答(10)、单选(2)、判断(2) |

计算机类按「后端面试风格、简答为主」命题，简答约 70%、客观题约 30%。旧「语数英」归档到
独立的「中小学/学科练习」分组，不进默认考证列表。

## 2. 影响面

- 新增：quiz 模块的自定义科目持久化、目录聚合、组卷题型权重；数据库迁移一条。
- 修改：`InterviewSkillService` 类目加载（考试分组与题型配置）、`InterviewQuestionDTO`
  题型常量、`ObjectiveAnswerGrader` 判断题判分、`quiz-paper-generation-*.st` 命题语境。
- 前端：`QuizHubPage` 考试分组与自定义科目弹层、`QuestionAnswerInput` 判断题渲染、
  `api/quiz.ts`、`types/quiz.ts`、`Layout` 文案。
- 不碰：试卷识别/切题/答案键、资料库、认证、语音后端；既有 `practice_sessions.skill_id`
  字段继续沿用，内部命名不迁移。

## 3. 数据模型

- 系统目录继续放 classpath，沿用现有 `skills/` 机制，新增 `skills/_exams.yml` 描述考试
  （含内置「其他/自定义」桶）。
- 系统科目的 `skill.meta.yml` 增加 `examCode`、`questionTypes[{type, defaultScore, weight}]`、
  `suggestedMinutes`。
- 新增表 `quiz_subjects` 仅存自定义科目；系统科目不落库，运行时由 `QuizCatalogService` 合并。

```sql
CREATE TABLE quiz_subjects (
  id            BIGSERIAL PRIMARY KEY,
  subject_code  VARCHAR(64) NOT NULL,
  owner_id      BIGINT NOT NULL,
  exam_code     VARCHAR(64) NOT NULL,
  name          VARCHAR(64) NOT NULL,
  config_json   TEXT NOT NULL,
  deleted_at    TIMESTAMPTZ,
  created_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at    TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (owner_id, subject_code)
);
```

- `config_json` 存：`description`、`knowledgePoints[{code,label}]`、
  `questionTypes[{type,defaultScore,weight}]`、`suggestedMinutes`、`outlineText`、`clonedFromCode`。
- 第一版考点用 JSON 存储，不做独立表；「知识点掌握度」落地时再提升为实体。
- 自定义科目软删除；历史会话靠 `quiz_config_json` 快照照常展示。
- 组卷入参 `skillId` 语义变为「科目代码」，字段名不改，避免破坏旧接口。
- 自定义科目唯一标识 `subject_code` 由后端生成（如 `custom-<uuid8>`），用户只填显示名。

## 4. 题型与判分

- `InterviewQuestionDTO` 增加 `TYPE_TRUE_FALSE`、`TYPE_CASE_ANALYSIS` 两个常量。
- 判断题生成 `options=[{A,正确},{B,错误}]`，前端按单选渲染，`ObjectiveAnswerGrader` 按单选
  同路径本地判分。
- 案例分析前端按多行文本渲染，走 `UnifiedEvaluationService` 主观批改，不新增判分引擎。
- `QuizPaperService.VALID_TYPES` 扩到 9 种：单选、多选、判断、填空、简答、阅读、写作、
  案例分析、其他；`defaultScore` 与题型权重从科目配置读取，模型可回填每题实际分值，
  总分由后端汇总。

## 5. 后端接口

```text
GET    /api/quiz/catalog                      考试→科目→考点→题型+默认分（系统+我的科目）
POST   /api/quiz/subjects                     新建自定义科目
PUT    /api/quiz/subjects/{subjectCode}       编辑自定义科目
DELETE /api/quiz/subjects/{subjectCode}       软删除自定义科目
POST   /api/quiz/subjects/clone               复制系统科目为我的科目
POST   /api/quiz/sessions                     沿用，组卷（skillId=科目代码）
GET    /api/quiz/sessions/{id}                沿用
POST   /api/quiz/sessions/{id}/submit         沿用
GET    /api/quiz/sessions/{id}/report|details|export  沿用
GET    /api/quiz/history                      沿用
POST   /api/quiz/sessions/{id}/retry          沿用
GET    /api/quiz/wrong-questions              沿用
POST   /api/quiz/wrong-questions/retry        沿用
```

- 科目管理接口全部走 `OwnerScope` 归属校验；`GET /api/quiz/catalog` 返回系统科目 + 当前用户
  自定义科目。
- 保留 `GET /api/quiz/subjects` 作为兼容别名，前端迁到 `catalog` 后下个迭代再删。

## 6. 组卷流程

- `QuizPaperService.generate` 读取统一 `SubjectCatalog`：科目名、考试名、允许题型、默认分、
  题型权重、考点、大纲文本。
- 分配顺序：选中的考点平均分题量 → 每个考点内按题型权重选型 → 优先主题型
  （计算机类简答约 70%）。
- 系统 prompt 从「高中学科」改为「{examName} 的 {subjectName} 命题教师」，注入大纲/参考文本；
  自定义科目注入用户填写的考点与 `outlineText`。
- 判断题、案例分析的输出规范写进 prompt 输出约束，后端在 `normalizeType` 补兜底。

## 10. 阅读材料截断与题料一致性（追加修复）

> 状态：已实现
> 日期：2026-10-27
> 触发：自定义「托福考试」科目组卷后，阅读材料被截到 1200 字并带「……（后文略）」，
> 但题目仍考到被截掉的后半段（如 green infrastructure），出现「题目在、材料缺」。

### 10.1 根因

- 材料上限写死 1200 字，托福阅读一篇约 3500+ 字，必然装不下。
- system prompt 要求「完整原文」，user prompt 又限「不超过 1200 字」，自相矛盾。
- `QuizPaperService` 生成后硬截断材料并加「……（后文略）」，但题目基于截断前的完整原文命制。

### 10.2 方案（按默认决策实施）

1. **分档预算**：`QuizProperties` 新增
   `maxReadingMaterialCharsPerMaterial=4000`、`maxLongReadingSectionsPerPaper=1`，
   `maxTotalMaterialChars` 由 3600 上调到 6000。阅读型板块单篇 4000，普通板块维持 1200。
   同时同步 `application.yml` 的 `app.quiz.*`：新增
   `max-reading-material-chars-per-material`、`max-long-reading-sections-per-paper`，
   并把 `max-total-material-chars` 的 yml 默认值从 3600 改为 6000。
   **只改 Java 字段默认值不够**：yml 里的 `${APP_QUIZ_MAX_TOTAL_MATERIAL_CHARS:3600}`
   会覆盖类默认值，必须一起改，否则 4000 字阅读材料仍会因总量超限被丢弃。
2. **阅读型板块判定**：板块有 material 且（考点中文名/标题命中关键词「阅读 / 完形 / 文言文」，
   或板块内存在 `READING` 题型）即为阅读型。考点中文名优先用科目配置 `categories` 的 label
   兜底，避免模型只回 knowledgeCategory 的 key。
3. **Prompt 对齐**：system prompt 与 user prompt 统一为「材料必须在板块上限内完整，先压缩到
   上限以内、再基于压缩后的原文出题」，并要求题目只能考最终材料里有的内容。
4. **段落边界截断**：新增 `truncateMaterial`，优先落在段落边界、其次句末，不再切断在单词中间。
5. **宁缺毋错**：阅读型板块材料一旦被截断、或整卷材料累计超上限，整板块丢弃并记 warning，
   提示用户重试；不保留「半截材料 + 越界题」。

### 10.3 影响面

- 修改：`QuizProperties` + `application.yml`（分档配置与 yml 同步）、
  `QuizPaperService`（分档上限、段落截断、阅读型判定、丢弃兜底）、
  `quiz-paper-generation-system.st` / `-user.st`（材料预算与题料一致措辞）。
- 测试：新增 `QuizPaperServiceTest`（段落截断、阅读型判定、截断丢弃）；`QuizPromptRenderTest`
  补 `maxReadingMaterialChars` 变量。
- 不碰：`PaperTree`、作答/批改/报告、目录聚合、自定义科目落库结构、前端。

### 10.4 验收

- 阅读材料被截断时整板块丢弃并 warning，不产出错卷。
- `:app:compileJava` / `compileTestJava` 通过；`QuizPaperServiceTest` 7 例、`QuizPromptRenderTest`
  全过。
- `application.yml` 默认值为：普通 1200 / 阅读 4000 / 整卷 6000 / 长阅读板块 1。

### 10.7 托福阅读测试大纲（可直接粘贴到自定义科目）

测试配置建议：考点只保留 1 个「阅读理解」；题型为单选（默认 2、权重 6）、多选（默认 2、权重 1）、
阅读（默认 5、权重 1）；题量 8。这样整卷就是一篇完整文章 + 8 题，便于验证题料一致性。

```text
【科目定位】
托福 iBT 学术阅读模拟。面向出国留学备考，训练学术文章的事实定位、否定判断、推理、词汇语境义、修辞目的、句子简化和篇章总结能力。

【练习结构】
- 一套只出一篇完整学术文章，配 8 道题，全部基于同一篇文章。
- 本测试版不考听力、口语和写作。

【文章要求】
1. 题材取自大学通识学科：生命科学、地球与环境、历史与人类学、艺术与文学、社会科学、天文与物理。
2. 篇幅约 600–650 个英文单词（约 3500–3900 字符），控制在 3900 字符以内。
3. 结构完整：标题 + 引言段 + 3–4 个主体段 + 结尾段。必须给出完整原文，不得出现「……（后文略）」「以下省略」等截断标记，不得只给摘录。
4. 学术英语风格，难度接近托福 iBT 阅读；允许少量生词，但必须能由上下文推断。
5. 全文围绕一个中心论点展开，段落之间用因果、对比、举例、让步等逻辑衔接。

【题型覆盖（8 题）】
1. 事实信息题 ×2：定位并复述文中明确信息。
2. 否定事实题 ×1：判断哪项未在文中提及。
3. 推理题 ×1：基于文中信息做一步推理。
4. 词汇题 ×1：考查单词或短语在语境中的含义。
5. 修辞目的题 ×1：判断某句或某段在文中的作用。
6. 句子简化题 ×1：选择与原句意思最接近的表述。
7. 篇章总结题（多选）×1：选出最能概括文章主旨的若干项。

【命题红线】
- 所有题目必须仅凭所给文章作答，不得引用文章之外的背景知识或细节。
- 题目只能考最终 material 里出现过的内容；材料没有写到的细节，不得作为正确答案或干扰项的依据。
- 若篇幅超出上限，先压缩到上限内再出题，不得先按长文出题再截断材料。
```

若想要更接近真实托福的约 700 词长文，可把 `APP_QUIZ_MAX_READING_MATERIAL_CHARS` 调到 4500
（默认 4000）后重启；当前大纲按 3900 字符以内设计，用默认值即可稳定通过。
