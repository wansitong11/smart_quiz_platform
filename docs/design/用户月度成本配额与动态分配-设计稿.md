# 用户月度成本配额与动态分配 设计稿

> 状态：已实现（2026-11-07）
> 目标：免费用户按“每月总量池”动态分配人均额度并超额拦截；授权用户豁免、不计入总量池；用户端用圆环展示额度。

> 实施结果：后端已完成月度总量池、动态人均额度、免费/授权/管理员路由、人民币记账、
> 同步与异步入口预占结算、用户额度接口和管理端配置；前端已完成额度圆环、额度总池配置、
> 用户授权开关和用户配额列表。同一操作号预占已做幂等保护；“开始作答”内部触发的自动重切
> 使用独立异步操作号和独立预占，避免同步请求结算后后台重切成本丢失。用户端展示已改为
> 只显示月度累计百分比，不再显示总额和余额；管理员调整总量或免费用户数时，已有百分比不回跳，
> 下一笔真实调用再按当时人均额度继续累加。实时语音 WebSocket
> 的 ASR/TTS 成本仍未纳入额度，已登记到
> `docs/待优化事项.md`。
>
> 2026-11-07 补充：当月首次读取额度时，会从 `ai_call_events` 明细账本回填本月历史成本，
> 不要求 Redis 键从当月 1 日就开始存在。CNY 明细直接采用账本金额；历史非 CNY 明细
> 按 token 数用当前 CNY 价格重算，避免旧 USD 金额被重复换算放大。回填只补
> `max(账本, Redis)` 的缺口，并写入 `seeded` 标记，后续新调用仍只由结算增量累加，
> 不会重复计数。

## 一、正文

### 1. 目的

把系统每月的 AI 成本控制在管理员设定的一个总量以内（默认 ¥100），并把这份总量**动态、公平地分摊**给普通用户。被管理员“授权”的用户不受总量限制，可以用更好的模型、不限额度。

### 2. 账怎么算

- 管理员设一个**月总量池** `G`，默认 `¥100`，随时可改。
- `N` = 当前**免费用户**人数（不含管理员、不含授权用户）。
- 每个免费用户的**人均月额度** `Q = G ÷ N`，**实时计算、不落库**。人少了每人分得更多，人多了每人分得变少；总量调大调小，所有人的额度同步变。
- 一个用户本月已花的钱记作 `U`。当 `U ≥ Q` 时，该用户本月不能再使用任何需要大模型的功能。
- 用户看到的进度记作 `P`，按自然月单独累计。每次真实模型调用结算时，
  `P += 本次真实费用 ÷ 当时的人均额度 × 100%`；管理员之后调整 `G` 或 `N` 不会反向改写已有的 `P`。
- 因为 `Q = G ÷ N`，即使所有免费用户都用满，总额正好等于 `G`，所以天然不会超预算。

**模型分档**

- 免费用户：文本、识图都走 `qwen3.7-flash`（输入 ¥0.2/百万，输出 ¥0.8/百万）。
- 授权用户：文本、识图都走 `qwen3.8-flash`（输入 ¥0.8/百万，输出 ¥2.7/百万）。
- 系统后台、没有用户上下文的调用：走 `qwen3.8-flash`（系统默认）。

一份卷样本（约 6.5 万输入 + 2 万输出）的费用：免费档约 ¥0.03，授权档约 ¥0.11。授权档单次贵约 3.6 倍，但因为授权用户不占池、不限额度，贵多少只影响真实总支出，不影响免费用户的人均额度。

### 3. 谁算“授权用户”

用户表上新增一个**档位**标记，只有两个值：`FREE`（免费）和 `AUTHORIZED`（授权）。新注册用户默认 `FREE`；管理员在用户管理里把某个账号勾成“授权”。管理员账号本身永远豁免，不受任何额度限制。

档位同时决定两件事：一是走哪个模型（免费→3.7，授权→3.8），二是是否占用总量池（免费占池，授权不占池、不限额度）。

### 4. 额度分配与重置

- **分配**：额度不预发，按 `Q = G ÷ N` 现算，用于真实费用拦截。展示进度 `P` 是独立的月度累计值：
  管理员调大总量或免费用户减少时，已有 `P` 不变；下一次模型调用因 `Q` 变大而增加得更少。
  反之，调小总量或用户增多时，已有 `P` 仍不变，下一笔调用增加得更多。
- **重置**：按**自然月**。每个自然月一个独立的计数键（键里带年月）。每月 1 日 0 点起用新键，所有免费用户的上月已用自动清零，额度按当月最新的 `G`、`N` 重算。
- **超额**：真实费用仍按 `U ≥ Q` 立即拦截，确保不会悄悄突破总量池；展示进度 `P` 不参与回算，
  只在下一次模型调用结算时继续增长。

### 5. 额度怎么记账

复用现有的“**先预占、后按真实消耗结算**”机制，只是把统计口径从“用户×功能×日/月”改成“用户×自然月”，并把币种从美元换成人民币。

- **预占**：一次 AI 操作开始前，按预估成本在“本月已用 + 已预占”里占坑。占坑后超过人均额度就当场拒绝，不产生调用。
- **结算**：操作结束后，用真实 token 数算出的真实成本，把预占撤销、把真实金额记进本月已用。
- **释放**：操作失败或没产生任何调用时，把预占全额退回。
- **历史回填**：当月第一次读取已用额度或进度时，从调用明细账本汇总本月成本并补进 Redis：
  账本总额大于 Redis 已用时才抬高已用；百分比取“账本总额 ÷ 当前人均额度”和已有百分比的
  较大值。之后只靠结算增量增长，不回扫明细，也不会把同一笔成本加两次。

授权用户和管理员：预占、结算阶段跳过额度判断和计数，但真实成本仍会记进调用事件流水，供管理员后台审计，只是不参与 ¥100 池的拦截。

### 6. 超额拦截哪些功能

只拦截**需要大模型参与**的入口，普通浏览、查看历史、编辑非 AI 内容不受影响。需要拦截的包括：试卷上传/导入/切题识别、模拟测验生成题目、问答助手、知识库上传（向量化）、答案批改、口语评测等。

拦截发生在**使用时**：按钮不提前置灰，用户点下去，后端在真正调模型前拒绝，前端弹出“本月 AI 额度已用完，X 月 1 日 0 点重置”。异步任务必须在**入队前**就检查，避免后台继续悄悄烧钱。

### 7. 用户看到的额度

登录后的侧边栏用户名区域，只显示一个**百分比圆环**，例如 `35% / 100%`，不再显示实际总额和剩余余额。
百分比最多保留两位小数；小额调用显示为 `0.16% / 100%`，不会被整数取整成 `0%`。
已显示的百分比不会因管理员调整总量、免费用户增减而回跳；只有发生新的模型调用并完成结算后，
才按当时的人均额度继续增加。增加到 100% 时圆环转为警示色。授权用户和管理员不显示圆环，显示“不限额度”。

### 8. 管理端

- 一个“月总量池”配置项，默认 ¥100，管理员可改，改完立即生效（所有人的额度随之变）。
- 用户列表增加“授权”开关，勾选即豁免并切到 3.8 模型。
- 现有的 RPM/TPM/并发限流配置保留；原有的“按功能设置日/月成本上限”下线，成本口径统一为新的用户总配额。

### 9. 币种

全链路统一改人民币：价格表存“元/百万 token”、记账用“微元（micro-CNY）”、界面显示“¥”。历史数据仍带当时的币种标记，不做换算。

### 10. 边界与失败模式

- 免费用户人数 `N` 为 0 时，没有分摊对象，不阻断任何调用（只有授权/管理员时等于无人受限）。
- 人均额度 `Q` 被除到极小（人数极多）时，正常一份卷可能就超，这是“总量÷人数”的必然结果；管理员应调大总量或给高频账号授权。
- Redis 计数键带年月，即使服务重启也不丢账；键设置一个较长的过期时间仅作清理兜底，不参与“是否重置”的判断。
- 授权档位在操作进行中被人从“免费”改成“授权”，该次操作按发起时的档位结算，避免中途口径漂移。
- 预占后长时间不结算的“僵尸预占”，沿用现有对账任务定时释放，避免虚假占用额度。

### 11. 可改点汇总

- 改总量：管理端“月总量池”或默认配置。
- 改模型单价：价格表（元/百万 token）。
- 改分档模型：免费档指向的 provider 配置。
- 改重置周期：现在按自然月，键里带 `yyyyMM`；想改周/日，把键粒度换成对应周期即可。
- 改超额文案：统一在异常与前端提示两处。

BigDecimal monthlyQuotaCny(Long userId) {

**预占**（复用现有 `ai_budget_reserve.lua`，软上限传与硬上限相同即等于不设软门）：

```java
public BudgetDecision reserve(String operationId, Long userId, AiFeature feature, BigDecimal estimatedCny) {
  boolean exempt = accessPolicy.isExempt(userId);
  saveOperation(operationId, userId, feature, estimatedCny, exempt); // 记录 exempt 快照
  if (exempt) return BudgetDecision.PASS; // 不触碰配额计数
  BigDecimal q = monthlyQuotaCny(userId);
  if (q == null) return BudgetDecision.PASS;
  int r = reserveMonth(userId, toMicro(estimatedCny), toMicro(q));
  if (r < 0) {
    releaseMonth(userId, toMicro(estimatedCny)); // 同 key，仅预占成功时才有值，clamp 到 0
    return BudgetDecision.HARD_LIMIT;
  }
  return BudgetDecision.PASS;
}
```

`reserveMonth` 调 `reserve.lua`，KEYS=`[quotaKey(ym,userId,"used"), quotaKey(ym,userId,"reserved")]`，ARGV=`[estMicro, qMicro, qMicro, monthTtlSeconds]`；`monthTtlSeconds=45*86400` 仅作清理兜底，重置由 `ym` 变化实现。

**结算 / 释放**（`finalize`）：

```java
public void finalize(String operationId) {
  op = find(operationId); if (op==null || status != RESERVED) return;
  calls/cost = redis 读取;
  if (Boolean.TRUE.equals(op.getExempt())) {
    op.setActualCost(...); op.setStatus(SUCCEEDED); // 只记录，不 settleMonth
  } else if (calls > 0) {
    settleMonth(op.userId, op.estimatedCost, actualCny);
    op.setActualCost(actualCny); op.setStatus(SUCCEEDED);
  } else {
    releaseMonth(op.userId, op.estimatedCost); op.setStatus(RELEASED);
  }
  save(op); delete per-op calls/cost;
}
```

`settleMonth` / `releaseMonth` 复用 `ai_budget_settle.lua` / `ai_budget_release.lua`，key 用 `quotaKey`。

### D. 状态与分支（完整）

**reserve 决策**

| 条件 | 结果 |
|---|---|
| userId 为 null（系统任务） | 不豁免、无额度归属：`saveOperation` 用 system 归属或跳过，返回 PASS，不入池 |
| admin / authorized | 记录 exempt 快照，返回 PASS，不占池 |
| `used + reserved + est > Q` | 退回本次预占，返回 HARD_LIMIT，抛 `AiBudgetExceededException` |
| 否则 | 入池预占，返回 PASS |

**finalize 分支**

| op 状态 | 分支 |
|---|---|
| 不存在 / 非 RESERVED | 直接返回 |
| exempt=true | 记录 actual，置 SUCCEEDED，不入池 |
| 非 exempt 且 calls>0 | settleMonth 入池，置 SUCCEEDED |
| 非 exempt 且 calls=0 | releaseMonth 退回，置 RELEASED |

**额度展示分支**

| 用户 | 展示 |
|---|---|
| 免费且未到 100% | 圆环显示累计 percent，文字 `X% / 100%`；总量或人数变化不回跳 |
| 免费且达到 100% | 圆环 100% 警示色，文字 `100% / 100%` |
| 授权 / 管理员 | 不显示圆环，显示“不限额度” |

### F. 错误码与文案

- 复用 `interview.guide.common.exception.AiBudgetExceededException`（若已存在专用 code 则沿用，否则新增 `AI_QUOTA_EXCEEDED`）。
- 文案：`本月 AI 额度已用完，{下月1日 0 点} 重置`。下月 1 日由 `YearMonth.now(ZoneId.of("Asia/Shanghai")).plusMonths(1).atDay(1)` 计算。
- 前端 `request.ts` 响应拦截或各 AI 入口 catch 该 code，统一 toast。

### G. 前端改造点

1. `types/auth.ts`：`CurrentUser` 增加 `tier?: 'FREE' | 'AUTHORIZED'`。
2. `api/aiCost.ts`：`aiUsageApi` 增加 `quota: () => request.get<QuotaView>('/api/ai-usage/quota')`；新增 `QuotaView` 接口（`tier/unlimited/percent`）。
3. `components/Layout.tsx`：底部用户区域加 `QuotaRing`（SVG `circle`，`stroke-dasharray = C * percent/100`，`C` 为圆周长；下方文字 `{percent}% / 100%`；`unlimited` 时显示“不限额度”）。数据在组件挂载时拉一次 `aiUsageApi.quota()`，并可在路由变化时刷新（保证动态额度及时体现）。
4. 管理端：总量池编辑（读/写 `/api/admin/ai-cost/quota-config`）；用户列表加“授权”开关（`PUT /api/admin/users/{id}/tier`）；`UserQuotaPanel` 删除日/月成本字段。

### H. 测试点（后端）

1. 动态人均：`G=100`、`N=50` → `Q=2.000000`；改 `G` 或增减免费用户 → `Q` 变化。
2. 授权豁免：authorized 用户 `reserve` 返回 PASS、`finalize` 不入池；admin 同样豁免。
3. 超额：`used + reserved + est > Q` → HARD_LIMIT，且本次预占被退回。
4. 自然月：`quotaKey` 含 `yyyyMM`；跨月后 `usedCny` 读到新 key 的 0。
5. 币种：`AiCostCalculator` fallback 与 `AiModelPriceEntity` 默认均为 `CNY`。
6. 接口：`GET /api/ai-usage/quota` 对免费/授权/管理员分别返回正确 `unlimited/percent`。
7. `percent` 边界：0、100、超额截断到 100；管理员调整总量或免费用户数后，已有 percent 不变。
8. 下一次调用：真实费用按新的 `Q` 折算增量，`Q` 变大时增长变慢，`Q` 变小时增长变快。
9. 历史回填：当月 Redis 无 `used/percent` 时，按 `ai_call_events` 汇总本月成本后初始化；
   CNY 明细直接取值，历史非 CNY 明细按当前 CNY 单价和 token 重算。
10. 去重：已有 Redis 已用值大于账本汇总时不回退、不重复累加；写入 `seeded` 后新调用只走结算增量。

### I. 迁移与回滚

- DDL 为增量 `ALTER TABLE ... ADD COLUMN`，带默认值，旧数据自动为 `FREE`，可平滑上线。
- `ai_usage_operations.exempt` 默认 false，历史行按非豁免处理，与新逻辑兼容。
- 旧 `ai:budget:day/month:{userId:feature}:...` 键不再读写，可保留等 TTL 自然过期，不影响新逻辑。
- 若需回滚：恢复 `AiBudgetService` 旧实现与价格表 USD 行即可；新增的 `tier` 列默认 `FREE` 不影响回滚后行为。
