## 一、正文（给产品 / 给人看）

### 1. 目的

普通用户默认走「免费/低档模型组合」（硅基流动极低成本模型）；管理员可决定每个用户实际调用哪个
「文字模型」和哪个「识图模型」，支持单个或批量修改，改完立即生效。Embedding 不开放按用户绑定，
保持全局统一。

### 2. 触发

管理员打开「AI 调用与成本 → 模型分配」页签，对单个用户或勾选多个用户，设置其文字/识图模型，
或点「恢复默认」。

### 3. 规则与步骤

1. 新增一张表 `ai_user_model_override`：每个用户最多两条记录，一条 `TEXT`（文字）、一条 `VISION`（识图）。
   没有记录 = 继承平台默认。
2. 解析优先级（每次真实调用时决定用哪个模型）：
   - 文字：调用方显式指定的 provider > 该用户绑定（TEXT）> 全局默认文字 provider > yml 兜底。
   - 识图：调用方显式指定的 provider > 该用户绑定（VISION）> 全局默认识图 provider > yml。
   - Embedding：始终走全局默认，不查绑定。
3. 实时生效：绑定表每次调用现查数据库（不缓存），所以改用户绑定立即生效；改 provider 的 `model`
   本来就会清缓存（`registry.reload()`）；改全局默认也是每次现查。三条路都不需要重启。
4. 解析发生在 `LlmProviderRegistry`：它从 `AiCallContextHolder` 读当前 `userId`
   （同步请求由 `@AiCost` 注入，异步由 Redis Stream 透传回填），有 userId 才查绑定；
   读不到就按系统任务走全局默认。因此不需要逐个业务调用点传 userId。
5. 管理员保存时校验：provider 必须存在且启用；识图 provider 还必须标记了「支持图片输入」。
6. 审计：记录 `updated_by`（哪个管理员改的）和 `updated_at`（何时改的）。

### 4. 结果

保存后，该用户下一次任何文字/识图调用（出题、批改、问答、试卷导入识图等）都解析到新模型；
成本账本也按实际解析到的模型计费。

### 5. 边界与异常

- 绑定指向的 provider 被禁用或删除：解析时回退全局默认并记 `warn` 日志——不会把用户所有 AI 调用卡死，
  也不会静默升到高成本模型（回退目标是低成本默认池）。这是可改点。
- 调用方显式写死 provider 的场景（语音模块、某些 feature 级配置）不受绑定影响。
- Embedding 绑定不开放：不同 embedding 模型维度不一致会破坏 1024 维向量空间。
- 批量是「把同一份绑定覆盖到所有选中用户」；要保留某维度就在界面传当前值，不做「部分字段不覆盖」的混合语义。

### 6. 可改点

- 是否给绑定表加短 TTL 缓存（默认现查 DB；AI 调用本身慢，一次索引查询可忽略）。
- 绑定失效策略：回退全局默认 vs 直接报错（默认回退）。
- 是否开放 Embedding 绑定（默认不开放）。
- 「模型分配」是否用独立权限点（默认复用 `ai:cost:view`）。

3. 新增以下私有方法：

```java
private String resolveProviderId(String providerId) {
  if (providerId == null || providerId.isBlank() || "default".equalsIgnoreCase(providerId.trim())) {
    return resolveChatProviderIdForCurrentUser();
  }
  return providerId;
}

private String resolveChatProviderIdForCurrentUser() {
  Long userId = currentUserId();
  if (userId != null && userModelOverrideRepository != null) {
    String override = userModelOverrideRepository
        .findByUserIdAndModality(userId, UserModelOverrideEntity.TEXT)
        .map(UserModelOverrideEntity::getProviderId)
        .filter(id -> !isBlank(id))
        .orElse(null);
    if (override != null) {
      if (isProviderUsable(override)) { return override; }
      log.warn("用户 {} 的文字模型绑定 {} 不可用，回退全局默认", userId, override);
    }
  }
  return resolveDefaultChatProviderId();
}

private String resolveVisionProviderIdForCurrentUser() {
  Long userId = currentUserId();
  if (userId != null && userModelOverrideRepository != null) {
    String override = userModelOverrideRepository
        .findByUserIdAndModality(userId, UserModelOverrideEntity.VISION)
        .map(UserModelOverrideEntity::getProviderId)
        .filter(id -> !isBlank(id))
        .orElse(null);
    if (override != null) {
      if (isVisionProviderUsable(override)) { return override; }
      log.warn("用户 {} 的识图模型绑定 {} 不可用，回退全局默认", userId, override);
    }
  }
  return resolveDefaultVisionProviderId();
}

private Long currentUserId() {
  AiCallContextHolder.AiCallContext ctx = AiCallContextHolder.get();
  return ctx == null ? null : ctx.userId();
}

private boolean isProviderUsable(String providerId) {
  if (providerRepository == null) { return properties.getProviders().containsKey(providerId); }
  return providerRepository.findById(providerId).map(LlmProviderEntity::isEnabled).orElse(false);
}

private boolean isVisionProviderUsable(String providerId) {
  if (providerRepository == null) {
    ProviderConfig c = properties.getProviders().get(providerId);
    return c != null && Boolean.TRUE.equals(c.getSupportsVision());
  }
  return providerRepository.findById(providerId)
      .filter(LlmProviderEntity::isEnabled)
      .map(LlmProviderEntity::isSupportsVision)
      .orElse(false);
}
```

4. 把三个「取默认文本客户端」的入口从 `resolveDefaultChatProviderId()` 改为 `resolveChatProviderIdForCurrentUser()`：
   - `getDefaultChatClient()`：`return getChatClient(resolveChatProviderIdForCurrentUser());`
   - `getPlainChatClient()`（无参）：`return getPlainChatClient(resolveChatProviderIdForCurrentUser());`

5. 修改 `getVisionChatClientOrDefault(String providerId)` 的空白分支：
   `resolveDefaultVisionProviderId()` → `resolveVisionProviderIdForCurrentUser()`。
6. 保持以下公开 getter 为「纯全局」（不回退当前用户），供 `AiCostEstimator` 与展示使用：
   `getDefaultChatProviderId()`、`getDefaultVisionProviderId()`、`getDefaultChatModelName()`、

步骤映射（零猜测）：

- `listUsers`：用 `UserRepository` 的 `Page<UserEntity>` 查询（`displayName`/`username` 模糊匹配
  `keyword`，否则全量分页），`Pageable` 用 `PageRequest.of(page, size, Sort.by("id"))`；
  对结果页的 `userId` 集合用 `overrideRepository.findAllByUserIdIn(ids)` 一次性取回绑定，
  按 `userId + modality` 组成 `Map<Long, Map<String,String>>`；
  每个用户输出 `UserModelAssignmentItem`（无绑定维度为 null，`updatedAt` 取两条绑定中较新的）。
- `options`：`textProviders` = 所有 `enabled=true` 的 provider（`id` + `model`）；
  `visionProviders` = 所有 `enabled=true` 且 `supportsVision=true` 的 provider。
- `assign(userId, request)`：校验 `userRepository.existsById(userId)`（否则
  `BusinessException(ErrorCode.AUTH_USER_NOT_FOUND, ...)`）；分别调用
  `applyDimension(userId, TEXT, request.textProviderId())` 与
  `applyDimension(userId, VISION, request.visionProviderId())`。
- `assignBatch(request)`：先对 `request.userIds()` 逐一 `existsById` 校验（不存在抛
  `AUTH_USER_NOT_FOUND`，并带 userId）；对文本、识图 provider 各校验一次；再循环调用
  `applyDimension`。

`applyDimension(Long userId, String modality, String providerId)` 私有方法：

- `providerId` 为 null/blank：`overrideRepository.deleteByUserIdAndModality(userId, modality)`，返回。
- 否则校验 provider：`providerRepository.findById(providerId).filter(LlmProviderEntity::isEnabled)`
  `.orElseThrow(() -> new BusinessException(ErrorCode.PROVIDER_NOT_FOUND, "Provider '" + providerId + "' 不存在或已禁用"))`；
  若 `modality == VISION` 且 `!entity.isSupportsVision()`，抛
  `BusinessException(ErrorCode.VISION_PROVIDER_NOT_CONFIGURED, "Provider '" + providerId + "' 未标记为支持图片输入")`。
- upsert：`findByUserIdAndModality` 存在则改 `providerId`，否则新建；
  两者都写 `updatedBy = CurrentUserHolder.requireCurrent().userId()`，再 `save`。

### H. 免费/低档默认组合（本次一并实现）

普通用户（无绑定）的全局默认 = 硅基流动极低成本组合：

| 维度 | provider id | 模型 | 价格（元/百万 Token，待官方复核） |
|------|-------------|------|----------------------------------|
| 文本 | `siliconflow-cheap` | `Qwen/Qwen3-14B` | 输入 0.50 / 输出 2.00 |
| 识图 | `siliconflow-vl` | `Qwen/Qwen3-VL-8B-Instruct` | 输入 0.50 / 输出 2.00 |
| Embedding | `siliconflow-free`（保持不变） | `BAAI/bge-m3` | 免费 |

实现步骤：

1. `application.yml` 的 `app.ai.providers` 增补 `siliconflow-cheap`（文本，`supports-vision:false`、
   `supports-embedding:false`，模型 `Qwen/Qwen3-14B`）与 `siliconflow-vl`（识图，`supports-vision:true`），两者
   `base-url` 与 `api-key` 复用 `PROVIDER_SILICONFLOW_BASE_URL` / `PROVIDER_SILICONFLOW_API_KEY`。
2. `app.ai.free-models.text-provider` 改为 `siliconflow-cheap`、`vision-provider` 改为 `siliconflow-vl`；
   `embedding-provider` 保持 `siliconflow-free`、`activate-embedding` 保持 `false`。
3. `prices/ai-model-prices.yml` 增加 `siliconflow-cheap`（TEXT）与 `siliconflow-vl`（VISION）两条价格。
4. 价格币种口径：现有种子代码把 yml 价格硬编码为 `USD`；本稿价格来自调研文档的**元**报价，
   正式接入前必须统一币种与汇率，并核对当日官方价与准确模型 ID（见 `docs/待优化事项.md`）。
5. 依赖 `.env` 的 `PROVIDER_SILICONFLOW_API_KEY`：无 Key 时按现有规则不切换，
   默认仍回落到 `dashscope`/`dashscope-vl`（安全默认），不会切到空 Key Provider。
