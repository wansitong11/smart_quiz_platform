# 知识库出题改造：生成改为「追加」+ 难度统一为「简单/中等/偏难」

> 状态：**已实现并实测**。

## 一、要解决的问题

1. **生成会覆盖原有题目**：`QuestionGenerationStateService` 原先执行 `deleteByKnowledgeBaseId(kbId)` 再 `saveAll(新题)`，这条 SQL 没有状态过滤，会把该资料下**所有**题目删掉——包含手工新增的、已启用的、已归档的。而生成时又反而把"已有题目"喂给模型让它别出重复的，行为自相矛盾。
2. **难度还是面试口径**：知识库模块前端标签写死 `校招 / 中级 / 高级`；而且传给模型的 prompt 只有裸值 `difficulty: mid`，模型只能猜含义。
3. **Prompt 绑死高考/中学**：知识库出题 prompt 里写着"语言必须是中学考试语体"，学科 persona 写着"高中××命题与阅卷老师，熟悉高考××的考查结构"，难度描述写着"面向高考常规水平/压轴水平"——小学资料也会被按高考标准出题。

## 二、最终方案（用户已拍板）

| 决策点 | 结论 |
| --- | --- |
| 生成方式 | **追加**（不覆盖；默认即唯一行为） |
| 难度三档 | 全平台统一 **简单 / 中等 / 偏难** |
| 难度语义 | 跟着**资料/知识板块本身的学段**走：小学资料出小学题、高中资料才出高中题，不按高考标准拔高 |

### 1. 生成改为追加

- `QuestionGenerationStateService.replaceQuestionsAndComplete` → **`appendQuestionsAndComplete`**：不再删除任何题目，直接 `saveAll`；完成消息改为「新增 N 道题，跳过 M 道重复题，原有 K 道保留」。
- **去重范围扩大**：原先是"本批内按题干去重"，现在同时与**该资料全部已有题目**比对（`KnowledgeBaseQuestionRepository.findQuestionTextsByKnowledgeBaseId`，题干 NFC 归一化后比较），重复的直接跳过、不动旧题。
- 提示词里的 `Existing Questions` 不再只看同难度最新 20 条，而是该资料最新 30 条（**不限难度**），并明确告诉模型"本次是追加、不会覆盖它们，没有新角度可以少出几道"。
- 前端生成弹窗文案同步说明"新题会追加到现有题库，不会覆盖已有题目"。

### 2. 难度统一为「简单 / 中等 / 偏难」

- 新增 `common/model/DifficultyLevel`：编码仍是 `junior / mid / senior`（**库里的既有值不做迁移**），展示标签为简单/中等/偏难；`normalize()` 额外接受 `easy/medium/hard` 与中文，为将来换编码留口子。
- 前端：`constants/knowledgebaseInterview.ts`（知识库模块）、`hooks/useInterviewConfig.ts` 与 `pages/QuizHubPage.tsx`（模拟测验）统一改成 简单/中等/偏难，描述也去掉"合格考/高考"字样。
- 后端：知识库出题与模拟测验组卷都改为给模型传**中文难度描述**（`DifficultyLevel.describe()`：简单＝直接考查基本概念…、中等＝两步以上推理…、偏难＝跨知识点综合…），不再传 `mid` 这种裸编码。

### 3. Prompt 去高考化（学段自适应）

- `knowledgebase-question-generation-system.st`：删掉"必须是中学考试语体"，改为"难度与语体跟着资料本身的学段走（小学按小学、初中按初中、高中按高中），不要一律按高考标准拔高"，知识板块示例同时给出小学（分数的意义）与中学（函数与导数）。
- `knowledgebase-question-generation-user.st`：`difficulty: {difficulty}` 换成中文难度描述 + 一段"按资料学段把握深浅"的说明；分值提示也改成学段无关（小学多小题、分值宜小）。
- 三个学科 persona（`skills/{chinese,english,math}/SKILL.md` 与 `docs/subject-content/` 的暂存副本）：从"高中××命题与阅卷老师，熟悉高考××"改成"按材料所属学段把握深浅，不要一律按高考标准"。

## 三、顺带修掉的 bug：生成过题目的知识库删不掉

验证时发现 `DELETE /api/knowledgebase/{id}` 对**有题目的知识库**直接 500：`knowledge_base_questions.knowledge_base_id` 是指向 `knowledge_bases` 的外键，而 `KnowledgeBaseDeleteService` 只解除了 RAG 会话关联，没删题库，删知识库时违反外键约束。现已在该流程里先删题库再删知识库。

## 四、实测（`scripts/verify-kb-question-append.ps1`）

上传一份「小学数学知识点」资料 → 生成 3 道题 → 再生成 3 道题：

- 第一轮：题库 0 → 3 道；
- 第二轮：3 → 5 道，消息「新增 2 道题，跳过 1 道重复题，原有 3 道保留」——**旧题没被删，重复题被跳过**；
- 生成出来的题目是小学内容（水渠应用题、体积单位换算、盈亏问题、平年判断），语体也是小学的，没有出现高考式命题；
- 删除该知识库返回 200（修复前 500）。
