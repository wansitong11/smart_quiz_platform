# 知识库检索范围与分类 · 设计稿

> 状态：P0 已实现（2026-09-24）
> 需求：① 问答助手不再「必须先选某个知识库」，可以从全部资料里检索；② 后续要能按分类（语文 / 数学 / 英语）限定检索范围；③ 知识库分类本身要有一套能扩展的逻辑。
> 前置：已确认不做老数据兼容（开发库重建即可）。

---

## 一、结论先说

| 问题 | 判断 |
| --- | --- |
| 跨库检索要不要新写一套检索？ | **不用**。`KnowledgeBaseVectorService.similaritySearch` 已经支持「kbIds 为空 = 搜索全部」，卡点在会话层与接口层 |
| 范围怎么表达？ | 会话上加 **`kb_scope`**：`ALL`（全部）/ `CATEGORY`（按分类）/ `SELECTED`（指定资料）。三选一，互斥 |
| 加枚举值算不算破坏扩展性？ | 不算。检索层最终只认「一组 kbId 或空」，范围语义收敛在一个解析器里；以后加「按学科」「按标签」「按题源」只是多一个分支 |
| 分类用字符串还是建表？ | **建表**（`kb_categories`），材料用 `category_code` 外键关联。当前是自由文本，无法重命名 / 排序 / 统一取值 |
| 一份资料能不能属于多个分类？ | P0 先**一对一**（语文/数学/英语本身互斥）；多标签留 P2，等真出现「数学 + 高考真题 + 2024」这类需求再上 |
| 分类 code 用什么词表？ | 直接复用平台的学科 key：`chinese` / `math` / `english`，与 `practice_sessions.subject_category`、skills 同一套，为「资料答疑 → 同科练习」留口子 |

一次跨库提问的链路：

```
会话（kb_scope）
  → ScopeResolver：解析出本次检索的资料范围
        ALL      → 空（= 全部已完成向量化的资料）
        CATEGORY → 该分类下全部资料
        SELECTED → 会话绑定的资料
  → 向量检索（召回池 topK × 3 → 每份资料保底 2 条 → 剩余名额按分数补齐 → 收口 topK）
  → 生成回答 + 标注出处（资料名 · 片段）
  → 提问计数按「实际命中的资料」归位
```

## 二、现状盘点

已有的能力（不用重做）：

| 能力 | 位置 |
| --- | --- |
| 空 kbIds = 全库检索 | `KnowledgeBaseVectorService.similaritySearch(query, kbIds, topK, minScore)` |
| 检索片段带来源 | 向量片段 metadata 里有 `kb_id`；`RagQueryExecution.RetrievedDoc` 已带 metadata |
| 分类字段 | `knowledge_bases.category`（自由文本 + 索引） |
| 分类相关接口 | `GET /api/knowledgebase/categories`、`/category/{category}`、`/uncategorized`、`PUT /{id}/category` |
| 前端分类分组 | `KnowledgeBaseQueryPage` 已按 `category` 分组，并且 `KnowledgeBaseManagePage` 能改分类 |

卡点（要改的）：

| 位置 | 现状 |
| --- | --- |
| `RagChatDTO.CreateSessionRequest` | `knowledgeBaseIds` 带 `@NotEmpty("至少选择一个知识库")` |
| `RagChatSessionService.createSession` | 强校验资料存在，写多对多关联；标题用所选资料名生成 |
| `RagChatSessionEntity` | 只有 `knowledgeBases` 关联，没有范围语义 |
| `KnowledgeBaseQueryService.answerQuestion*` | 开头 `kbIds 为空 → NO_RESULT`，把空当非法 |
| `KnowledgeBaseQueryService` 单次问答 | 用 `knowledgeBaseIds.getFirst()` 当主库，隐含「一定有库」 |
| `KnowledgeBaseCountService.updateQuestionCounts` | 按会话范围全量 +1，跨库时会虚高 |
| 分类是自由文本 | 无法重命名（改名要逐条改）、无法排序、取值会漂（「数学」vs「数学 」）、无法按分类统一取资料 |

## 三、检索范围模型

### 3.1 数据模型

`rag_chat_sessions` 增加两列：

```sql
kb_scope     VARCHAR(16) NOT NULL DEFAULT 'ALL',   -- ALL / CATEGORY / SELECTED
kb_category  VARCHAR(64),                          -- 仅 CATEGORY 有效，存分类 code
CONSTRAINT rag_chat_sessions_kb_scope_check
  CHECK (kb_scope IN ('ALL', 'CATEGORY', 'SELECTED'))
```

- `ALL`：忽略 `kb_category` 与关联表
- `CATEGORY`：检索该分类下的全部资料，忽略关联表
- `SELECTED`：沿用现有的 `rag_session_knowledge_bases`

存**分类 code** 而不是分类名：分类改名后历史的范围仍然有效。

### 3.2 解析器（扩展点）

```java
/** 会话检索范围 → 本次检索要用的资料 ID 集合；空集合表示「全部」。 */
public record ResolvedScope(List<Long> knowledgeBaseIds, ScopeKind kind, String description) {}

public interface RagScopeResolver {
    ScopeKind kind();                                  // ALL / CATEGORY / SELECTED
    ResolvedScope resolve(RagChatSessionEntity session);
}
```

三个实现：`AllScopeResolver`、`CategoryScopeResolver`、`SelectedScopeResolver`，用 `Map<ScopeKind, RagScopeResolver>` 注入。
以后加「按学科」「按标签」「按题源」，只需新增 `ScopeKind` 枚举值 + 一个实现类，检索与前端不用动。

范围解析后统一交给现有的 `similaritySearch(query, kbIds, topK, minScore)`：空 = 全库。

### 3.3 接口变化

| 接口 | 变化 |
| --- | --- |
| `POST /api/rag-chat/sessions` | 请求体改为 `{ scope: "ALL"\|"CATEGORY"\|"SELECTED", categoryCode?, knowledgeBaseIds?, title? }`；`scope` 缺省时按 `knowledgeBaseIds` 是否为空推断（非空→SELECTED，空→ALL） |
| `PUT /api/rag-chat/sessions/{id}/scope` | 新增，替代原来的 `/knowledge-bases`（会话内随时切范围） |
| `GET /api/rag-chat/sessions/{id}` | 返回体补 `scope` / `categoryCode` / 解析后的 `scopeDescription`（如「全部资料」「分类：数学」「2 份指定资料」） |

## 四、知识库分类方案

### 4.1 三个档位

| 档位 | 做法 | 取舍 |
| --- | --- | --- |
| C1 最小 | 沿用字符串，只收敛取值（预置语数英 + 自定义），前端改下拉 | 两小时能做，但改名/排序/统计仍然别扭 |
| **C2 推荐** | 建 `kb_categories` 表，材料用 `category_code` 关联 | 改名一次生效、可排序、可删除迁移、能挂学科 code；改动中等 |
| C3 最灵活 | 多对多标签（`kb_tags` + 关联表） | 能表达「数学 + 高考真题 + 2024」，但和分类语义重叠，检索范围会变复杂，等有真实需求再上 |

### 4.2 表结构（C2）

```sql
CREATE TABLE kb_categories (
  id BIGINT GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
  code VARCHAR(64) NOT NULL,          -- chinese / math / english / 自定义 code
  name VARCHAR(64) NOT NULL,          -- 展示名：语文 / 数学 / 英语
  subject_code VARCHAR(64),           -- 关联平台学科 key，可空（自定义分类不挂学科）
  sort_order INTEGER NOT NULL DEFAULT 0,
  is_system BOOLEAN NOT NULL DEFAULT false,   -- 系统预置（语数英）不可删
  created_at TIMESTAMP(6) NOT NULL,
  updated_at TIMESTAMP(6),
  CONSTRAINT uk_kb_categories_code UNIQUE (code)
);

ALTER TABLE knowledge_bases
  ADD COLUMN category_code VARCHAR(64),
  ADD CONSTRAINT fk_kb_category FOREIGN KEY (category_code) REFERENCES kb_categories(code);
```

预置数据：`chinese/语文`、`math/数学`、`english/英语`（`is_system = true`）。
`knowledge_bases.category` 字符串列直接删掉（不兼容老数据，开发库重建）。

要点：

1. **code 与 name 分离**：会话里存 code，改展示名不影响历史会话；
2. **一份资料一个分类**（P0）：需要跨分类时用 `SELECTED` 范围勾选多份资料；
3. **未分类是一等状态**：`category_code IS NULL`，前端固定分组「未分类」，不新建一个假的分类行；
4. `subject_code` 让分类和学科对齐——「按分类检索」等价于「按学科检索」，将来「资料答疑 → 出同科练习」不用再翻译一层。

### 4.3 接口变化

| 接口 | 变化 |
| --- | --- |
| `GET /api/kb-categories` | 新增，返回分类列表（code / name / 资料数 / 未向量化数） |
| `POST /api/kb-categories` | 新增分类（自定义 code 由前端生成或服务端按 name 生成） |
| `PUT /api/kb-categories/{id}` | 改名 / 排序 / 挂学科 code |
| `DELETE /api/kb-categories/{id}` | 删除，其下资料落回「未分类」（系统分类禁止删除） |
| `GET /api/knowledgebase/list` | 支持 `?categoryCode=`；返回体补 `categoryCode`（`category` 字段继续返回展示名） |
| `PUT /api/knowledgebase/{id}/category` | 入参由「分类名」改为 `categoryCode` |
| `GET /api/knowledgebase/categories` | 由「字符串列表」升级为分类对象列表（前端 KB 管理页与问答页同步改） |

## 五、必须一起处理的细节

| # | 细节 | 做法 |
| --- | --- | --- |
| 1 | **跨库召回与配额** | 向量检索只按全局分数排序，跨库时前 topK 条可能全被单份大资料占满，其它资料连进候选的机会都没有。所以要「先放大召回池、再按资料保底、最后收口」：①按 `topK × candidateMultiplier`（默认 3）召回，给均衡留素材；②按 `kb_id` 分组，每份资料**保底**取 `perKbQuota`（默认 2）条；③剩余名额按全局分数补齐，最后收口到 topK。放大的是候选池，不是送进模型的上下文，token 不变 |
| 2 | **引用来源** | 回答标注「出处：××讲义 · 第 N 段」，由片段 metadata 的 `kb_id` 反查资料名，前端渲染成可点击来源 |
| 3 | **提问计数归位** | `updateQuestionCounts` 从「按会话范围全量 +1」改为「按本轮实际命中的资料去重 +1」 |
| 4 | **空范围兜底** | 分类下没有已完成向量化的资料时，直接回「「数学」分类下还没有可用资料」，不要混进「未检索到相关内容」 |
| 5 | **未向量化提示** | 范围解析时顺带统计 `PENDING / FAILED` 的资料数，UI 提示「有 2 份资料未完成向量化，暂不会被检索到」 |
| 6 | **标题生成** | `ALL` → 用首条提问生成；`CATEGORY` → 「数学 · 资料问答」；`SELECTED` → 沿用现有资料名拼接 |
| 7 | **检索可观测** | RAG trace 补 `scope` / 命中资料分布，便于讲「跨库检索的召回质量」 |

| 分类管理接口 | `GET/POST/PUT/DELETE /api/kb-categories`（含资料数、未向量化数，末尾带「未分类」统计） |
| 资料关联分类 | `knowledge_bases.category_code`（外键到 `kb_categories.code`），列表接口支持 `?categoryCode=` 与 `?uncategorized=true` |

| 范围接口 | `POST /api/rag-chat/sessions` 接受 `{scope, categoryCode, knowledgeBaseIds}`；`PUT /api/rag-chat/sessions/{id}/scope` 切换 |
| 查询放开空范围 | `KnowledgeBaseQueryService` 空资料列表 = 全库检索（沿用 `similaritySearch` 既有语义），`QueryRequest` / `CreateSessionRequest` 去掉「至少选一个」校验 |
| 跨库均衡 | 召回池 `topK × candidateMultiplier`（默认 3）→ 每份资料保底 `perKbQuota`（默认 2）条 → 剩余按分数补齐，收口 topK；单库不裁剪 |

| 空范围提示 | 分类/指定资料为空时给专门文案，与「检索没命中」区分；范围内有未向量化资料时附提示 |
| 前端 | 问答页：全部资料 / 按分类 / 指定资料三态选择器、会话范围回显、每轮出处；知识库管理页：**行内常驻分类下拉（选中即保存）**、新建分类、分类删除、分类筛选、按分类入口上传；上传页：先选「导入到分类」再导入文件，支持 `?categoryCode=` 深链预选 |

实现时与设计稿的差异：

1. 配额语义从「每份资料最多 N 条」改成「每份资料保底 N 条、剩余按分数补齐」——上限语义会误伤单库场景（详见「必须一起处理的细节」第 1 条）。
2. 出处先以回答末尾的 Markdown 块落地（流式最后一段），未做单独的 SSE 事件与可点击来源；前端渲染走已有的 Markdown 渲染器。
3. 上传页的分类选择与「分类入口上传」已补齐（`BatchUploadPage` 增加 `contextSlot`，适配器通过 `createKnowledgeBaseUploadAdapter(getCategoryCode)` 在读取上传那一刻的分类，保证适配器引用稳定）。

后续修掉的两个可用性问题（2026-09-24）：

| 问题 | 原因 | 修法 |
| --- | --- | --- |
| 选「全部资料 / 按分类」后聊天框消失 | 聊天面板仍按老条件 `selectedKbIds.size > 0` 渲染，而这两种范围不勾选资料 | 条件改成「范围可用」（ALL 恒真 / CATEGORY 需选分类 / SELECTED 需勾资料），会话头部改为显示范围描述 |
| 「+ 新建对话」按钮点不动 | 同一个原因：按钮上还挂着 `disabled={selectedKbIds.size === 0}` | 改为 `disabled={!isScopeReady}`，title 说明原因；空状态文案补成「新对话 · 当前范围：xxx，直接输入问题即可」 |
| 无法修改某份资料的分类 | 入口是悬浮才出现的铅笔 + 保存按钮，等于藏起来了 | 分类改为行内常驻下拉，选中即调用 `PUT /api/knowledgebase/{id}/category` 保存，乐观更新 + 失败回滚 |

## 九、验收标准

1. 新建会话不选资料 → 范围 `ALL`，提问能命中任意分类下的资料，回答带出处；
2. 范围选「数学」→ 只检索数学分类下的资料，语文资料不会出现在出处里；
3. 范围选「指定资料」→ 与现在的行为一致；
4. 范围里有多份资料时，每份至少有一条进入上下文（保底生效）；只有一份资料时，取回条数不受配额影响（仍是 topK 条）；
5. 分类改名后，历史会话的范围仍然有效（存的是 code）；
6. 分类下没有可用资料时给出明确提示，而不是「未检索到相关内容」；
7. 提问计数只加在实际命中的资料上。
