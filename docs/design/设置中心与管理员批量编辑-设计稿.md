# 设置中心与管理员批量编辑（设计稿）

> 范围：前端设置中心导航、AI 调用成本页、模型分配、用户配额、模型价格交互。
> 不改计费口径、限流算法和模型调用链本身的业务规则。

## 一、正文（给产品 / 给人看）

### 1. 目的

- 把原来散落在侧边栏底部的「AI 调用」「用户管理」「改密码」「退出登录」收进统一设置中心。
- 让管理员能分页查看用户，对单个用户或一批用户修改模型分配和 AI 配额。
- 保持调用成本页现有总览、趋势、排行、失败原因和最近调用的信息，不把它简化成一张列表。
- 统一列表、分页和编辑侧窗的视觉与交互。

### 2. 设置中心结构

```text
设置
├─ 用户信息     所有登录用户
├─ 调用成本     ai:cost:view
├─ 用户管理     user:manage
└─ 系统设置     provider:manage
```

- 触发：点击主侧边栏「设置」或底部用户卡片。
- 规则：设置中心左侧是二级菜单；没有权限的菜单不显示，直接访问无权限地址会回到用户信息。
- 结果：用户信息页展示用户名、显示名、邮箱、角色，并提供修改密码和退出登录。
- 兼容：旧 `/admin/users`、`/admin/ai-cost` 等地址自动跳到新地址。

### 3. 调用成本页

- 顶部保留视图选择、模型筛选和时间范围。
- 总览区保留总调用、估算成本、Token、P95 耗时。
- 下方保留成本趋势、功能成本排行、Provider 排行、用户用量 Top 10、失败原因、最近调用。
- 用户用量 Top 10 和最近调用右上角「查看 →」进入独立分页页，并带上当前模型与时间筛选。
- 分页统一使用数字页码、上一页/下一页和「第 X / Y 页」。

### 4. 模型价格

- 列表展示 Provider / Model、模态、输入价、输出价、来源（手工/自动）、生效时间。
- 点击编辑打开右侧侧窗。已有价格的 Provider、模型、模态锁定，只允许改输入价和输出价。
- 新增价格时先选 Provider，模型和可选模态自动带出，不允许手输任意模型名。
- 自动同步价不能删除；手工价可删除并回落到自动同步价。
- 列表按每页 20 条分页，操作结果使用页面内提示，不用浏览器弹窗。

### 5. 模型分配

- 表格列：用户、文字模型、识图模型、更新时间、操作。
- 表格展示按用户档位解析后的实际生效模型；该维度没有用户级绑定时，显示实际模型名并标注「（默认）」。
- 单用户编辑：侧窗里分别是文字模型和识图模型两个下拉框，留空即恢复该维度默认。
- 批量分配：勾选多个用户后打开侧窗，两个下拉框会同时覆盖所有选中用户。
- 批量恢复默认：把选中用户的文字模型和识图模型同时清空。
- 勾选可跨页保留；重新搜索或保存完成后清空选择。

### 6. 用户配额

- 表格列：用户、登录名、角色、状态、操作。管理员账号不受限流/成本限制，因此不进入列表。
- 单用户编辑：先选生效范围（全局默认或某个 AI 功能），再编辑 RPM、TPM、并发、日软上限、
  日硬上限、月硬上限。留空表示清除该范围的对应覆盖。
- 列表展示每个用户的「全局实际生效」六项配额；未配置时显示系统默认值，并单独显示已有功能级
  覆盖的数量。实际生效值按「功能级覆盖 > 用户全局覆盖 > 系统功能/默认值」解析。
- 编辑框里的输入值仍表示用户覆盖值：有覆盖就显示覆盖值，没有就留空；输入框下方和
  placeholder 同时显示当前实际生效值，并标注是“已单独配置”还是“使用默认/继承值”。
- 批量编辑：先选生效范围，再勾选要修改的字段。只有勾选的字段会生效，未勾选字段保持每个
  用户各自的原值。多选模式不展示单个用户的实际值，避免把不同用户的值混在一个表单里。
- 批量保存前先读取每个选中用户在该范围的原配额并合并；合并后统一校验「日硬上限不得低于
  日软上限」「配额不能为负数」，校验通过后才开始写。
- 清除覆盖：按所选范围清除，不清除其他功能或全局配置。

### 7. 边界与异常

- 用户列表为空：显示空态，不渲染空表头。
- 当前页被删空：自动回到最后一个有效页。
- 批量保存中任一请求失败：页面保留选择并提示错误，便于重试；已成功的用户不会回滚。
- 没有已启用的识图 Provider：模型分配侧窗给出提示，识图下拉只剩「默认」。
- 没有权限：菜单隐藏；直接访问时回到用户信息页。

## 二、附录（实现映射）

### A. 路由

```ts
settings: '/settings'
settingsAccount: '/settings/account'
settingsCost: '/settings/ai-cost'
settingsCostUsers: '/settings/ai-cost/users'
settingsCostEvents: '/settings/ai-cost/events'
settingsUsers: '/settings/users'
settingsSystem: '/settings/system'
```

`App.tsx` 用嵌套路由挂 `SettingsCenterPage`，子路由分别渲染账号、成本、用户、系统设置；
旧 `/admin/*` 路由用 `Navigate` 重定向。

### B. 权限

| 页面 | 权限 |
| --- | --- |
| 设置中心 / 用户信息 | 登录即可 |
| 调用成本 | `ai:cost:view` |
| 用户管理 | `user:manage` |
| 系统设置 | `provider:manage` |

### C. 配额用户列表接口

配额页不能复用 `/api/admin/users`，因为后者要求 `user:manage`。新增：

```http
GET /api/admin/ai-cost/quota-users
```

返回非管理员用户：

```json
[
  {
    "id": 2,
    "username": "stonee",
    "displayName": "Stonee",
    "status": "ACTIVE",
    "roles": ["ROLE_USER"],
    "effective": {
      "rpmLimit": 10,
      "tpmLimit": 200000,
      "concurrencyLimit": 4,
      "daySoftUsd": 0.20,
      "dayHardUsd": 0.50,
      "monthHardUsd": 8.00
    },
    "featureOverrideCount": 0
  }
]
```

实现：`AiCostAdminController.quotaUsers()` → `AiUserLimitAdminService.users()` →
`UserRepository.findAllWithRoles()`，过滤 `ROLE_ADMIN`。用户列表一次性加载当前生效的
用户覆盖，计算全局实际值与功能覆盖数量，不在前端逐用户发请求。

编辑接口返回的每个 `UserLimitsView` 同时包含：

- 顶层 `rpmLimit` / `tpmLimit` / ...：当前范围的用户覆盖值，`null` 表示未覆盖；
- `effective`：按系统默认、用户全局覆盖、功能级覆盖解析后的最终生效值。

### D. 批量配额合并规则

```ts
request[field] = enabled.has(field)
  ? parse(form[field])           // 空字符串 => null，表示清除
  : existing[field]              // 未勾选 => 保持该用户原值
```

每个用户单独读取当前范围视图，合并后先校验，再 `Promise.all` 提交。
