# 试卷作答与题型交互 · 设计稿

> 状态：P0 已实现（2026-09-22）
> 关联需求：导入的数学题选项丢了 A/B/C/D；选择题要用鼠标点选（单选/多选），填空题用输入框，主观题保留文本框；材料没写明题型时由 AI 自行判断。

## 实现说明（P0）

| 设计项 | 落地情况 |
| --- | --- |
| 选项结构化 | `InterviewQuestionDTO` 新增 `questionType` 与 `options`（`{key,text}`）；切题时按 A/B/C/D 重新编号，模型不带标签也能正确渲染 |
| 题型判定 | Prompt 增加选项写法与题型判定规则；后端 `resolveQuestionType` 兜底（多选信号词、空线、作文关键词），缺失/非法值会写入解析告警 |
| 选项清洗 | 空选项忽略、少于 2 个降级为文本作答、超过 10 个截断、题干里重复的选项行自动剔除 |
| 作答控件 | 新增 `QuestionAnswerInput`：单选/多选卡片、填空输入框、主观题文本域（带字数统计），老数据无选项时自动退化为文本 |
| 结构化作答 | 前端提交 `selectedKeys` + `questionType`；`practice_answers` 新增 `answer_json` 与 `auto_scored` 两列 |
| 客观题判分 | 新增 `ObjectiveAnswerGrader`：单选/多选直接比对选项，填空题忽略空格标点比对；纯数字字母答案不兜底，其余交模型判等价性 |
| 多选给分 | 漏选按配置给部分分（默认 50%，`app.interview.evaluation.multi-choice-partial-credit`），错选不得分 |
| 报告 | 客观题显示「正确答案 / 你的选择」并按对错高亮；纯客观题试卷不调用大模型，本地生成总评与强弱板块 |

实测（数学测试卷 8 道选择题）：切题得到 8 题 / 卷面 40 分，选择题全部结构化；交卷后 6 对 2 错 → 卷面 30/40，**零模型调用**，批改耗时由 50 秒量级降到 4 秒。

仍待处理：题干内联填空（P1）、公式渲染（P2）、老试卷需要点「重新切题」才能拿到结构化选项（已在解析面板提供入口）。

---

## 一、问题定位

### 1.1 现象

上传数学卷后，题干里能看到四个选项，但**没有 A/B/C/D 标签、不能点选**，只能用一个空白文本框作答。

### 1.2 根因

| 环节 | 现状 | 后果 |
| --- | --- | --- |
| 切题 Prompt | 示例里写了 `"options": ["A. ...", "B. ..."]`，但没有硬性约束 | 模型有时返回带标签的字符串数组，有时不带标签（截图就是后者） |
| 后端 DTO | `InterviewQuestionDTO` **没有 options 字段**，选项被 `toQuestionText()` 拼进题干文本 | 选项退化成普通文本，前端拿不到结构 |
| 前端作答 | 全部题型共用一个 `textarea` | 选择题要手打字母，无法点选 |
| 作答数据 | `practice_answers.user_answer` 只存字符串 | 无法做确定性判分，只能整卷交给 LLM |

配套问题：题型字段 `questionType` 在切题时已经产出（`SINGLE_CHOICE` / `MULTI_CHOICE` / `FILL_BLANK` / `SHORT_ANSWER` / `READING` / `WRITING` / `OTHER`），但前端完全没使用，落库时也只是当作 `type` 原样存着。

---

## 二、目标

1. **题型驱动渲染**：单选 → 鼠标点选（radio）；多选 → 点选多个（checkbox）；填空 → 输入框；简答/阅读/作文 → 多行文本框。
2. **选项结构化**：选项带稳定的 A/B/C/D 标签，独立于题干存储，彻底消除“标签丢失”。
3. **AI 判定题型 + 后端兜底**：材料没写明题型时由模型判断，后端再做规范化与合法性校验，异常降级为文本作答并产生告警。
4. **判分分层**：客观题走确定性判分（快、准、省 token），主观题保持 LLM 批改。
5. **向后兼容**：已切好的老试卷、进行中的会话、已提交的作答都不能失效。

非目标（本轮不做）：图片题识别、公式渲染（KaTeX）、题干内嵌输入框（放 P1）。

---

## 三、数据结构设计

### 3.1 切题输出（模型 → 后端）

```json
{
  "subjectKey": "math",
  "questions": [
    {
      "questionNo": 1,
      "questionType": "SINGLE_CHOICE",
      "question": "已知全集为实数集 R，集合 A={x|x²-2x<0}，B={x|log₂x>0}，则 (∁ᵣA)∩B 的值为",
      "options": [
        { "key": "A", "text": "(-∞,0]∪(1,+∞)" },
        { "key": "B", "text": "(0,1]" },
        { "key": "C", "text": "[2,+∞)" },
        { "key": "D", "text": "∅" }
      ],
      "fullScore": 5,
      "knowledgeCategory": "ALGEBRA_BASICS",
      "knowledgePoints": ["集合运算", "对数不等式"],
      "referenceAnswer": "C",
      "scoringRubric": "选对得 5 分，错选、多选不得分",
      "note": null
    }
  ]
}
```

关键变化：

- `options` 从「字符串数组」升级为「`{key, text}` 对象数组」；后端同时兼容模型返回纯字符串数组（自动按 A/B/C/D 补标签）。
- 选择题的 `referenceAnswer` 统一规范成选项 key 序列：单选 `"C"`，多选 `"BD"`；填空题是标准文本。
- `questionType` 必填，取值受限（非法值由后端兜底改写并记 note）。

### 3.2 落库

**题目（`practice_sessions.questions_json`）**：题目对象内嵌 `questionType` 与 `options`，属于 JSON 结构升级，不需要改表结构。

**作答（`practice_answers`）**：新增两列

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `answer_json` | TEXT | 结构化作答：`{"selectedKeys":["B","D"],"text":"..."}` |
| `auto_scored` | BOOLEAN default false | 该题是否走了确定性判分（用于报告展示“系统判分/教师模型判分”） |

现有 `user_answer` 继续存人类可读答案（报告与 PDF 直接展示），不破坏已有数据。

**迁移**：当前库无生产数据，直接把这两列加进 `V1__init_schema.sql` 的 `practice_answers` 建表语句。

### 3.3 API

整卷交卷请求体扩展（旧字段保留，`selectedKeys` 可选，兼容老前端）：

```json
{
  "answers": [
    { "questionIndex": 0, "questionType": "SINGLE_CHOICE", "selectedKeys": ["B"], "answer": "B" },
    { "questionIndex": 1, "questionType": "MULTI_CHOICE", "selectedKeys": ["A","C"], "answer": "AC" },
    { "questionIndex": 2, "questionType": "FILL_BLANK", "answer": "一览众山小" },
    { "questionIndex": 3, "questionType": "SHORT_ANSWER", "answer": "运用拟人的修辞……" }
  ]
}
```

后端约定：`answer` 是参与评估与展示的权威文本（选择题由 `selectedKeys` 拼接生成，避免前后端不一致）；`selectedKeys` 仅用于确定性判分与报告高亮。

`GET /api/interview/sessions/{id}` 返回的题目里带上 `questionType` 与 `options`（已有字段，扩展 `options`）。

## 四、题型判定

### 4.1 AI 主判（Prompt 强化）

在 `paper-question-extraction-system.st` 中新增/收紧规则：

1. `questionType` 必填，取值只能是上述 7 个枚举。
2. **多选信号**：题干含「多项 / 多选 / 至少两项 / 选出所有 / 全部正确」→ `MULTI_CHOICE`。
3. **单选信号**：题干含「一项 / 最恰当 / 正确的是 / 不正确的一项是」→ `SINGLE_CHOICE`。
4. 材料明确标注题型（如「多选题」「填空题」）时必须遵守标注。
5. 选项必须输出 `{key, text}`，key 用大写字母从 A 连续编号，标签不得省略。
6. 无选项且题干含 `______`、空括号、「填空」→ `FILL_BLANK`。
7. 题干含「作文 / 不少于 N 字 / 写一篇」→ `WRITING`。

### 4.2 后端兜底（`PaperQuestionExtractionService`）

模型给不出合法值时按规则表判定，并写入 `note`（“题型为推断值”）：

| 条件 | 判定 |
| --- | --- |
| AI 给出合法枚举 | 直接采用 |
| 选项 ≥ 2 且命中多选关键词 | `MULTI_CHOICE` |
| 选项 ≥ 2 且未命中 | `SINGLE_CHOICE` |
| 无选项且题干含空线/「填空」 | `FILL_BLANK` |
| 题干命中作文关键词 | `WRITING` |
| 其他 | `SHORT_ANSWER` |

### 4.3 选项清洗

- 纯字符串数组 → 自动补 A/B/C/D；
- 标签重复或数量 < 2 → 丢弃选项，降级为文本作答并写入告警；
- 数量 > 10 → 截断并告警；
- 题干里残留的选项文本（模型把选项写进 `question` 又重复输出 options）→ 去重保留一次。

## 五、判分策略

| 题型 | 判分方式 | 说明 |
| --- | --- | --- |
| 单选 | 确定性：`selectedKeys[0] == referenceAnswer` | 无需调用模型 |
| 多选 | 确定性：选项集合相等才得分 | 是否给部分分待定（见第七节） |
| 填空 | 先做规范化比对（去空格 / 全半角 / 大小写 / 标点），命中即满分；不命中再交 LLM 判等价 | 避免「一览众山小。」被判错 |
| 简答 / 阅读 / 写作 | LLM 批改（现状） | 按评分标准踩点给分 |

确定性判分的收益：

- 一道 8 题的选择题卷子，从 1 次 LLM 评估降为 0（全部客观题时）；
- 判分结果稳定可复现，不再受“模型自己给的参考答案可能错”影响（上一轮实测语文卷参考答案只有 5/8 与官方一致）；
- 报告能明确展示「正确答案 C / 你的选择 B」，而不是一段评语。

实现落点：`AnswerEvaluationService` 在组装 `QaRecord` 前先分流，客观题直接产出得分与评语，仅把主观题交给 `UnifiedEvaluationService`；两部分的结论合并成同一份 `EvaluationReport`。

## 六、交互设计（前端）

### 6.1 组件拆分

新增 `components/QuestionAnswerInput.tsx`，按 `questionType` 分发：

| 题型 | 控件 | 交互要点 |
| --- | --- | --- |
| `SINGLE_CHOICE` | 选项卡片 + radio 语义 | 整行可点，选中态用主色描边 + 浅底 + 实心圆点 |
| `MULTI_CHOICE` | 选项卡片 + checkbox 语义 | 右侧显示「已选 n 项」，并提示给分规则 |
| `FILL_BLANK` | 单行输入框 | 一个空即一个输入框；占位提示「填写答案」 |
| `SHORT_ANSWER` / `READING` | textarea | 保留现有多行输入 |
| `WRITING` | textarea + 字数统计 | 显示「不少于 800 字」提示 |
| `OTHER` / 无选项 / 老数据 | textarea | 与当前行为一致 |

### 6.2 状态模型

```ts
type AnswerValue = { selectedKeys: string[]; text: string };
type AnswerState = Record<number, AnswerValue>;
```

- 单选：写入 `selectedKeys = [key]`；
- 多选：增删 key；
- 填空/主观：写入 `text`；
- 提交时由 `selectedKeys` 生成 `answer` 文本（选择题），避免前后端两套口径。

本地暂存写入 localStorage（key 不变），读取时兼容旧格式（纯字符串 → `{ selectedKeys: [], text }`）。

### 6.3 答题卡与交卷

- 答题卡按题型给出状态：客观题“已选”才计已答，填空/主观题非空才算已答；
- 交卷前校验：未作答数量提示（现有）+ 多选题只选一项时二次确认（避免误交）；
- 交卷后报告页：客观题显示「正确答案 / 你的选择」并高亮对错，主观题保持文本对照。

## 七、待决策（需要你拍板）

| # | 决策点 | 我的建议 |
| --- | --- | --- |
| 1 | 多选题给分 | 漏选得一半、错选不得分（兼顾公平与严格），并做成可配置 |

## 十、验收标准

1. 上传含选择题的数学卷后，作答页出现 A/B/C/D 可点击选项，单选只能选一个、多选可多选；
2. 材料未标注题型的题目，能被判定为单选/多选/填空并在界面用对应控件呈现；
3. 客观题判分与参考答案完全一致（不依赖模型），报告显示“正确答案 / 你的选择”；
4. 老试卷（无 options）仍按文本框呈现，不报错；
5. 整卷交卷一次请求完成，卷面分折算与知识板块统计保持正确。
