# 试卷层级树（大题 → 小节 → 材料/小题）· 设计稿

> 状态：已确认并落地（数据模型与链路已实现）
> 关联：本稿取代 `试卷题组与材料-设计稿.md` 第三章的数据模型（两层「材料 + 题组」升级为任意层级的树），其余章节（切题两段式、批改带材料、兼容策略）继续有效。
> 需求：题目之间是**链/层级**关系——一级是大题（如文章材料），下面可以再分二级（如选择题），二级还可以再分三级；展示时按层级区分。

---

## 一、结论先说

| 问题 | 判断 |
| --- | --- |
| 改 JSON 还是改表结构？ | **改 JSON：把会话上的题目列直接换成树**。不建节点表，也不把题目行化。 |
| 为什么不用表？ | 试卷是「一次生成、整体读取、几乎不改」的文档型数据；层级要顺序 + 嵌套，关系表要么写递归 CTE、要么建闭包表/path 枚举，复杂度远高于收益。需要 SQL 过滤的是「按知识点查题」，那是知识点标签表的事，不是层级树的事。 |
| 树和扁平题目列表要不要各存一份？ | **不要**。存储只有一份树（数据库列与 Redis 缓存都只存树）；内存/接口层的扁平题目列表由树**运行时派生**（`flattenQuestions`）。单一数据源，不存在两份数据漂移的可能。 |
| 为什么要替换而不是新增一列？ | 批改与报告同样需要原文（材料、小节标题），树是这些信息的唯一来源；再留一份扁平数组等于把「材料上下文」重新塞回题目文本，正是当前丢材料的根因。 |
| 老数据怎么办？ | **不兼容**：解析器只认树（`{ "version": 1, "root": {...} }`）。开发库直接重建，不做列重命名与数组兜底。 |

数据流（存储一份，视图按需派生）：

```
切题（结构化）→ paper_json（树：唯一数据源，含材料原文与层级）
                    ├─ 运行时派生：flattenQuestions() → 批改 / 缓存 / 历史去重
                    ├─ 运行时派生：sectionOf(questionIndex) → 批改上下文 / 报告分组
                    └─ 直接渲染：作答页 / 报告页 / PDF
                → paper_analyses（概览：题量 / 卷面总分 / 板块 / 告警）
作答 → practice_answers（每题一行，questionIndex 与树中 QUESTION 叶子一一对应）
```

## 二、树的数据模型

### 2.1 节点类型

| 类型 | 语义 | 典型来源 | 是否叶子 |
| --- | --- | --- | --- |
| `PAPER` | 整卷根节点 | 卷名、满分、考试时间 | 否 |
| `SECTION` | 大题 / 小节（可多层嵌套） | 「一、现代文阅读」「（一）现代文阅读 I」 | 否 |
| `MATERIAL` | 材料 / 语段 | 「材料一」「材料二」「阅读下面的文字」 | 否（可含子材料） |
| `QUESTION` | 题目 | 1、2、3… | 是 |
| `INSTRUCTION` | 说明性文字 | 「注意事项」「完成 1～5 题」 | 是（不可作答） |

层级不写死：`level` 由树深度推导，渲染时按 `type` 决定样式，因此「大题 → 小题」和「大题 → 小节 → 材料 → 小题」都能表达。

### 2.2 节点 Schema

```json
      {
        "id": "n9",
        "type": "SECTION",

        "meta": { "fullScore": 9 },
        "children": []

```

要点：

1. `QUESTION` 节点的 `question` 复用现有 `InterviewQuestionDTO` 结构（含 `questionIndex`、`questionType`、`options`、`fullScore`、`referenceAnswer`…），**不发明第二套题目结构**；
2. `questionIndex` 是树与 `practice_answers` 的唯一连接键，扁平数组的下标与它一致；
3. `MATERIAL` 的正文只在树里存一份，不再复制进任何题干；
4. `meta` 里的 `fullScore` / `questionCount` 供组头和统计使用，由后端按子节点自动汇总（模型给错也能纠正）。

### 2.3 叶子标识与深度（避免"过度下钻"）

节点上显式带三个结构字段：

| 字段 | 含义 | 由谁决定 |
| --- | --- | --- |
| `type` | 节点语义（PAPER / SECTION / MATERIAL / QUESTION / INSTRUCTION） | 抽取阶段 |
| `leaf` | 该节点是否已经是结构终点，不需要再往下分 | 抽取阶段给"建议"值，**组装阶段以后端计算结果为准并回写**（`leaf = children.isEmpty()`） |
| `depth` | 层级深度（PAPER = 0，往下递增） | 组装阶段按树深度计算并回写 |

为什么需要 `leaf`（`children` 为空其实可以推导出叶子，但显式字段有三个实际用途）：

1. **约束模型不要编造层级**：数学卷这种层级不深的材料，结构识别阶段直接给出「一、选择题（`leaf: true`）」，模型就不会硬造「（一）（二）」这种不存在的子层级；
2. **渲染与校验不必递归**：前端按 `leaf` 决定"是否显示展开箭头"，后端按 `leaf` 决定"是否继续下钻切题"；
3. **为惰性展开留口子**：将来材料很长时可以先下发一层（父节点带 `leaf: false` 但 `childrenLoaded: false`），展开时再取子节点。

注意：`leaf` 以**计算值**为准，模型给错（比如声明 leaf 却仍返回 children）时以后端计算结果覆盖并写告警，避免自相矛盾。

数学卷这类浅层结构的树形示例（两级、无 MATERIAL）：

```json
{
  "root": {
    "id": "n0", "type": "PAPER", "depth": 0, "leaf": false, "title": "2026 届高三数学测试卷",
    "children": [
      {
        "id": "n1", "type": "SECTION", "depth": 1, "leaf": false, "title": "一、选择题",
        "meta": { "questionCount": 8, "fullScore": 40 },
        "children": [
          { "id": "q1", "type": "QUESTION", "depth": 2, "leaf": true, "questionIndex": 0, "question": { "questionType": "SINGLE_CHOICE", "options": [] } }
        ]
      }
    ]
  }
}
```

### 2.4 存储

`practice_sessions` 的题目列**直接替换**为树（列名同步改为 `paper_json`，避免"名字是 questions 内容是树"的错位）：

```sql
paper_json TEXT   -- 树：唯一数据源，含材料原文、层级与题目节点
```

老库处理：`ALTER TABLE ... RENAME COLUMN questions_json TO paper_json`（内容仍是老数组，由解析器兼容读取），新会话写入树。开发库可以直接重建。

内存与接口层不存第二份数据：

```java
PaperTree tree = PaperTree.parse(objectMapper, session.getPaperJson());  // 只认树
List<InterviewQuestionDTO> questions = tree.flattenQuestions();
String sectionPath = tree.sectionPathOf(questionIndex);      // 该题的所属小节标题路径
String context = tree.contextOf(questionIndex);              // 批改上下文（小节 + 材料原文）
```

## 三、层级与页面展示的映射

渲染器递归遍历树，按节点类型决定样式，层级只影响缩进与视觉权重：

| 节点类型 | 展示方式 | 交互 |
| --- | --- | --- |
| `PAPER` | 页面头部：卷名、卷面总分、考试时间、总进度 | — |
| `SECTION`（1 级） | 大字标题条 + 该大题满分与进度（如「已答 3/5 · 得 12/19」） | 可整体折叠 |
| `SECTION`（2 级及更深） | 次级标题 + 左侧缩进竖线，标明小节题量与满分 | 可折叠 |
| `MATERIAL` | 材料卡片（灰底），标题如「材料一」，正文整段展示 | 默认展开；可折叠；可「固定材料」常显（P1） |
| `QUESTION` | 题目卡片：题号 / 题型 / 板块 / 分值 + 题型作答控件 | 单选点选、多选多选、填空输入、主观题文本域 |
| `INSTRUCTION` | 浅色提示条（如「阅读下面的文字，完成 1～5 题」），不可作答 | — |

答题卡：只列 `QUESTION` 叶子，按最近的 `SECTION` 祖先分段（`1-5 | 6-9 | 10-12 …`），点击定位到对应题；组标题点击定位到组头。

报告页：按 `SECTION` 汇总（「现代文阅读 I 12/19 分」），与现有知识板块统计并列；`MATERIAL` 不参与统计但作为主观题批改的上下文。

## 四、抽取链路怎么产出这棵树

沿用上一稿的两段式，只是中间产物由「题组列表」升级为「树骨架」：

```
① 结构识别（一次调用 / 规则兜底）
   输出树骨架：PAPER → SECTION(一、) → SECTION(（一）) → MATERIAL(材料一/二) …
        每个 SECTION 带 questionNos（如 [1,2,3,4,5]）与标题
② 按最小题组（SECTION 的叶子分组）切题
   输入：该节点的材料正文 + 题号区间原文
   输出：QUESTION 节点（复用现有题目结构）+ questionIndex
③ 后端组装
   - 把 QUESTION 按 order 挂到所属 SECTION 下（材料在前、题目在后）
   - 汇总每组/每节的 questionCount 与 fullScore，与卷面总分核对，不一致写告警
   - 回写 depth / leaf，并校验「题目节点必须是叶子、非题目节点不得带 questionIndex」
   - 落库只写一棵树（paper_json）；扁平题目列表在运行时由 flattenQuestions() 派生
```

规则兜底线索（优先级从高到低）：

1. 「完成 1～5 题」这类题号区间提示；
2. 行首中文序号「一、」「二、」（1 级）与「（一）」「（二）」（2 级）；
3. 「材料一 / 材料二 / 阅读下面的文字」等材料引导语；
4. 连续长度 > 120 字且不含选项标签的段落 → 材料块。

校验：

| 校验项 | 不通过时 |
| --- | --- |
| 每个 `QUESTION` 恰好有一个父节点 | 挂到最近的 SECTION，并写告警 |
| 同层 `order` 连续、题号递增 | 重排并写告警 |
| 组内分值之和 = 组满分 | 以题目分值之和为准，写告警 |
| 全部题目分值之和 = 卷面总分 | 写告警（不阻断） |

## 五、接口

| 接口 | 变化 |
| --- | --- |
| `GET /api/interview/sessions/{id}` | 增加 `paperTree` 字段（树）；`questions` 字段保留，由后端从树拍平后返回（运行时视图，不落库） |
| `GET /api/interview/sessions/{id}/details` | 报告中按 SECTION 增加 `sectionScores`（组维度得分） |
| 交卷/批改 | 不变（仍按 `questionIndex` 关联 `practice_answers`） |

说明：`questions` 是**运行时派生视图**（不落库），保留它让现有前端、缓存与批改链路零改动；前端在有树时按层级渲染，无树时退回平铺渲染（如普通 AI 出题的会长在 `PaperTree.fromFlatQuestions` 生成的单节点树上）。

### 5.1 批改与报告如何使用树

| 题型 | 调整 |
| --- | --- |
| 客观题 | 判分仍走确定性比对（不调用模型），但评语带上切题阶段抽取的 `analysis` 解析与考点；没有解析时退回「考点 + 评分标准」 |
| 主观题 | 把该题**到根路径上的全部 MATERIAL 文本 + 所属 SECTION 标题**作为上下文一并送入模型，评语要求指出「是否结合材料、要点是否齐全」 |
| 统计 | 按 SECTION 汇总：组内折算分之和 / 组满分（`sectionScores`） |

两个工程细节：

1. **批改按小节分组，而不是单纯按 `batchSize` 切**：同一小节的题目放进同一批，材料只送一次，避免材料重复 N 次导致 token 翻倍；
2. `QaRecord` 增加 `contextText` 字段承载材料与小节标题，`AnswerEvaluationService` 通过 `tree.sectionOf(questionIndex)` 取上下文。

报告展示：逐题解析块里带上「所属小节」与可折叠的「材料原文」，避免报告页看不到原文；PDF 导出同理。

## 六、迁移策略

已确认**不兼容老数据**：

| 场景 | 处理 |
| --- | --- |
| 老会话（`paper_json` 里是旧扁平数组） | 不兼容；解析失败即报错，开发库直接重建 |
| 老试卷（材料已丢） | 点「重新切题」用新链路重建，产出完整树 |
| 数据库 | `V1__init_schema.sql` 直接建 `paper_json`；开发库 `DROP DATABASE` 重建正库 + 清 Redis |
| 题型判定 | 沿用现有规则（选择题/填空/主观题），树上只负责组织结构 |

## 九、验收标准

1. 上传 23 题语文模拟卷后，树为 `PAPER → 一、现代文阅读 → （一）现代文阅读 I → [材料, 第1题…第5题]` 的结构，材料完整且只出现一次；
2. 作答页按层级展示：大题标题条 → 小节标题 → 材料卡片 → 题目卡片，答题卡按节分段；
3. 题号与 `practice_answers` 一一对应，交卷/批改/报告链路不变；
4. 报告页给出节维度得分（如「现代文阅读 I 12/19 分」）；
5. 老数据不迁移：重建库后新会话全部写树，链路无数组兜底分支；
6. 数学这类浅层试卷的树只有 `PAPER → SECTION(leaf:false) → QUESTION(leaf:true)`，不会硬造子层级。

## 十、落地记录

本轮端到端验证（2026-09-22，开发库重建后）：

1. 上传《高三语文模拟试卷》→ 切题：`大题 4 个 / 叶子分组 8 个`，产出 `23 题 / 150 分`，零告警，树里小节顺序为「（一）→（二）」；
2. 整卷交卷 23 题 → 批改：11 题客观题走确定性判分（`auto_scored = true`），12 题主观题走模型批改；报告的 `sectionScores` 为 8 个小节逐节给出「得分/满分/题量」；
3. 主观题批改的评语中出现「按材料提取……」这类措辞，说明 `contextOf` 提供的材料上下文确实进入了 Prompt。

过程中修掉的两个真实缺陷，已补回归测试（`PaperTreeTest`）：

| 缺陷 | 原因 | 修法 |
| --- | --- | --- |
| 批改上下文里没有材料 | 材料是题目的**同级**节点，`pathTo` 只返回祖先链，因此取不到 | 新增 `materialsOf(questionIndex)`：祖先链上的材料 + 每层中排在本题分支之前的材料，且不含本题之后的材料 |
| 批改任务 `UnsupportedOperationException` | `flattenQuestions()` 返回不可变列表，而批改/作答链路沿用旧的「在列表上写回答案」用法 | `flattenQuestions()` 统一返回可变副本，需要回写树时再走 `withQuestions` |
