# 试卷切题、答案键与批改链路失败收敛-设计稿

> 状态：已实现并完成定向回归（2026-11-05；全量测试仍剩 18 个历史 OwnerScope 用例）
> 范围：`resume` 试卷切题 / 答案键 + `interview` 批改下游 + `common/ai` 限流重试
> 配套决策：grilling 三轮已闭环
> 等级：L3（跨模块、AI 调用、异步、并发、数据一致性）

## 一、背景与目标

试卷导入 -> 切题 -> 答案键 -> 批改这条链路里，存在一批"一个点失败就把整卷或整场放大成失败 / 全部重算"的逻辑，导致第四单元这类大卷出现：答案键一次生成失败后全卷答案作废重跑、主观题空答案把整卷判失败、批改侧瞬态错误不重试整场 FAILED、重复交卷覆盖已批改答案等。本设计目标：

1. 把"整卷必须齐全才成功"改成"按题复用、只补缺失、缺失题单独转人工"，单点失败不再放大。
2. 让答案有明确权威来源顺序，结构答案、卷末官方答案区不再被丢弃，AI 只补缺。
3. 在不增加并发数量的前提下，用统一限流等待 + 统一失败分类 + 单层重试 + 背压消化限流。
4. 收敛批改下游同类失败放大，补上作答提交幂等与历史字段回填。

非目标：不改变答案池并发数量（仍是 2 worker、队列 20）；不引入平行分层；不处理总分口径、低置信度前端合并等纯展示项（登记 docs/待优化事项.md）；不做 questionId 全局稳定主键（后续演进）。

## 二、现状问题清单（根因）

- 结构答案被整体丢弃：PaperStructureService.toQuestion 写入 node.referenceAnswer()，但 answerKeySource 为 null；AnswerKeyPreparationService.isUsableAnswerKey 要求 answerKeySource != null 且 analysis 非空，导致结构答案全部不可复用，每次 prepare() 都从 0 重算。
- 一题不完整导致整卷重算：prepare() 用 sources.stream().allMatch(isUsableAnswerKey)；alignedAnswerKeys 只比较题号集合，不相等整张丢弃。
- 主观题空答案一律判失败：ensureAllAnswersPresent 对非空 referenceAnswer 强校验，主观题 Prompt 也强制"每道题 referenceAnswer 必须非空"，一题空答案抛 PAPER_EXTRACTION_FAILED 整卷失败。
- 限流阶段不统一：只有解析批次走 PaperAnalysisPacer；答案键文字/视觉/复核/裁决、结构切题都不接入；本地 AiUsageGate 抛 AI_RATE_LIMIT_EXCEEDED，VisionFailureClassifier 只认 provider 429，本地限流被归成 TERMINAL 不重试；文本答案重试无退避，三次撞同一 RPM 窗口。
- fatal 取消其他批次、最后才落库：AnswerBatchRunner.CANCEL_ON_FATAL 一个 fatal 取消其余 future 并抛异常；成功批次答案在 applyAndStoreAnswerKeys 前不保存，下次全部重来。
- 单题错误题号静默改挂：selectAnswers 在单题批次、单条返回时忽略模型题号直接绑定期望题号；AnswerBatchRunner.validate 只校验 phase/batchIndex。
- 卷末答案区与父题答案被丢弃：assemble 遇 ANSWER_KEY 直接 continue 且 afterAnswerKey=true，后续节点不进入题目树；PaperSubQuestionGrouper 把父题转 MATERIAL 时丢失 referenceAnswer/keyPoints/scoringRubric/analysis/fullScore。
- 批改侧同类失败放大：AbstractStreamConsumer 把任何 BusinessException 判为确定性失败直接 markFailed；AnswerEvaluationService / stageFailure 把超时、网络、限流等瞬态错误包成 BusinessException，3 次 Stream 重试形同虚设；批改无心跳，进程崩溃后 evaluateStatus 永久 PROCESSING；文本模型漏评被记 0 分、MANUAL_REVIEW 兜底不触发。
- 提交无幂等：submitAnswer 不检查会话已批改、无幂等键，客户端重试/双击覆盖已批改答案并把分数重置 0；enqueueEvaluationTask 无条件把状态重置 PENDING，可重复入队批改。
- 报告/历史字段缺口：saveReport 吞 JacksonException 不回滚；历史详情未作答题把 referenceAnswer/keyPoints/scoreStatus 置 null。

## 三、正文设计

### 3.1 答案权威顺序与来源标记

- 目的：确定一道题最终答案以谁为准，避免 AI 重算覆盖人工答案或卷面官方答案。
- 权威顺序（从高到低）：人工 > 官方答案区 > 结构显式答案 > AI（TEXT/VISION）。
- 规则与步骤：
  1. 每个答案来源落库都带 source 标记：人工 MANUAL、卷末官方答案区 OFFICIAL、结构节点显式答案 STRUCTURE、模型生成 TEXT / VISION。AnswerKeyDTO.source 已存在，扩展两个取值。
  2. 结构切题时，PaperStructureService.toQuestion 写入 referenceAnswer 的同时把 answerKeySource 置为 STRUCTURE（现在为 null）。
  3. 答案键生成时，isUsableAnswerKey 只判断"有权威答案"，不再要求 analysis 非空：referenceAnswer 非空且非"暂缺/无法确定/N/A"，且来源属于人工/官方/结构，即可复用；AI 来源还要求 confidence 不为 0。
  4. 复用已有答案时，低优先级来源不得覆盖高优先级来源；人工与官方答案在任何情况下都不被 AI 重算。
- 结果：结构答案和官方答案直接进答案键，只有真正缺答案的题才触发模型调用。
- 边界与异常：权威来源答案缺失（空/"暂缺"）时按 3.2 的 answerMode 降级，不阻断整卷。
- 可改点：想调整"AI 是否可覆盖官方答案"，改权威顺序比较函数 AnswerKeyPreparationService.preferredSource。

### 3.2 主观题答案模式 answerMode

- 目的：主观题不一定有"唯一标准答案"，用"评分依据形态"替代"答案非空"的二元判断。
- 取值：FIXED（选择/判断/填空，必须有确定答案）、SAMPLE（有参考答案）、RUBRIC_ONLY（只有评分规则/要点）、MANUAL_REVIEW（三者全无，转人工）。
- 规则与步骤：
  1. 在 InterviewQuestionDTO（或 AnswerKeyDTO）增加 answerMode 字段，默认 FIXED。
  2. 答案键生成后按题型和实际内容回填：选择/判断/填空 -> FIXED；简答/阅读/案例分析 -> 有 referenceAnswer 为 SAMPLE，无但有 keyPoints/scoringRubric 为 RUBRIC_ONLY；写作 -> 有 scoringRubric 为 RUBRIC_ONLY，无但有 referenceAnswer/keyPoints 为 SAMPLE；三者全无 -> MANUAL_REVIEW。
  3. ensureAllAnswersPresent 不再对主观题强校验"答案非空"，只校验 FIXED 题必须有答案；MANUAL_REVIEW 题记 warning、不抛异常、不阻断整卷。
- 结果：主观题空 referenceAnswer 但有评分依据时正常通过；全无时标记人工复核，其余题照常完成。
- 边界与异常：FIXED 题缺答案时按 3.9 转人工（确定性题无答案键人工拦截，保留现状），同样不整卷失败。
- 可改点：想改变"写作默认优先评分规则"，改 3.2 第 2 步的题型 -> answerMode 映射函数。

### 3.3 按题指纹复用与增量重算

- 目的：只重算真正缺失或题干变化的题，不再"题号集合不完全相等就整张作废"。
- 指纹构成：questionType + 规范化题干 + 选项 + 来源行/页（不含答案、解析，避免答案生成后指纹变化）。
- 规则与步骤：
  1. 每题计算稳定 fingerprint（AnswerKeyPreparationService.fingerprintOf），存进答案键快照（PaperStructureSnapshot）。
  2. alignedAnswerKeys 改为逐题比对：题号存在且 fingerprint 相等 -> 复用；题号缺失或 fingerprint 不同 -> 丢弃该题，其余题保留。
  3. prepare() 把"可复用题"排除，只对缺失题生成 PRIMARY/VERIFY 批次；complete 判定由"所有题完整"改为"无缺失题"。
  4. schema 升级按逐题迁移：读取旧快照，逐题计算 fingerprint 回填，不清空整张答案键表。
- 结果：第四单元只重算真正缺答案的题，已成功的题不再付费重跑。
- 边界与异常：题干被 OCR 修正、选项顺序变化会改变 fingerprint，触发该题重算（可接受）；规范化和指纹算法升级时用 schema 版本号区分。
- 可改点：想放宽"题干微调也算变更"，改 fingerprintOf 的规范化策略。

### 3.4 官方答案区回填

- 目的：卷末"参考答案 / 答案与解析"块应回填前面题目的 referenceAnswer，而不是被跳过。
- 规则与步骤：
  1. PaperStructureService.assemble 遇到 ANSWER_KEY 节点时，不再简单 continue，而是调用 parseOfficialAnswerKey(text) 解析该块，提取"题号 -> 答案"，生成 Map<Integer, AnswerKeyDTO>（source=OFFICIAL）。
  2. afterAnswerKey 只对"明确识别为卷末答案区"的节点生效；无法确认是卷末答案区时只记 warning，不吞掉后续题目。
  3. 解析出的官方答案在题目树组装完成后，按权威顺序合并进题目（source=OFFICIAL）。
- 结果：卷面官方答案被复用，减少 AI 重算，且不会把答案区后面的题全部吞掉。
- 边界与异常：答案区格式无法解析、题号对不上 -> 写 warning，不阻断，答案仍由结构/AI 兜底。
- 可改点：想调整"哪些块算官方答案区"，改 parseOfficialAnswerKey 的识别正则与 assemble 的判断条件。

### 3.5 主观题复核：补评分依据，不裁决对错

- 目的：主观题复核不输出"对/错"，只补全/校正 sample answer / keyPoints / scoringRubric，为后续批改提供更完整上下文。
- 规则与步骤：
  1. prepare() 在选择题 VERIFY 之外，对 answerMode 属于 SAMPLE / RUBRIC_ONLY 的主观题增加一个 VERIFY 批次，Prompt 只要求输出评分依据（keyPoints/scoringRubric/sample answer），不要求"与主答案一致"。
  2. 主观题复核结果与主答案合并：参考答案取高权威来源，评分要点/评分规则用复核结果补齐。
  3. MANUAL_REVIEW 题不参与复核。
- 结果：主观题批改上下文更完整，又避免模型对开放答案做精确字符串裁决。
- 边界与异常：主观题复核失败只记 warning，不覆盖已有答案，不阻断整卷。
- 可改点：想关闭主观题复核，把 3.5 第 1 步的题型过滤条件收紧到空集。

### 3.6 限流统一等待与失败分类

- 目的：在不改变并发数量（2 worker / 队列 20）的前提下，用等待 + 单层重试消化限流。
- 规则与步骤：
  1. 把 PaperAnalysisPacer 泛化成统一 pacer：结构切题、答案键 PRIMARY/VERIFY/TIE_BREAK、解析批次，每个批次调用前都先 awaitAvailable(paperId)。
  2. awaitAvailable 逻辑：读 AiUsageGate.remainingRpmWindowMillisIfExhausted，窗口已满则等待"剩余窗口毫秒 + jitter"，上限 65 秒；未满直接返回。
  3. 统一失败分类：把本地 BusinessException(AI_RATE_LIMIT_EXCEEDED) 和 VisionRequestRejectedException 归为"限流/可等待"，VisionFailureClassifier.classify 增加这两个分支；provider 429 优先 Retry-After，没有则指数退避。
  4. 重试预算只保留一层：限流只由 pacer 处理，StructuredOutputInvoker 的底层重试只处理 JSON 格式修复，业务层不再额外乘重试次数。
- 结果：答案键与切题不会因为本地 RPM 满被立即判失败，而是等窗口恢复；超时上限内不无限 sleep。
- 边界与异常：等待超过 65 秒仍无额度 -> 转入"稍后重试"状态（Stream 重投，见 3.8），不无限等待。
- 可改点：等待上限、jitter 范围、RPM 阈值改 app.paper.answer.analysis-rate-limit-max-wait 与 AiUsageGate 配置。

### 3.7 批次背压与单批失败不放大

- 目的：队列满时不再把 LLM 调用内联进消费线程，单批失败也不再取消其它批次、不再全卷作废。
- 规则与步骤：
  1. AnswerBatchRunner 改为 IGNORE_FATAL 语义：单批失败记 warning 返回，不 cancel 其余 future、不抛异常。
  2. 队列满后的剩余任务不内联执行，改为"本轮已提交的在途任务跑完后，再继续提交下一轮"（背压），或用 completion service 控制未完成数上限 = pool + queue。
  3. prepare() 每批成功后立即增量落库（调 applyAndStoreAnswerKeys 保存已成功批次），失败批次只重试缺失题，不重算已成功题。
- 结果：一处失败不再拖垮整卷，已成功的题不重跑。
- 边界与异常：背压轮询要有上限，防止死循环；单批连续失败仍按 3.3 降级为单题重试（Q5 决策）。
- 可改点：在途上限 pool + queue 这个值改 PaperAnswerExecutorProperties（默认 2+20=22）。

### 3.8 心跳与重投 AI 上下文

- 目的：长任务超过恢复阈值被误判卡死重复执行、以及重投丢失限流上下文，都会重复烧模型。
- 规则与步骤：
  1. 答案键批次循环内按节流回调 PaperExtractionStreamConsumer.heartbeat(payload)（每批或每 N 秒一次），避免答案键多批次一慢就超过 15 分钟恢复阈值被重投。
  2. Stream 重投 / 恢复时保留 ownerId / aiFeature / aiOperation 字段，确保 PaperAnalysisPacer.awaitAvailable 能读到上下文；否则 pacer 直接返回，限流失效。
- 结果：长任务不重复执行，恢复任务不绕过配额。
- 边界与异常：心跳失败（执行权已失效）继续抛异常终止，保持现有 fencing 语义。
- 可改点：恢复阈值、心跳节流改 application.yml 的 resume.recovery 配置。

### 3.9 批改侧失败放大收敛

- 目的：批改链路也有"瞬态错误不重试、永久卡死、漏评记 0 分"三处失败放大，需一并收敛。
- 规则与步骤：
  1. 异常分类：新增 common 级 RetryableFailureClassifier，按 ErrorCode 判断 BusinessException 是否可重试（AI_RATE_LIMIT_EXCEEDED、AI_SERVICE_TIMEOUT、AI 连接失败 -> 可重试）。
  2. AbstractStreamConsumer.handleTaskFailure 改为：可重试的 BusinessException 走 retryMessage，只有确定性业务失败才 markFailed。
  3. AnswerEvaluationService.evaluateInterview / PaperExtractionStreamConsumer.stageFailure 不再把瞬态错误包成普通 BusinessException，保留可重试语义。
  4. 批改心跳：给 interview 评估加 evaluateAttemptId + 心跳 + 卡死恢复（PROCESSING 超过阈值且心跳过期 -> 重新投递），参照 resume 的 heartbeatAnalyzeProcessing。
  5. 漏评兜底：文本模型少返回一题时，UnifiedEvaluationService 不再生成 0 分 DTO，改为"未评估"语义，ReportAssembler 转 MANUAL_REVIEW。
- 结果：瞬态错误真正重试，进程崩溃后批改可恢复，漏评不再静默 0 分。
- 边界与异常：确定性业务失败（文件无文字层、素材缺失、参数不合法）仍直接 FAILED，不无限重试。
- 可改点：可重试错误码集合、批改恢复阈值、心跳节流改 common 分类器与 application.yml。

### 3.10 作答提交幂等与状态守卫

- 目的：客户端重试 / 双击不得覆盖已批改答案，也不得重复入队批改。
- 规则与步骤：
  1. InterviewSessionService.submitAnswerLocked 增加状态守卫：仅 IN_PROGRESS 可写答案；COMPLETED/EVALUATED 已批改时拒绝（或幂等返回原结果，不重写分数）。
  2. enqueueEvaluationTask 改为条件入队：只有 status=COMPLETED 且 evaluateStatus 属于 PENDING(首次)/FAILED 才置 PENDING 并投递；PROCESSING/COMPLETED 不重置、不重发。
  3. 用 repository 条件更新（如 tryMarkEvaluatePendingIfIdle），避免并发下状态被覆盖。
- 结果：重复交卷不会把已批改答案重置为 0 分，也不会产生并发批改。
- 边界与异常：FAILED 后允许重新入队（对应"重新批改"语义）；历史会话已 EVALUATED 的重复提交直接拒绝。
- 可改点：是否允许"批改完成后允许覆盖答案"，改状态守卫的白名单状态集合。

### 3.11 报告/历史回填与落库完整

- 目的：报告序列化失败不回滚、未作答题不显示参考答案，都是结果正确性缺口。
- 规则与步骤：
  1. InterviewPersistenceService.saveReport 捕获 JacksonException 时不再吞掉，改为抛 BusinessException 让事务回滚，评估状态置 FAILED。
  2. 重写报告时对 referenceAnswer、keyPointsJson 显式写入 null/空集合，避免旧参考答案残留。
  3. InterviewHistoryService.buildAnswerDetailList 未作答题分支用题目快照回填 referenceAnswer/keyPoints/scoreStatus。
- 结果：报告要么完整落库要么整体回滚；未作答题也能看到参考答案与复核状态。
- 边界与异常：序列化失败属于数据完整性错误，不回滚会留下半套报告，必须失败。
- 可改点：历史回填的字段范围改 withAnswerKeyMeta 的映射逻辑。

## 四、数据与配置变更

- AnswerKeyDTO：source 增加 OFFICIAL、STRUCTURE；增加 answerMode（FIXED/SAMPLE/RUBRIC_ONLY/MANUAL_REVIEW）、fingerprint（String）。
- InterviewQuestionDTO：增加 answerMode 字段（可选，若放 AnswerKeyDTO 则不加）。
- PaperStructureSnapshot：CURRENT_SCHEMA_VERSION +1；快照内增加逐题 fingerprint 存储（Map<Integer, String> questionFingerprints 或并入 AnswerKeyDTO），旧快照逐题迁移。
- PracticeSessionEntity（interview 评估）：增加 evaluateAttemptId、evaluateHeartbeatAt 列（DDL 迁移）。
- application.yml：app.paper.answer.analysis-rate-limit-max-wait 复用；新增批改恢复阈值与心跳节流（interview.recovery.*，参照 resume）。
- 复用错误码：AI_RATE_LIMIT_EXCEEDED(7005)、AI_SERVICE_TIMEOUT(7002)；ScoreStatus.MANUAL_REVIEW 复用。

## 五、边界与失败模式

- 官方答案区解析失败 / 题号对不上 -> warning，答案由结构/AI 兜底，不阻断。
- 主观题全无评分依据 -> MANUAL_REVIEW，不阻断整卷，其余题正常批改。
- 确定性题无答案键 -> 人工拦截（保留现状），不自动猜分。
- 限流等待超过 65 秒 -> 转"稍后重试"，不无限 sleep。
- 单批失败 -> 记 warning + 只重试缺失题，不取消其它批次、不整卷作废。
- 确定性业务失败（素材缺失/参数错误）-> 直接 FAILED，不无限重试。
- 批改进程崩溃 -> 心跳超时后重新投递，evaluateStatus 不永久卡 PROCESSING。

## 六、测试清单

- 结构答案保留（answerKeySource=STRUCTURE 可复用）。
- 官方答案区回填且不吞后续题目。
- 一题缺失只重算该题（fingerprint 逐题比对）。
- 主观题空 referenceAnswer 但有 rubric/keyPoints 通过（RUBRIC_ONLY）。
- 无评分依据主观题 -> MANUAL_REVIEW，不整卷失败。
- 本地 AI_RATE_LIMIT_EXCEEDED 分类为可等待/可重试。
- 单批失败不取消已成功批次，已成功题不重算。
- 错误题号不静默改挂（带期望题号重试）。
- 瞬态 BusinessException 在批改 Stream 中走重试而非直接 FAILED。
- 重复交卷不覆盖已批改答案、不重复入队。
- saveReport 序列化失败回滚且置 FAILED。
- 历史详情未作答题显示参考答案与复核状态。
