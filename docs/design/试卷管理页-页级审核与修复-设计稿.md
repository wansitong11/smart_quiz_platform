# 试卷管理页页级审核与修复 - 设计稿

> 用途：审批用设计稿。解决「第四单元试卷重新切题时报
> `STRUCTURE: 第 1 页缺少几何快照，请重新识别该页`」，并补齐试卷管理页缺失的
> 逐页审核 / 单页重识别 / 整卷重识别入口。
> 状态：待审批，未实施。
> 前置事实：2026-10-31 本地日志与数据库；受影响试卷 `paperId=19`，文件
> `四年级（上）语文第四单元名校真题卷_.pdf`，共 8 页，识别状态 READY、分析状态 FAILED。

## 0. 结论摘要

这不是切题模型或 prompt 的问题，而是「旧数据缺少页几何快照，新切题逻辑要求它必须存在」。

1. 当前确定性问题：这份试卷 8 页全部是识图页，页面上已经保存了资源图（7 张），
   但每页的 `assets_json`（几何快照）都是空的。新的确定性资源归属逻辑在切题前要求
   「识图页 + 有资源 + 有几何快照」三样齐全，否则直接拒绝并提示第 1 页缺少快照。
2. 修复方式：给管理页补「识别审核」入口，让用户能对整卷或单页重新识别，
   重新生成几何快照，再重新切题。
3. 本轮不引入新视觉模型，不改 Redis 生产消费协议，不改 `paper_assets` 表结构。

## 1. 现象与根因

### 1.1 现象

用户在试卷管理页对「第四单元试卷」点「重新切题」后，分析失败，错误为：

```text
STRUCTURE: 第 1 页缺少几何快照，请重新识别该页
```

试卷管理页没有像试卷导入页那样的逐页审核与单页重识别入口，用户找不到修复入口。

### 1.2 数据库证据

`paperId=19` 的页面行：

- 8 页全部 `source=IMAGE`、`status=READY`；
- 8 页的 `assets_json` 全部为 NULL；
- `paper_assets` 有 7 行资源（第 1、3、4、5、6、8 页各有资源，第 2、7 页无资源）。

### 1.3 代码路径

切题时 `PaperStructureService.loadGeometry(...)` 对每一页执行：

1. 有 `assets_json` 且能反序列化、且 `compatible()` 通过 → 用快照；
2. 否则，若「该页有资源」且「该页是识图页」→ 抛
   `第 N 页缺少几何快照，请重新识别该页`；
3. 否则走文本页的合成几何兜底。

第 1 页有资源（`p1a1`）且是识图页，但 `assets_json` 为空，于是最先在第 1 页抛出。

根因：这批行是在「资源归属确定性改造」落库几何快照之前识别的，页面和资源已保存，
但几何快照从未写回。几何快照里的行级坐标无法从现有资源图反推，必须重新识别才能补回。

## 2. 目标与非目标

### 2.1 目标

- 在试卷管理页的详情页暴露「识别审核」入口，展示逐页状态、文本、资源与几何快照可用性；
- 支持逐页：查看原页、编辑文本、单页重识别（含强制识图）、删除本页；
- 支持整卷：重试失败页、整份重新识别、预览结构、保存并重新切题；
- 对「几何快照缺失」这类可修复问题给出醒目提示和一步修复入口；
- 有进行中的作答或批改时，禁用会改变试卷内容的操作，避免覆盖正在进行的会话；
- 重新切题与识别状态正确衔接（识别完成 → 切题中 → 就绪），不留「永远待校对」。

### 2.2 非目标

- 不引入新的视觉模型 / provider；
- 不改 Redis Stream 生产 / 消费协议；
- 不改 `paper_pages` / `paper_assets` 表结构；
- 不给旧数据做一次性自动迁移（几何快照无法离线反推，只能重新识别）；
- 不做管理员批量重识别队列。

## 3. 业务设计（正文）

### 3.1 入口与展示

试卷管理页点开某份试卷后，原有两个标签：试卷分析、答题记录。

- 当这份试卷走的是「识图识别」路径（有页级识别数据）时，新增第三个标签「识别审核」；
- 纯文字直切试卷不显示该标签，因为它的内容没有逐页校对语义。

「识别审核」页展示：

- 整卷识别状态、页数、就绪页数、失败页数；
- 每页一张卡片 / 列表：页码、来源（文字层 / 识图）、状态（就绪 / 失败 / 识别中）、
  是否含图、资源数、几何快照状态（正常 / 缺失 / 不兼容）；
- 顶部醒目横幅列出「缺少几何快照的页」，并给「整份重新识别」按钮；
- 选中某一页后，右侧显示原页图与可编辑文本。

### 3.2 逐页操作

对选中页：

- 查看原页：打开原图；
- 编辑文本并保存：改完保存，该页重新标记为就绪；
- 用识图重做：无论该页原来有没有文字层，都强制走识图重新识别这一页；
- 删除本页：删除后页码前移，整卷页数减一；至少保留 1 页。

逐页操作只允许在「没有进行中的作答 / 批改」时执行；有进行中会话时按钮置灰并说明原因。

### 3.3 整卷操作

- 重试失败页：只把状态为失败的页重新排队识别；
- 整份重新识别：把每一页都重新排队识别，用于修复「几何快照缺失」这类旧数据问题；
- 预览结构：不落库，先看切题层级、题数、总分、告警；
- 保存并重新切题：把当前就绪页合并并投递切题任务，失败页需要先处理或显式勾选忽略。

整份重新识别会重新生成所有识图页的几何快照，因此是「几何快照缺失」的主要修复按钮。

### 3.4 修复路径（针对本问题）

1. 打开「识别审核」，看到横幅提示第 1、3、4、5、6、8 页缺少几何快照；
2. 点「整份重新识别」，等所有页回到就绪；
3. 逐页 / 结构预览确认无误；
4. 点「保存并重新切题」，系统把识别状态从「待校对」推进到「切题中」，
   切题完成后回到「就绪」；
5. 回到试卷分析查看新的解析结果。

### 3.5 边界与异常

- 有进行中的作答或批改：整卷 / 逐页修改全部禁用；未作答的进行中会话由后端在必要时安全释放；
- 所有页都识别失败：不允许切题，提示先重试或重传；
- 只删到 1 页：禁止继续删页；
- 单页连续重试达到上限：提示重传或删除该页；
- 越权试卷：所有读写接口统一按归属校验，返回 404；
- 几何快照不兼容（版本不对）：按「缺失」处理，提示重新识别该页；
- 识别 / 切题任务投递失败：返回业务错误，前端提示稍后重试，不改变页面状态；
- 高并发：整份重新识别与逐页操作复用现有单卷 Redis 内容锁和
  PENDING → PROCESSING 条件领取，多实例下不会重复执行同一页。
- 防重复点击：识别请求发出后，前端统一动作锁立即生效，识别状态为
  PENDING / PROCESSING 时「整份重新识别」「重试失败页」「页级重做」「保存并重新切题」
  全部禁用；后端同样拒绝识别进行中的重复重识别、页修改与切题请求。

### 3.6 可改点

- 想改「识别审核」标签显示条件：改前端 `isVisionPaper` 判断；
- 想改单页重试上限：改后端 `MAX_PAGE_ATTEMPTS`；
- 想改横幅里「几何快照缺失」的判定：统一改几何快照检查工具，前端只展示后端给出的页号列表；
- 想改「保存并重新切题」是否允许忽略失败页：改 `force` 确认请求里的 `ignoreFailed` 语义。

## 4. 前端交互设计（正文）

### 4.1 标签与状态

- `试卷分析 / 答题记录 / 识别审核` 三标签；识别审核标签仅在识图试卷显示；

#### 5.1.2 几何快照检查下沉为共享工具

新建：`app/src/main/java/interview/guide/modules/resume/service/PageGeometryInspector.java`

纯静态方法，输入页面字段，输出判定结果，供 `getRecognition` 与 `loadGeometry` 共用：

```java
public final class PageGeometryInspector {
  public enum GeometryIssue { OK, MISSING, INVALID, NOT_REQUIRED }

  public static GeometryIssue inspect(
      PageSource source,
      String assetsJson,
      int pageNo,
      int assetCount,
      ObjectMapper objectMapper
  ) { ... }
}
```

判定规则（与现有 `PaperStructureService.loadGeometry` 语义一致）：

- `source == TEXT`：能解析且 `compatible()` → OK；`assetsJson` 为空 → NOT_REQUIRED；
  解析失败 / 不兼容 → INVALID（文本页通常不会出现，展示兜底）；
- `source == IMAGE` 且 `assetCount == 0`：NOT_REQUIRED（无资源无需几何快照）；
- `source == IMAGE` 且 `assetCount > 0`：
  - 能解析且 `compatible()` → OK；
  - `assetsJson` 为空 → MISSING；
  - 解析失败或不兼容 → INVALID。

`PaperStructureService.loadGeometry` 改为：

- 先调 `PageGeometryInspector.inspect(...)`；
- `OK` → 反序列化返回快照；
- `MISSING` 或 `INVALID` 且 `source == IMAGE` 且 `assetCount > 0` → 抛现有
  `第 N 页缺少几何快照，请重新识别该页`；
- 其余 → `syntheticGeometry(...)`。

`PaperRecognitionService.getRecognition` 改为：

- 对每页调 `PageGeometryInspector.inspect(...)` 得到 `geometryStatus`；
- 收集 `geometryStatus ∈ {MISSING, INVALID}` 且 `source == IMAGE` 且 `assetCount > 0`
  的页码到 `geometryMissingPages`；
- `assetCount` 从 `assetService.list(paperId)` 按 `pageNo` 分组计数得到。

#### 5.1.3 确认接口支持强制重新切题

文件：`app/src/main/java/interview/guide/modules/resume/PaperRecognitionController.java`

```java
@PostMapping("/api/papers/{id}/recognition/confirm")
@RateLimit(dimension = RateLimit.Dimension.GLOBAL, count = 5)
public Result<Void> confirm(
    @PathVariable Long id,
    @RequestBody(required = false) ConfirmRecognitionRequest request,
    @RequestParam(defaultValue = "false") boolean force
) {
  recognitionService.confirm(id, request != null && request.ignoreFailed(), force);
  return Result.success();
}
```

文件：`app/src/main/java/interview/guide/modules/resume/service/PaperRecognitionService.java`

```java
public void confirm(Long paperId, boolean ignoreFailed) {
  confirm(paperId, ignoreFailed, false);
}

public void confirm(Long paperId, boolean ignoreFailed, boolean force) {
  paperContentGuard.withPaperLock(paperId,
      () -> confirmLocked(paperId, ignoreFailed, force));
}
```

`confirmLocked(Long paperId, boolean ignoreFailed, boolean force)` 的早期返回改为：

- `recognitionStatus == EXTRACTING` → 直接返回（不变）；
- `recognitionStatus == READY && !force` → 直接返回（保留导入页旧行为）；
- 其余（含 `READY && force`、`NEEDS_REVIEW`、`FAILED`）继续执行合并 + 切题。

其余合并、失败页检查、`EXTRACTING → PENDING → 投递切题` 的逻辑保持不变。

### 5.4 调用顺序（端到端）

修复几何快照缺失：

1. 用户打开详情页 → `GET /api/resumes/{id}/detail` 得到 `recognitionStatus`；
2. 前端判定 `isVisionPaper`，渲染「识别审核」标签；
3. 面板挂载 → `GET /api/papers/{id}/recognition` 得到页列表、
   `geometryMissingPages`、`hasActiveAttempt`；
4. 用户点「整份重新识别」→ `POST /api/papers/{id}/recognition/retry {all:true}`
   → 后端置 PENDING → 投递识别 Stream；
5. 面板轮询 `GET /api/papers/{id}/recognition`，直到所有页 READY、整卷 NEEDS_REVIEW；
6. 用户点「保存并重新切题」→
   `POST /api/papers/{id}/recognition/confirm?force=true {ignoreFailed:false}`
   → 合并页文本 → 置 EXTRACTING + 分析 PENDING → 投递切题 Stream；
7. 切题完成 → `recognitionStatus=READY`、`analysisStatus=COMPLETED`；
8. `onConfirmed` 重新拉详情并切回「试卷分析」。

### 5.4.1 防重复点击与后端幂等守卫

- 前端 `PaperRecognitionPanel` 使用 `actionLockRef` 作为同步动作锁：
  任一保存 / 单页重试 / 整卷重识别 / 删除 / 切题请求未结束时，后续点击直接忽略；
- `recognitionSubmitting` 从重识别请求发出时置 true，直到请求返回并重新拉取识别状态；
- `recognitionLocked = recognizing || recognitionSubmitting`，
  为 true 时重识别、页级操作、结构预览与切题按钮均禁用；
- 后端 `PaperRecognitionService.assertRecognitionIdle(...)`：
  `recognitionStatus=PENDING/PROCESSING` 时拒绝 `updatePageText`、`retryPage`、
  `deletePage`、`retryRecognition`；`EXTRACTING` 时同样拒绝；
- `confirmLocked(...)`：`PENDING/PROCESSING` 抛
  「识别任务正在处理中，请稍候再切题」；`EXTRACTING` 保持幂等直接返回。

### 5.5 可改点映射

- 标签显示条件 → `ResumeDetailPage` 的 `isVisionPaper`；
- 单页重试上限 → `PaperRecognitionService.MAX_PAGE_ATTEMPTS`；
- 几何快照判定 → `PageGeometryInspector.inspect(...)`；
- 切题前失败页策略 → `confirmLocked(...)` 的 `hasFailed && !ignoreFailed` 分支；
- 有进行中会话判定 → `PaperContentGuard.hasActiveAttempt(...)`。

## 7. 风险与边界

- 旧数据只能重新识别恢复，无法离线补几何快照；
- 整份重新识别会重新调用视觉模型，产生识别成本与耗时；
- 若视觉模型本身对某些页持续失败，仍会回到失败态，需要单页重试或删除；
- 本轮不改历史识别代次资源 GC（仍按待优化事项 1.11 单独处理）。
