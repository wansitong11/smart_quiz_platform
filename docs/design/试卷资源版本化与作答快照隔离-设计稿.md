# 试卷资源版本化与作答快照隔离-设计稿

> 状态：已实施（当前工作区，尚未提交 / 部署）
>
> 关联问题：
> 1. 同一页重新识别后，旧 `OPTION_ITEM` 可能被新题目继续复用；
> 2. 已开始的作答与后续页重试 / 重新分析之间没有内容版本护栏；
> 3. 删页、改文字、重识别后，历史会话和当前试卷资源之间可能发生地址复用。
>
> 关联设计：
> - `docs/design/资源归属确定性改造-设计稿.md`
> - `docs/design/视觉调用稳定性改造-设计稿.md`

## 0. 实施记录

2026-10-30 已按本设计完成当前工作区实现，并补充以下落地决策：

1. 页资源键采用 `基础 key@12 位识别代次`；历史代次保留，当前结构只消费当前页几何快照中的键。
2. `OPTION_ROW` 每次按当前行图重新切分，不再复用同父节点下的旧 `OPTION_ITEM`。
3. 页识别成功、改文字、删页、整卷重识别、确认切题与重新分析均原子推进
   `practice_papers.content_revision`；新建 PAPER 会话冻结该值。
4. 已开始的会话分为两类处理：
   - `IN_PROGRESS` 且版本过期：直接拒绝，避免覆盖用户已有作答；
   - `CREATED` 且版本过期：没有答案可保护，忽略旧草稿并按当前结构新建会话。
5. 已交卷后再次开始作答必须从当前 `PaperStructureService.build(paperId)` 重建，
   不复用上一场 `PaperTree`，避免形成“旧题目树 + 新内容版本号”。
6. `PaperGradingAssetContractTest` 已覆盖当前代次选项切片、视觉答案键与批改资源的一致性；
   不读取旧代次切片。
7. 历史代次资源暂不回收；引用关系与保留期清理另立任务，见 `docs/待优化事项.md`。
8. 新开作答的结构构建放在内容锁外；构建前后用内容代次做栅栏校验，
   构建期间内容变化时拒绝创建“旧树 + 新版本号”的会话。
9. 定向验证 13 个测试类共 40 例通过；全量后端 639 例中 26 失败、45 跳过，
   失败均为已登记的知识库 `OwnerScope` / 上传异步化旧用例，本设计相关测试无失败。

## 1. 定位

这次改造解决的不是“图片归到哪道题”，而是更底层的一层：

**一次作答使用的那套题面、答案键和图片，必须始终属于同一个内容版本。**

当前资源归属已经是确定性的，但资源本身仍会被原地覆盖：

- 重新识别一页时，同一个 `assetKey` 可能指向新的裁图；
- 已开始的会话只保存了题目树，没有保存“当时资源属于哪个版本”；
- 交卷批改时会用旧题目树里的 `assetId` 去查当前资源表；
- 如果期间发生页重试、删页或重新分析，旧树可能查到新图。

本设计把资源从“可覆盖的当前值”改成“按识别代次保留的不可变值”，
并给作答会话增加内容版本校验。正常作答期间继续允许页级并发识别，
不新增 Redis Stream，不改变现有 worker 池模型。

## 2. 当前问题

### 2.1 旧图片选项切片会被复用

当前链路：

```text
OPTION_ROW p1a5
  -> 切出 p1a5:A ~ p1a5:D
  -> 写入 paper_assets
```

重新识别同一页时：

1. `PaperAssetService.saveAll()` 按 `paperId + assetKey` 更新原 `OPTION_ROW`；
2. 旧的 `OPTION_ITEM` 没有被删除；
3. `PaperAssetBindingService.splitRow()` 发现同 `parentKey` 下已有至少两个切片，直接复用旧图；
4. 新答案键和后续批改可能继续使用旧切片。

影响：

- 页重试后，用户看到的新题目结构可能仍引用旧选项图；
- 图片选择题的视觉答案键可能基于旧图生成；
- 旧图如果本身包含相邻题内容，会把原始归属错误重新带回来。

### 2.2 进行中会话没有资源版本

当前链路：

```text
startAttempt
  -> 会话保存 paper_json
  -> 用户作答
  -> submit
  -> EvaluateStreamConsumer 读取 session.paper_json
  -> VisualQuestionEvaluationService 按 assetId 查当前 paper_assets
```

如果用户作答期间发生页重试或重新分析：

- `paper_json` 仍是旧题目树；
- `paper_assets` 可能已经被新一页结果覆盖；
- 旧树里的 `assetId` 仍能查到记录，但记录背后的图片已经变了。

影响：

- 图形主观题可能把别的题裁图送给视觉模型；
- 图片选择题若答案键已经生成，字母比较本身不受影响，
  但报告里的图片、解析上下文和历史回看仍可能错位；
- 现在没有失败保护，属于静默使用错误资源。

### 2.3 删页和人工修改没有统一版本标记

删页会删除页实体、前移后续页号，但不会同步 `paper_assets.page_no`。
当前图片页通常能靠页面里的几何快照找回正确资源，所以不一定立刻出错；
但这依赖一个没有显式断言的隐含条件。

此外：

- 改文字只更新 `paper_pages`；
- 重识别只更新页状态和资源；
- 重新分析只更新结构快照；
- 会话只保存题目 JSON。

这些动作之间没有统一的“内容版本”表示，调用方无法判断旧会话是否仍然可以安全批改。

## 3. 目标与非目标

### 3.1 目标

- 每次页识别生成独立资源代次，新结果不覆盖旧会话正在使用的资源。
- 新结构只消费当前页几何快照指向的资源，不把历史代次资源混入当前结构。
- 图片选项每次绑定都按当前 `OPTION_ROW` 重新切分，不再复用旧切片。
- 开始作答时冻结内容版本；进行中作答和批改中会话禁止修改试卷内容。
- 交卷批改前再次校验内容版本，版本不一致时失败关闭，不使用错误资源。
- 删页、改文字、重识别都推进内容版本。
- 保持页级 worker 并发；不新增 Stream，不改现有消费组。
- 历史会话的报告图片仍可解析到其创建时的资源版本。

### 3.2 非目标

- 不引入新的视觉 provider。
- 不新增 Redis Stream 主题、生产者或消费者。
- 不改页级识别的有界执行器容量与 worker 调度模型。
- 本轮不做资源垃圾回收的定时任务；历史版本先保留。
- 不自动迁移旧会话的题目树到最新内容版本。
- 不做前端重新设计；仅允许增加必要的“内容已更新 / 暂不可修改”提示。

## 4. 方案选择

### 4.1 方案 A：资源代次 + 内容版本护栏（推荐）

核心规则：

1. 每次页识别使用唯一识别代次生成新的 `assetKey`；
2. 旧代次资源不覆盖、不删除，历史会话仍可读取；
3. 当前结构只使用页面几何快照里记录的当前代次资源；
4. 作答开始后锁定内容版本，禁止影响内容的修改；
5. 批改前再次校验版本，不一致则拒绝自动批改。

优点：

- 同时解决旧切片复用、历史报告图片变化和作答中资源覆盖；
- 不需要复制整份题目树或图片文件；
- 与现有页级 fencing、`assetKey` 查找方式和前端取图接口兼容；
- 并发边界清楚：长耗时识别不持有 Redis 锁，只在状态切换和内容版本推进时串行。

代价：

- 需要新增资源代次字段和资源键版本格式；
- 暂时保留历史资源，存储量会随重试次数增长；
- 需要增加按 `paperId` 粒度的内容锁。

### 4.2 方案 B：只按页删除旧资源

每次识别成功后删除该页所有旧资源，再保存新资源。

优点：实现较小。

缺点：

- 历史会话和错题快照里的旧 `assetId` 会变成死链；
- 历史报告图片会丢失；
- 与“历史记录可回看”的产品目标冲突。

不推荐。

### 4.3 方案 C：开始过作答后永久禁止重新识别

只要有任意作答记录，就禁止改页和重新分析。

优点：实现最简单。

缺点：

- 用户无法修正已经练习过、但切题仍不理想的试卷；
- 历史记录也会阻止内容改进；
- 与当前“校对后重新分析”的工作流冲突。

不推荐。

## 5. 业务规则

### 5.1 每次识别生成一套新资源

- 目的：让新识别结果不覆盖旧结果。
- 触发：页面识别成功，准备保存文字、几何快照和图片资源时。
- 规则：本次识别产生的新资源使用独立代次标识；同一代次内的行图、题干图和选项切片共享该标识。
- 结果：新题目树只引用新代次；旧会话仍引用旧代次。
- 边界：识别失败不生成当前代次；被页级 fencing 淘汰的旧 worker 即使已经写了资源，也不能被当前页面引用。
- 可改点：代次标识格式和是否清理历史资源。

### 5.2 当前试卷只看当前代次

- 目的：避免旧资源混入新切题。
- 触发：重新分析、打开结构预览或确认切题。
- 规则：后端先读取每页当前的几何快照，再只保留快照中出现的资源键。
- 结果：旧代次资源仍存在，但不参与新结构、答案键和当前页面展示。
- 边界：几何快照指向的资源在数据库缺失时，记录 warning；仍由现有“未绑定资源”或人工复核承接。
- 可改点：是否把“当前资源缺失”提升为失败状态。

### 5.3 图片选项始终按当前行图重新切分

- 目的：避免旧选项切片继续指向旧图。
- 触发：当前题目的图片选项行需要生成 A/B/C/D 图片选项时。
- 规则：不再因为数据库里已有同父级切片就直接复用；先清理当前代次下该行图的旧切片，再按当前行图重新切分。
- 结果：当前代次的选项图只来自当前 `OPTION_ROW`。
- 边界：切分失败仍保留现有 warning 和空占位，不回退到旧切片。
- 可改点：是否保留同代次、同切分参数的缓存优化。

### 5.4 开始作答时冻结内容版本

- 目的：确保这次作答从题目树到图片都属于同一个内容版本。
- 触发：用户点击“开始作答”或继续未完成作答时。
- 规则：后端在试卷级内容锁内检查识别 / 分析状态，并记录本次会话的内容版本；会话从草稿转成“进行中”。
- 结果：进行中的会话拥有明确的内容版本。
- 边界：试卷仍在识别、等待校对或切题中时拒绝开始作答。
- 可改点：内容版本字段名称，以及开始作答时是否立即推进会话状态。

### 5.5 进行中作答期间不允许修改内容

- 目的：避免旧题目树配新图片。
- 触发：用户尝试重试页、重识别整卷、删除页、修改页文字或重新分析。
- 规则：如果同一份试卷存在进行中作答，或存在尚未完成批改的已交卷会话，拒绝修改。
- 结果：用户必须完成 / 完成批改后再修改内容。
- 边界：自动生成的“草稿会话”不算进行中作答；新建后还未真正开始的会话可以被新分析结果替代。
- 可改点：是否允许前端在修改前提示用户放弃进行中的作答。

### 5.6 批改前再次核对内容版本

- 目的：即使内容锁出现遗漏，也不能静默用错图批改。
- 触发：异步批改任务开始处理一份试卷会话时。
- 规则：会话记录的内容版本必须等于试卷当前内容版本，否则不调用视觉模型、不生成报告。
- 结果：版本一致才批改；不一致时把批改标记为失败，并给出“试卷内容已更新”的明确原因。
- 边界：该失败不能通过原会话重新投递解决，用户需要基于最新题目重新开始一次作答。
- 可改点：错误文案，以及是否需要提供“新开一次”入口。

### 5.7 删页、改文字和识别成功都推进版本

- 目的：让所有可能改变题面或资源的动作都进入同一套一致性判断。
- 触发：
  - 页识别成功并写回文字 / 几何快照；
  - 人工修改页文字；
  - 删除页面；
  - 确认切题后触发新的分析。
- 规则：这些动作成功后推进内容版本；识别失败和单纯的任务入队不推进。
- 结果：旧的草稿或会话能被识别为“基于旧内容”。
- 边界：一次整卷识别中多个页面并行成功会推进多次，只要求最终版本不同，不要求连续递增 1。
- 可改点：确认切题是否单独推进版本，还是只依赖页内容变化。

## 6. 结果与用户体验

正常路径：

1. 上传并识别试卷；
2. 用户校对页文字、重试单页；
3. 确认切题；
4. 开始作答；
5. 作答期间分析页的修改按钮被拒绝，提示“当前试卷有进行中的作答”；
6. 交卷批改正常；
7. 批改完成后可以再次修改和重新分析；
8. 历史报告里的旧图片仍能打开。

异常路径：

- 批改任务发现内容版本不一致：不生成错误报告，批改状态为失败，提示重新开始作答。
- 当前几何快照引用的资源不存在：记录告警，当前结构继续按“未绑定资源”处理。
- 旧识别 worker 在 fencing 失败后已经写了资源：资源保留为不可见历史代次，当前页面不引用它。

## 7. 并发边界

- 内容锁粒度为单份试卷：`paper:content-lock:{paperId}`。
- 只有“开始作答”和“短内容变更操作”持有该锁。
- 页级视觉识别、答案键生成、报告合并等长耗时任务不持有内容锁。
- 页级识别仍由 `PaperPageRecognitionProcessor` 和现有有界执行器并发执行。
- 页终态继续使用 `recognitionAttemptId` fencing；内容版本不能替代 fencing。
- 多个页面同时成功时，内容版本使用数据库原子 `+1`，不使用 Java 读后写。

## 8. 失败模式

| 场景 | 行为 |
| --- | --- |
| 作答中存在 `IN_PROGRESS` 会话 | 拒绝改页、删页、重新分析 |
| 已交卷但批改 PENDING / PROCESSING / FAILED | 拒绝修改；保证重批仍有原资源 |
| 会话已 `EVALUATED` | 允许修改，历史会话继续读取旧资源代次 |
| 只有自动生成且未开始的 `CREATED` 草稿 | 允许修改；新分析会生成新草稿会话 |
| 开始作答时版本与试卷不一致 | 拒绝返回旧会话，提示内容已更新 |
| 批改前版本不一致 | 批改失败，不调用模型 |
| 当前代次资源缺失 | 当前结构记录 warning，不让旧代次顶上 |
| 旧 worker fencing 失败 | 清理本次尝试资源；清理失败只留孤儿，不进入当前结构 |
| 页切片失败 | 保持现有空占位和 warning，不复用旧切片 |

## 9. 可改点

| 想改什么 | 改哪里 |
| --- | --- |
| 资源键中的代次长度 | `PaperAssetKey.VERSION_TOKEN_LENGTH = 12` |
| 内容锁等待时间 | `PaperContentGuard.LOCK_WAIT_SECONDS = 5` |
| 哪些会话算“进行中” | `InterviewSessionRepository.existsActivePaperAttempt(...)` |
| 批改版本不一致后是否自动新开一次 | `EvaluateStreamConsumer` 的失败分支 |
| 是否清理历史代次资源 | 后续独立 GC 设计，不在本轮 |
| 确认切题是否推进版本 | `PaperRecognitionService.confirm(...)` |

## 10. 实施分期

### 10.1 P0：正确性护栏

1. 新增 Flyway：`practice_papers.content_revision`、`practice_sessions.paper_content_revision`、
   `paper_assets.source_attempt_id`。
2. 新增资源键版本工具，页识别和文本页初始资源统一带代次。
3. 当前结构只使用页几何快照中的资源键。
4. 删除 `splitRow` 的旧切片直接复用；按当前行图重建切片。
5. 页面成功、改文字、删页时原子推进内容版本。
6. 开始作答和批改前校验版本。
7. 新增试卷级内容锁，统一包住开始作答与内容变更。

### 10.2 P1：体验与清理

1. 分析页展示“当前有进行中作答，内容暂不可修改”。
2. 批改版本不一致时提供“基于最新内容再练一次”入口。
3. 增加按代次清理孤儿资源的巡检任务。

### 10.3 本轮明确不做

- 不把历史会话迁移成最新题目树；
- 不删除历史代次资源；
- 不改 Redis Stream 的领取、ACK、重试语义；
- 不改页级识别 worker 数量。

## 11. 测试计划

### 11.1 资源代次

- 同一页两次识别生成不同 `assetKey`；
- 新代次资源保存不会覆盖旧代次；
- 选项切片键带当前代次，旧代次切片不会被新行图复用；
- 当前结构过滤掉历史代次资源；
- 旧会话仍可按旧 `assetKey` 取到原图。

### 11.2 内容版本

- 页识别成功推进版本，失败不推进；
- 人工改文字和删页原子推进版本；
- 并发页成功时版本不丢失；
- 新建会话记录当前版本；
- 版本不一致时批改消费者不调用视觉模型。

### 11.3 会话状态

- `CREATED` 草稿不阻止重新分析；

- `EVALUATED` 允许内容变更，历史报告仍能打开旧图。

## 12. 评审决策点

| # | 议题 | 推荐 | 理由 |
| --- | --- | --- | --- |
| 1 | 旧代次资源是否立即删除 | 否 | 历史会话和错题快照需要继续取图；先保留，GC 单独设计 |
| 2 | 资源键格式 | `基础key@12位识别代次` | 不改变现有按 key 查找接口，改动面最小 |
| 3 | 是否引入新 Stream | 否 | 内容版本在现有同步路径和批改消费者内即可完成 |
| 4 | 开始作答时是否立即转 `IN_PROGRESS` | 是 | 消除“startAttempt 已返回、真正打开题目前仍可改内容”的窗口 |
| 5 | 内容版本不一致时批改策略 | 拒绝批改 | 不能保证旧树对应旧图时，失败关闭优于静默错判 |
| 6 | 清理历史资源 | 后续独立任务 | 需要引用关系扫描和保留期策略，不混入本轮正确性改造 |

## B. 资源键

新增：

```java
public final class PaperAssetKey {
  public static final int VERSION_TOKEN_LENGTH = 12;

  public static String attemptToken(String sourceAttemptId) {
    if (sourceAttemptId == null || sourceAttemptId.isBlank()) {
      return "initial";
    }
    String compact = sourceAttemptId.replace("-", "");
    return compact.length() <= VERSION_TOKEN_LENGTH
        ? compact
        : compact.substring(0, VERSION_TOKEN_LENGTH);
  }

  public static String versioned(String baseKey, String sourceAttemptId) {
    return baseKey + "@" + attemptToken(sourceAttemptId);
  }

  public static String optionTile(String versionedOptionRowKey, String label) {
    return versionedOptionRowKey + ":" + label;
  }
}
```

约束：

- `asset_key` 仍保持最长 64；

## H. 开始作答

`PaperAttemptService.startAttempt(Long paperId)` 的实际编排：

1. 先获取 `paper:attempt:lock:{paperId}`，让同一试卷的“继续 or 新开”判定串行；
2. 获取内容锁执行短检查：
   - 读取试卷并校验识别 / 切题状态；
   - 查询 PAPER 来源会话；
   - 找到可继续会话时立即标记开始并返回。
3. 没有可继续会话时释放内容锁，在锁外调用 `PaperStructureService.build(paperId)`；
   该步骤可能调用模型或 S3，不能占内容锁；
4. 检查客观题答案键；缺失时触发 `reanalyze(...)`，本次开始作答失败；
5. 再次获取内容锁，重新读取试卷并校验 `contentRevision` 与第一次短检查一致；
   不一致抛 `PAPER_CONTENT_CHANGED`，不创建“旧树 + 新版本号”会话；
6. 在第二次短锁内重新检查可继续会话，最后创建新会话并立即
   `markPaperAttemptStarted(sessionId)`。

`inspectAttempt` / 最终创建分支的检查：

1. 读取试卷；
2. 若 `recognitionStatus` 为 `PENDING`、`PROCESSING`、`NEEDS_REVIEW`、
   `EXTRACTING`、`FAILED`，拒绝开始作答；
3. 若 `analysisStatus` 为 `PENDING` 或 `PROCESSING`，拒绝开始作答；
4. `IN_PROGRESS` 会话版本一致才继续，版本不一致抛 `PAPER_CONTENT_CHANGED`；
5. `CREATED` 会话版本一致才继续，版本不一致则忽略旧草稿并按当前结构新建；
6. `COMPLETED` / `EVALUATED` 不继续，走新作答；
7. 内容锁只覆盖检查、创建会话和状态切换，不覆盖结构构建。

`InterviewSessionService` 新增：

```java

```

规则：

- `CREATED -> IN_PROGRESS`；
- `IN_PROGRESS` 幂等返回；
- `COMPLETED` / `EVALUATED` 抛 `INTERVIEW_ALREADY_COMPLETED`；
- 同时更新数据库和 `sessionCache`；
- 不推进 `currentQuestionIndex`。

## N. Definition of Done

- 同一页连续识别两次后，两次 `assetKey` 不同，旧资源仍可查询。
- 新结构只出现当前代次资源键。
- 旧 `OPTION_ITEM` 在新代次中永不复用。
- 开始作答后，重试页、删页、改文字、重新分析均被拒绝。
- 内容版本不一致时批改不会调用视觉模型。
- `EVALUATED` 后的历史报告仍能加载其旧代次资源。
- 未新增 Redis Stream 主题或消费组。
- 未使用 `Executors.newXxxThreadPool()`。
- 定向测试和跨模块契约测试全绿。
