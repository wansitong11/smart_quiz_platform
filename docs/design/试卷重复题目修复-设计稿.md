# 试卷重复题目修复 · 设计稿

> 更新时间：2026-11-05
> 对应问题：第四单元名校真题卷批改后大量题目重复（45 题 / 167 分）
> 本文只讲「子题与空位并入父题 + 同范围去重 + 答案键对齐」这一件事。

## 一、正文

### 1. 目的

学生上传一份语文卷后，作答页和批改报告里同一道题会重复出现：一道「看拼音写字词」既显示成
一道父题，又显示成 6 个空位小题，还会因为同一行里写了 3 个空而出现 3 道一模一样的题。
最终 45 道题、总分 167，和卷面 28 题、100 分对不上。

根因是切题时把三种节点都当成了独立题目：`QUESTION`（大题）、`SUB_QUESTION`（子问）、
`BLANK`（空位）。而后端本来有一处「父题 + 子问合并」的逻辑，但它判断子问时读错了字段，
导致合并从来没生效。上一份同样的卷没出问题，只是因为那次模型只返回了大题节点，没返回子问和空位。

### 2. 触发

任何一次试卷切题都会触发：既包括首次上传后确认切题，也包括从缓存结构 JSON 再次组装
（例如重新切题、重新进入校对页）。因此修复后，用户对存量坏卷点「重新切题」即可自动修复，
不需要手工改数据库。

### 3. 规则与步骤

#### 3.1 同范围去重

结构模型偶尔会给同一行范围输出多个一模一样的节点。切题前先做一次防御性去重：对
`QUESTION` / `SUB_QUESTION` / `BLANK` 三类节点，按「类型 + 起始行 + 结束行」作为唯一键，
重复的只保留第一个。这一步只按行号去重，不做文本相似度判断，避免把真正需要拆开的多空题误合并。

#### 3.2 子题 / 空位并入父题

去重之后，逐个检查 `SUB_QUESTION` 和 `BLANK` 节点：

- 如果这个子题/空位**自己标了分值**，保留它，交给第 3.3 步的拆分逻辑处理。
- 如果它**没标分值**，并且存在一个大题 `QUESTION` 的行号范围把它完全包住，就把它并入父题：
  不再给它分配题号。父题的题干文本本来就是按行号切片拼出来的，已经包含这些子空内容，
  所以直接丢弃子题节点即可，不需要再拼文本。
- 如果它没标分值、也没有任何大题包住它（比如英语完形填空：一段材料 + 一串空，没有独立大题），
  保留它，当作一道独立题。

判断「完全包住」用行号：`父题.startLine <= 子题.startLine` 且 `父题.endLine >= 子题.endLine`。
这一步在结构归一化入口执行，所以首次切题和缓存重放都会走到，存量数据重切即可修复。

#### 3.3 无分父题 + 有分子问，仍拆小问

数学卷常见「8. 如图所示完成下列各题」这种父题本身不给分，`(1)(2)` 各自给分的场景。
这种不能被第 3.2 步吞掉，而是保留现有拆分逻辑：父题降级成一道「题干组/材料」，
子问各自成题。因为第 3.2 步只折叠「没标分值的子题」，带分值的子问会原样留下来，走到这一步。

这一步沿用已有的题干组后处理，但要修掉它读错字段的问题：它现在判断「是不是子问」看的是
题目 DTO 的 `type` 字段，而生产链路里这个字段被写成了分类标签，不是原始节点类型，所以永远判不中。
改成在组装时额外传一份「题号 → 原始节点类型」的映射给它，并且把 `BLANK` 也纳入子问判定。

#### 3.4 答案键与题号对齐

折叠后题目从 45 道变 28 道，题号重新从 0 开始排。存量结构 JSON 里还存着 45 个旧答案键，
旧题号和新的 28 个题号对不上，不能直接套用。组装完成后做一次对齐校验：

- 如果存量答案键的题号集合，和折叠后的题目题号集合**完全一致**，直接复用，避免重复付费调用。
- 如果不一致，丢弃旧答案键，按新题号重新生成；同时在日志里记一条「答案键与切题结果不一致，已重新生成」。

这样存量 `paperId=52` 重切后，会先用新规则折叠成 28 题，再重算 28 个答案键，题目、答案键、
会话、报告四处的数量自然一致。

### 4. 结果

- 第四单元卷从 45 题回到 28 题；同范围重复节点不再出现。
- 答案键、作答会话、批改报告都基于这 28 题生成，数量一致。
- 总分不再因子空单独按默认分计分而虚高（从 167 明显下降）。
- 数学「有独立分值的子问」仍拆成小问，不回退既有能力。
- 存量坏卷通过「重新切题」即可修复，无数据迁移。

### 5. 边界与异常

- 子题/空位没有可归属的父题：保留为独立题，不丢弃、不告警（英语完形是正常场景）。
- 子题/空位自己带分值：保留，交给拆分逻辑，不并入父题。
- 同一行多个空位：先被第 3.1 步去重合并，再被第 3.2 步并入父题，不会重复成题。
- 答案键题号与新题号不一致：丢弃旧答案键并重算，不静默错配。
- 折叠不改变题目 DTO、树节点结构和持久化 schema；总分与卷面 100 分仍可能有偏差，
  属于另一个问题，本次不处理，登记到待优化事项。

### 6. 可改点

- 想调整「子题/空位什么情况算没分值」：改折叠时对 `fullScore` 的判断（当前是 `null` 或 `<= 0`）。
- 想去重范围从题目类节点扩展到所有节点：改去重时参与判断的类型集合。
- 想改答案键重算的告警文案或行为：改对齐校验失败时的处理。
- 想改「拆小问」的父题降级标题（当前是「第 N 题」）：改题干组后处理的标题生成。

## 二、附录（零猜测实现）

### A1. 新增结构归一化：子题折叠 + 同范围去重

新增类，放在 `interview/guide/modules/resume/service` 包，命名 `PaperSubQuestionFoldNormalizer`，
包级可见、构造器私有、只暴露一个静态方法（与现有 `PaperBlockBoundaryNormalizer`、
`PaperMaterialHierarchyNormalizer` 同风格）。

入口签名：

```java
static java.util.List<BlockTreeDTO.BlockNodeDTO> normalize(
    java.util.List<BlockTreeDTO.BlockNodeDTO> nodes,
    java.util.List<String> lines)
```

输入：规范化前的块节点列表，按 `startLine` 升序、`endLine` 升序传入。
输出：折叠与去重后的节点列表，顺序保持升序。

步骤：

1. 去重。遍历输入，对 `type ∈ {QUESTION, SUB_QUESTION, BLANK}` 的节点生成键
   `type + "|" + startLine + "|" + endLine`，用 `LinkedHashMap` 只保留首次出现的节点；
   其它类型节点原样追加。
2. 折叠。先收集去重后所有 `type == QUESTION` 的节点，记录它们的 `startLine/endLine`；
   再遍历去重结果中的 `SUB_QUESTION` / `BLANK` 节点：
   - 若 `node.fullScore() != null && node.fullScore() > 0`：保留。
   - 否则若存在某个 `QUESTION` 满足 `q.startLine <= node.startLine && q.endLine >= node.endLine`：丢弃。
   - 否则：保留。
3. 返回保留节点列表。

说明：丢弃子题不需要改父题文本，因为父题题干在组装阶段按行号切片生成，已包含子空所在行。
`lines` 参数当前不参与计算，仅保留给将来「按行号二次校验」使用；不调用它也不影响结果。

### A2. 集成进 normalizeBlocks

修改 `PaperStructureService.normalizeBlocks(BlockTreeDTO blocks, List<String> lines)`，
把处理顺序改成「折叠去重 → 边界归一化 → 材料层级归一化」：

```java
List<BlockNodeDTO> folded = PaperSubQuestionFoldNormalizer.normalize(blocks.nodes(), lines);
List<BlockNodeDTO> bounded = PaperBlockBoundaryNormalizer.normalize(folded, lines);
List<BlockNodeDTO> hierarchy = PaperMaterialHierarchyNormalizer.normalize(bounded, lines);
BlockTreeDTO normalized = new BlockTreeDTO(
    blocks.subjectKey(), blocks.totalScore(), hierarchy, blocks.warnings());
```

保留原有的 `PAPER_STRUCTURE_NORMALIZE_BEGIN / END / NORMALIZED_BLOCKS` 日志不变，
日志里的 `before/after` 节点数会自然反映折叠效果。

### A3. 组装时传原始节点类型，修复题干组后处理

修改 `PaperStructureService.assemble(...)`：

1. 在循环外新增局部变量
   `Map<Integer, String> questionKinds = new LinkedHashMap<>();`。
2. 在 `case "QUESTION", "SUB_QUESTION", "BLANK"` 分支内、调用 `toQuestion(questionIndex++, ...)`
   之前，记录 `questionKinds.put(questionIndex, type);`（`type` 是当前节点的原始类型大写串，
   `questionIndex` 是本次自增前的值）。
3. 把分组调用从
   `subQuestionGrouper.group(PaperTree.recalculate(...))`
   改为
   `subQuestionGrouper.group(PaperTree.recalculate(...), questionKinds)`。

修改 `PaperSubQuestionGrouper`：

- 保留无参 `group(PaperTree tree)`，委托到
  `group(tree, java.util.Map.of())`，兼容既有单测与调用方。
- 新增 `group(PaperTree tree, Map<Integer, String> rawTypes)`；`groupNode`、`toQuestionGroup`
  内部把 `rawTypes` 一路传下去。
- 子问判定改为：先查 `rawTypes.get(node.questionIndex())`，查不到再回退到
  `node.question().type()`；命中 `SUB_QUESTION` 或 `BLANK` 即为子问。
- 父题判定改为：`node.question() != null && !isChildQuestion(node)`。

伪代码：

```java
private boolean isChildQuestion(PaperNode node, Map<Integer, String> rawTypes) {
  String raw = rawTypes.get(node.questionIndex());
  if (raw == null && node.question() != null) {
    raw = node.question().type();
  }
  return "SUB_QUESTION".equalsIgnoreCase(raw) || "BLANK".equalsIgnoreCase(raw);
}
```

### A4. 答案键对齐校验

修改 `PaperStructureService.buildInScope(...)` 最后组装答案键的部分。当前是
`assemble(...).withAnswerKeys(snapshot.answerKeys())`，改为：

1. 先 `BuiltStructure assembled = assemble(...)`。
2. 调用新私有方法 `alignedAnswerKeys(assembled.questions(), snapshot.answerKeys())` 得到
   `Map<Integer, AnswerKeyDTO> keys`，并可能追加一条 warning。
3. `BuiltStructure built = assembled.withAnswerKeys(keys).withAdditionalWarnings(generationWarnings)`。

`alignedAnswerKeys` 逻辑：

```java
if (stored == null || stored.isEmpty()) return Map.of();
Set<Integer> indexes = questions.stream()
    .map(InterviewQuestionDTO::questionIndex).collect(Collectors.toSet());
if (indexes.equals(stored.keySet())) return stored;
PaperFlowLog.event("ANSWER_KEY_MISMATCH_DISCARDED questions={}, storedKeys={}",
    indexes.size(), stored.size());
return Map.of();
```

对齐失败时追加 warning：`"答案键与切题结果不一致，已重新生成"`。
丢弃旧答案键后，`AnswerKeyPreparationService.prepare` 会因「存在无可用答案键的题」而重新生成全部答案键，
并通过 `applyAndStoreAnswerKeys` 覆盖存储。

### A5. 数据与配置影响

- 无 DDL、无新增配置项、无错误码变更。
- 不迁移存量数据；结构归一化对缓存块会重放，重切即修复。
- 总分与卷面不符的问题，落地时在 `docs/待优化事项.md` 追加一条记录，不在本设计内解决。
