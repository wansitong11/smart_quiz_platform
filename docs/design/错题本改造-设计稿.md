## 0. 目标与非目标

### 0.1 目标

- 错题按稳定指纹聚合，同一道题多次做错只出现一条。
- 展示完整原题：题干、选项、阅读材料/图片上下文、我的答案、参考答案、解析。
- 按「考试 → 科目 → 考点 → 题型」分类，加状态与关键字筛选、分页。
- 错题重练支持「勾选指定题」与「按筛选范围一键随机抽题」两种方式。
- 掌握度：累计答对 3 次自动标为已掌握；答错后可降级；支持手动移出与恢复。
- 原题展示不依赖源会话仍存在，科目改名/删除后错题仍可查看。

### 0.2 非目标（本期不做）

- 试卷分析（PAPER）与知识库出题（KNOWLEDGE_BASE）来源的错题纳入（本期只收 QUIZ 与 QUIZ_WRONG）。
- AI 推荐题、艾宾浩斯复习计划。
- 掌握率曲线、按考点聚合等统计图表。
- 内部业务命名迁移（`resume / interview / skill` 暂不改名）。

## 1. 领域模型与既定决策

| 决策 | 结论 |
| --- | --- |
| 错题来源 | 仅 `QUIZ` + `QUIZ_WRONG`（模拟测验与错题重练） |
| 同一道错题 | `科目代码 + 题型 + 归一化题干 + 归一化选项（含图片资源 ID）`；READING 额外并入章节标题与材料原文 |
| 身份载体 | SHA-256 哈希（`question_key`），答案/解析/分值/页码不参与 |
| 状态 | `待复习 PENDING` / `已掌握 MASTERED` / `已移除 ARCHIVED`，三态 |
| 掌握规则 | 累计答对 3 次即掌握；答错不清零，但已掌握后再错降级并清零 |
| 掌握触发 | 仅系统自动，不提供手动「标为已掌握」 |
| 移出 | 手动；已移除的题在普通测验中再错时自动回 `待复习` |
| 答对口径 | 客观题得分率 `==100`，主观题 `>=80`（阈值配置化） |
| 回写时机 | 批改完成（EVALUATED）后统一回写，交卷不提前写，幂等 |
| 重练方式 | 勾选重练 + 一键随机重练；随机默认 10 题、只抽 `待复习` |
| 已掌握在重练 | 默认不参与，可切换状态手动勾选；`已移除` 永不参与 |
| 原题保障 | 错题表冗余题目快照，不依赖源会话仍存在 |
| 展示名 | 考试/科目/考点/题型中文名由后端下发，前端不本地映射英文 ID |

### 1.1 术语

- 错题（WrongQuestion）：某科目下某次作答得分率 `<100` 的题，按 `question_key` 唯一。
- 错题指纹（questionKey）：见上表身份载体。
- 掌握进度（correctCount）：累计答对次数 `0..3`。
- 错题快照（questionSnapshot）：学生视角题目 + 小节/材料上下文 + 内部答案键（仅后端判分用）。

## 3. 数据模型

新增表 `wrong_questions`，归属沿用 `owner_id` 隔离；`question_snapshot` 存完整题目与材料上下文，
内部答案键仅后端读取，不下发学生端。

```sql
CREATE TABLE wrong_questions (
  id                    BIGSERIAL PRIMARY KEY,
  owner_id              BIGINT NOT NULL,
  question_key          VARCHAR(64) NOT NULL,
  skill_id              VARCHAR(64) NOT NULL,
  exam_code             VARCHAR(64),
  exam_name             VARCHAR(64),
  subject_name          VARCHAR(64),
  knowledge_point_key   VARCHAR(64),
  knowledge_point_name  VARCHAR(64),
  question_type         VARCHAR(32),
  question_snapshot     TEXT NOT NULL,
  status                VARCHAR(16) NOT NULL DEFAULT 'PENDING',
  correct_count         INTEGER NOT NULL DEFAULT 0,
  wrong_count           INTEGER NOT NULL DEFAULT 0,
  last_wrong_at         TIMESTAMPTZ,
  last_correct_at       TIMESTAMPTZ,
  mastered_at           TIMESTAMPTZ,
  archived_at           TIMESTAMPTZ,
  created_at            TIMESTAMPTZ NOT NULL DEFAULT now(),
  updated_at            TIMESTAMPTZ NOT NULL DEFAULT now(),
  UNIQUE (owner_id, question_key)
);

CREATE INDEX idx_wrong_questions_owner_status
  ON wrong_questions (owner_id, status);
CREATE INDEX idx_wrong_questions_owner_subject
  ON wrong_questions (owner_id, subject_name);
```

- `status` 取值：`PENDING` / `MASTERED` / `ARCHIVED`。
- `correct_count` 表示掌握进度 `0..3`；`wrong_count` 表示累计答错次数，二者独立。
- `question_snapshot` JSON 结构（内部）：
  - `question`：完整 `InterviewQuestionDTO`（含内部答案键）。
  - `sectionTitle` / `sectionSubtitle`：小节标题。
  - `materials`：材料上下文；每个材料块保存 `title` / `content` / `assetIds`。
  - `paperId` / `assetIds`：源试卷 ID 与题目配图资源 ID，用于原题图片回看和重练。
- 登记时从 `QuizCatalogService` 反查考试名、科目名、考点中文名并落库，之后即使科目改名/删除，
  展示名仍保留登记时快照。

## 4. 指纹与状态机

### 4.1 指纹计算

```text
normalize(s) = s.trim().replaceAll("\\s+", "")

part = skillId
     + "|" + questionType
     + "|" + normalize(stem)
     + "|" + options 按 key 排序后逐项 "key:normalize(text):assetId" 拼接
     + (READING ? "|" + normalize(sectionTitle + sectionSubtitle
                                  + materialTitlesAndContents) : "")

question_key = SHA-256(part).hex()
```

- READING 的章节标题与材料原文参与哈希，不进入身份列；其他题型不因材料上下文变化拆题。
- 选项存在图片资源时，`assetId` 也参与选项身份，避免题干/选项文字相同但图片不同被误合并。

### 4.2 状态机

| 当前状态 | 事件 | 结果 |
| --- | --- | --- |
| 无 / 任意 | 普通测验或重练答错 | `PENDING`，`wrong_count +1` |
| `PENDING` | 答对一次 | `correct_count +1`（封顶 3）；满 3 → `MASTERED` |
| `MASTERED` | 再次答错 | `PENDING`，`correct_count=0`，`wrong_count +1` |
| 任意 | 手动移出 | `ARCHIVED` |
| `ARCHIVED` | 普通测验中再错 | `PENDING`，`wrong_count +1` |
| `ARCHIVED` | 手动恢复 | `PENDING`（保留计数） |

- `MASTERED` 只由系统自动产生；`PUT status` 只接受 `ARCHIVED` / `PENDING`。

## 6. 后端接口

```text
GET /api/quiz/wrong-questions
    ?examCode=&subjectCode=&knowledgePointKey=&questionType=&status=&keyword=&page=&size=
    → WrongQuestionPageDTO { items[], total, aggregates{ subjectCounts[], statusCounts[] } }

POST /api/quiz/wrong-questions/retry
    { mode: SELECTED|RANDOM,
      questionKeys?: string[],
      scope?: { examCode?, subjectCode?, knowledgePointKey?, questionType?, status?, keyword? },
      count?: number }
    → InterviewSessionDTO

PUT /api/quiz/wrong-questions/{questionKey}/status
    { status: ARCHIVED | PENDING }
    → void
```

- 列表、状态、重练全部走 `OwnerScope` 归属校验。
- 列表条目 `WrongQuestionItemDTO` 只含学生可见字段：`questionKey / examName / subjectName /
  knowledgePointName / questionType / typeLabel / stem / options / materialBlocks[] / paperId /
  assetIds[] / userAnswer / referenceAnswer / analysis / wrongCount / correctCount / status /
  lastWrongAt / masteredAt / archivedAt`，不暴露内部答案键。
- 保留 `GET /api/quiz/wrong-questions` 的旧 `skillId` 参数作为兼容，语义等同 `subjectCode`。

## 7. 重练流程

- SELECTED：按 `questionKeys` 从 `wrong_questions` 读取快照，不依赖源会话。
- RANDOM：在当前筛选范围 + `status=PENDING` 内随机抽 `count`（默认 10、上限可配），
  不抽 `MASTERED` 与 `ARCHIVED`；筛选范围包含关键字。
- 从快照重建 `PaperTree`：`PAPER → SECTION(考点标题) → [MATERIAL] + QUESTION`，沿用
  `PaperNode.section / material / ofQuestion` 与 `PaperTree.fromFlatQuestions` 的现有构造方式。
- 新会话 `source_type=QUIZ_WRONG`，照常入答题记录；错题本不因重练产生重复条目。
- 重练会话批改完成后，错题服务幂等回写对应 `question_key` 的 `correct_count / wrong_count /
  status`（同一批改结果只回写一次）。

## 8. 回填与性能

- 首次访问（或显式后台任务）按 `owner_id` 惰性、幂等回填：扫描已批改的 `QUIZ / QUIZ_WRONG`
  会话的作答，重建指纹并登记 `PENDING`；`wrong_count` 取累计答错次数，`correct_count` 按历史
  答对次数回推，状态按规则归位。
- 回填重复执行不产生重复行：靠 `(owner_id, question_key)` 唯一键及逐题回写事件标记跳过已处理作答。
- 删除现 `listWrongQuestions` 的全量会话 + 全量答案进内存做法，改分页仓库查询。
- 回填与回写均在事务内执行，回写使用唯一键 upsert 防并发重复计数。
