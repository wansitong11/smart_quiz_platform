# 免费与低成本模型选型调研（2026-11-03）

> 目标：为「免费用户用免费模型、付费用户用付费模型」提供可落地的模型组合与接入评估。
> 本文只做选型与调研，不改业务代码。价格、免费额度、限流以各厂商官网/控制台当日为准。
>
> **实施状态（2026-11-06）**：已接入 `glm-free` / `glm-vl-free` / `siliconflow-free`
> 三个免费 Provider，并补上启动时自动激活文本/识图默认值的逻辑。后续实测发现 GLM 免费文本
> 并发只有约 1，当前免费文本默认已改为 `siliconflow-free / Qwen/Qwen3-8B`（Provider 文本许可 8）；
> 免费识图继续保持 `glm-vl-free / GLM-4.6V-Flash`（视觉许可 1）。付费识图增加 Provider 级
> 并发保护。用户档位路由仍未实现，管理员可通过「模型分配」按用户覆盖。详见
> `docs/design/免费文本与识图并发档位优化-设计稿.md` 与 `docs/改造说明.md` §4.11。

## 一、结论先行

### 推荐组合

| 档位 | 文本（出题/切题/批改/问答） | 视觉/OCR（试卷识图） | Embedding（向量化） |
|------|---------------------------|---------------------|---------------------|
| 免费用户 | 智谱 `GLM-4.7-Flash` | 智谱 `GLM-4.6V-Flash` | SiliconFlow `BAAI/bge-m3` |
| 付费用户 | 阿里百炼 `qwen3.8-flash` | `qwen3.8-flash`（多模态）或 `qwen3.5-ocr` / `qwen-vl-ocr` | `qwen3.7-text-embedding-flash` 或 `text-embedding-v4` |

### 为什么这么选

- 免费档：文本和视觉都在智谱官方免费价格表内，中文与结构化输出能力贴合考试场景；BGE-M3 免费、中文检索常用、固定 1024 维，能与当前 pgvector 维度（1024 / COSINE）对齐，避免换向量空间。
- 付费档：沿用现有阿里百炼 Qwen 生态，接入改动最小；`qwen3.8-flash` 已支持图片/文本/视频输入与结构化输出，可以把现有的「文本 / 视觉拆两个 Provider」合并为一个。

## 二、免费用户方案

### 首选组合

| 用途 | 模型 | 免费情况 | 关键能力 | 注意 |
|------|------|---------|---------|------|
| 文本 | `GLM-4.7-Flash` | 官方价格表免费 | 200K 上下文、结构化输出/JSON、文本输入输出 | 免费档并发低（约 1），高并发会限流 |
| 视觉/OCR | `GLM-4.6V-Flash` | 官方价格表免费 | 图片/视频/文本/文件输入，128K 上下文；OCR、复杂表格、跨页文档、结构化 JSON/Markdown | 免费档同样受限流 |
| Embedding | SiliconFlow `BAAI/bge-m3` | 官方价格页免费 | 多语言、中文检索常用、固定 1024 维 | 需确认硅基流动对该模型的 RPS/TPM 限制 |

### 备用（免费回退，禁止回退到付费模型）

- 视觉：`GLM-4V-Flash`（智谱完全免费图像理解模型，能力较旧）或 SiliconFlow `PaddlePaddle/PaddleOCR-VL-1.5`（免费，偏 OCR，需验证 OpenAI 兼容 chat 接口与结构化输出稳定性）。
- 文本：智谱/硅基流动上的其他免费文本模型，或 OpenRouter `openrouter/free`（作为低优先级兜底，见第五节）。
- Embedding：硅基流动 `bge-large-zh-v1.5`（免费，但维度为 1024 需核对；换 Embedding 模型必须整体重建向量库）。

## 三、付费用户方案（低成本优先）

| 用途 | 模型 | 参考价格（元/百万 Token，北京地域） | 免费额度 |
|------|------|------------------------------------|---------|
| 文本 + 视觉 | `qwen3.8-flash` | 输入 0.8 / 输出 2.7 | 100 万 Token / 90 天 |
| 专精 OCR | `qwen3.5-ocr` | 输入 0.5 / 输出 2.0 | 100 万 Token |
| 低成本 OCR | `qwen-vl-ocr` | 输入 0.3 / 输出 0.5 | 100 万 Token |
| Embedding | `qwen3.7-text-embedding-flash` | 0.125 / 百万 Token | 100 万 Token，默认 1024 维 |
| Embedding 备选 | `text-embedding-v4` | 官方推荐迁入 | 100 万 Token，默认 1024 维 |

可增加一个便宜的付费替代：

- 智谱 `GLM-5.3-Flash`：1M 上下文、多模态，约 0.8 / 2.8 元每百万 Token，适合作为付费档备用。

注意：

- 阿里百炼的「免费额度」不是永久免费，用完后按量计费；主要用于华北 2（北京）地域。
- 现有成本表部分按 USD 设计，接入费用表时必须统一币种与汇率口径。

## 四、降级与路由策略

- 路由键建议：`用户档位 + 功能 + 模态`。
  - 免费 + 文本 → `GLM-4.7-Flash`
  - 免费 + 视觉 → `GLM-4.6V-Flash`
  - 免费 + Embedding → SiliconFlow `BAAI/bge-m3`
  - 付费 + 文本/视觉 → `qwen3.8-flash`
  - 付费 + Embedding → `qwen3.7-text-embedding-flash` / `text-embedding-v4`
- 免费档只能在免费 Provider 内回退，**禁止静默回退到付费模型**，否则成本不可控。
- 付费档可向上回退：`qwen3.8-flash` / `GLM-5.3-Flash` → 更贵的 `qwen3.7-plus` / `qwen3.8-max`。
- 限流、失败率、重试次数统一交给现有成本控制层（`@RateLimit` + AI 调用记录）。
- Embedding 不做运行时随意切换；换模型必须整体重建 pgvector 索引，不同模型向量空间不能混用。

## 五、其他免费候选（可作为低优先级兜底）

| Provider | 免费情况 | 备注 |
|----------|---------|------|
| Google Gemini | 有免账单免费层，单模型 RPM/TPM/RPD 在 AI Studio 控制台内显示 | 国内访问/合规需单独评估；接入需 OpenAI 兼容适配（Gemini 原生协议不同，可走其 OpenAI 兼容端点） |
| OpenRouter | 约 17 个 `:free` 模型，可用 `openrouter/free` 路由 | 免费模型池会变动；必须只用 `:free`，混入付费模型会被计费 |
| Groq | 免费层约 30 RPM / 1000 RPD，单模型差异大 | 适合低延迟文本兜底，中文模型选择有限 |
| Mistral | 有「Free 模式」，不公开具体数值 | 中文能力弱于国产模型，不适合主力 |
| ModelScope | 每日约 2000 次免费调用，OpenAI 兼容 | 适合开源模型兜底，速度与稳定性需实测 |
| GitHub Models | 免费访问部分模型，约 15 RPM / 150 RPD | 需 GitHub Token，适合开发期小流量 |
| Cloudflare Workers AI | 免费约 10000 Neurons/天，部分模型已转付费计划 | 协议非标准 OpenAI，接入成本较高，不建议纳入主链路 |

## 六、接入成本与风险

- 接入成本低：本项目 Spring AI 走 OpenAI 兼容客户端（`LlmProviderRegistry` + `OpenAiChatModel` + `OpenAiEmbeddingModel` + `ApiPathResolver`），新 Provider 只要提供 `/v1/chat/completions` 与 `/v1/embeddings` 即可复现现有配置结构。
- 新增「用户档位 → 模型路由」是主要代码工作：目前代码只看到预算与 Provider 配置，免费/付费档的模型路由可能需要新增一个路由层（与现有 `LlmProviderRegistry` 对齐，不另起一套）。
- 风险：
  - 免费模型限流严格（智谱免费档并发约 1），批量导入/多线程 worker 下容易触发限流，必须配合排队、退避重试与明确报错。
  - 免费 Provider 的数据留存、是否用于训练需逐条确认，涉及学生试卷数据隐私。
  - 免费状态会调整，必须做成可配置 + 快速切换，不要把模型名写死在业务代码里。
  - BGE-M3 维度已由多来源确认 1024，但仍建议接入前用 1 条请求实测返回维度，避免与 pgvector 1024 不一致。
