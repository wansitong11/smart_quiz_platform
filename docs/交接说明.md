## 二、项目目标

把原「AI 面试官平台」改造成**面向高中生的在线刷题与测评平台**，学科为语文 / 数学 / 英语。

改造原则：**保留后端骨架，替换业务外壳，补上教育内核**。

保留不动的骨架（与业务无关的工程能力）：

- Redis Stream 异步任务：生产者/消费者模板、心跳、卡死任务恢复、`attempt_id` fencing token 防旧消费者写终态
- Redis Lua 脚本实现的可重复注解限流（Global / IP / User）
- `StructuredOutputInvoker` 结构化输出 + 重试 + 降级
- 统一评估引擎（分批评估 + 二次汇总 + 兜底），`common/evaluation/EvaluationReport` 的字段本身就是一份批改报告
- pgvector RAG 全链路 + RAG 评估数据集与基线（`app/src/test/resources/rag-eval/`）
- 多 Provider 注册与运行时切换、API Key 加密落盘
- Tika 解析 / S3 / PDF 导出 / SSE 流式 / WebSocket 语音 / Micrometer 埋点

## 七、阶段三设计：语文 / 数学 / 英语学科体系

### 设计原则

- 一个学科 = 一个 skill 目录（`skills/{subjectId}/`），目录名即 skillId
- 一个知识板块 = `skill.meta.yml` 中 `categories[]` 的一项
- 参考资料统一放 `skills/_shared/references/`，用 `shared: true` 跨学科共享
- `priority` 语义：`CORE` → 高频必考，`NORMAL` → 常规考点，`ALWAYS_ONE` → 每次必出

### 两个必须遵守的技术约束

1. **`ref` 路径只能用小写字母、数字、点、下划线、斜杠**（源码正则 `[a-zA-Z0-9._/-]+`）。**中文文件名会被静默丢弃**，资料文件只能用英文名。
2. **单个资料文件超过 3000 字符会被截断**（评估阶段上限 6000，多文件合计 12000）。资料要写成高密度知识点大纲，单文件控制在 2500 字符以内。

### 学科与知识板块

**语文（`skills/chinese/`）**

| --- | --- | --- |
