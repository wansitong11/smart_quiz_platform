## 一、这个项目是什么

把上游开源项目「AI 面试官平台」改造成**面向高中生的在线刷题与测评平台**（语数英）。

改造原则：**保留后端骨架，替换业务外壳，补上教育内核**。骨架（Redis Stream 异步、限流、
结构化输出、统一评估引擎、RAG、对象存储、PDF 导出、SSE/WebSocket、Micrometer）继续沿用。

主要产品线：

| 能力 | 入口 | 说明 |
| --- | --- | --- |
| 试卷分析 | `/papers` | 上传做过的试卷 → 结构化切题 → 整卷作答 → 一次交卷 → 批改报告（含按小节得分） |
| 扫描件识别 | `/papers` 上传区 | 扫描 PDF / 拍照 JPG/PNG → 视觉模型逐页转写 → 预览校对 → 确认后切题 |
| AI 出题练习 | `/interview*` | 按学科 + 难度 + 题量生成练习，逐题作答 + 批改 |
| 资料问答 | `/knowledgebase/chat` | 上传资料 → 向量化 → 检索问答（范围可选：全部资料 / 按分类 / 指定资料） |
| 资料库管理 | `/knowledgebase` | 资料上传、分类、向量化状态、重新向量化 |
| 口语练习 | `/voice-interview` | WebSocket 实时语音（ASR/TTS） |
| 练习安排 | `/interview-schedule` | 学习计划与考试排期 |

## 四、四个核心机制（改相关代码前必读）

### 4.1 试卷层级树（唯一数据源）

- 切题产出 `PaperTree`（`PAPER → SECTION → MATERIAL / QUESTION`），落在 `practice_sessions.paper_json`
- 扁平题目列表由 `PaperTree.flattenQuestions()` **运行时派生**，不落第二份
- `depth` / `leaf` / `meta` 由 `PaperTree.recalculate()` 回写；同级顺序按 `order`
- 批改上下文用 `PaperTree.contextOf(index)`（路径上的小节标题 + 材料原文）
- 前端按节点类型渲染（`components/PaperTreeView.tsx`）；答题卡按最近小节分段

### 4.2 题型与判分

- 题目统一用 `InterviewQuestionDTO`：`questionType`（SINGLE_CHOICE / MULTI_CHOICE / FILL_BLANK / SHORT_ANSWER / READING / WRITING / OTHER）、`options[{key,text}]`、`fullScore`、`referenceAnswer`、`keyPoints`、`scoringRubric`、`analysis`（解析）
- 客观题走 `ObjectiveAnswerGrader` **确定性判分**（不调用模型）；评语拼「你的选择 / 正确答案 / 解析 / 考点」
- 主观题走统一评估引擎；报告按分值折算卷面分（`utils/paperScore.ts` 与后端同口径）

### 4.3 资料分类与检索范围

- 分类表 `kb_categories`（code / name / subject_code / sort_order / is_system），资料用 `knowledge_bases.category_code` 关联；code 是系统标识，改名不影响历史数据与历史会话
- 会话范围 `rag_chat_sessions.kb_scope`：`ALL`（默认）/ `CATEGORY` / `SELECTED`；解析器在 `service/scope/`，检索层只认「一组 kbId 或空集合」
- 跨库召回：`topK × candidate-multiplier` 召回 → 每份资料保底 `per-kb-quota` 条 → 剩余按分数补齐 → 收口 topK
- 回答末尾追加「出处」块；资料提问计数按**实际命中的资料**归位，不按会话范围全量加

### 4.4 问答工具化（function calling）+ ChatMemory + 轨迹

- 两个工具（`service/tool/`）：`search_knowledge_base`（检索范围通过 `ToolContext` 隐式注入，模型不能改范围）、`get_conversation_history`（`ASC` 取最早 / `DESC` 取最近）
- 对话上下文由 Spring AI `ChatMemory` + `MessageChatMemoryAdvisor` 注入；`RagChatMemoryRepository` 是**只读适配**（读 `rag_chat_messages`，写操作空实现，落库仍由业务侧负责），窗口裁剪在读取侧按 `app.ai.rag.tools.chat-memory-max-messages` 完成
- 主流程**没有**规则式意图路由：模型按工具描述自行决定是否调用；预检索片段仍会注入作为保底
- 轨迹表 `rag_query_traces`（intent / outcome / tools_json / retrieved_kb_ids / top_score / latency_ms），榜单接口 `GET /api/rag-chat/traces/summary | /no-hit-questions | /unused-knowledge-bases`

### 4.5 图片试卷识别（视觉模型 → 文本 → 复用切题）

- 详细方案见 [`docs/design/复杂试卷识别与结构化-设计稿.md`](design/复杂试卷识别与结构化-设计稿.md)
- 入口 `POST /api/papers/upload`（1~10 个 PDF/JPG/PNG，合并为一份试卷）；旧 `POST /api/resumes/upload` 遇到无文字层 PDF 会自动转到这条链路
- 输入统一成 `Document → Page(行 + assets)`：PDF 用 PDFBox 取文字行与图片位置；DOCX 用 POI 顺序取段落与内嵌图片（不走视觉模型）；JPG/PNG 每张一页走视觉模型
- 页源判定不再只看字符数：图像覆盖率 >50% 且字符 <150、或字符 <120 且无题号，一律走识图（修复"第一页只有标题文字层导致正文丢失"）
- 结构化改为"模型标块类型 + 行号，后端按行切片建树"（`PaperStructureService`），不再依赖中文数字标题正则；支持 PART/SECTION/MATERIAL/QUESTION/SUB_QUESTION/BLANK，材料按位置归组
- 页面资源落 `paper_assets`：图形选项 `OPTION_ROW` 用墨迹投影切分（等宽兜底），题干图 `FIGURE`；`QuestionOption.assetId` 驱动前端图片选项
- 行内标记 `{{字}}` = 加点、`[[u:]]` = 下划线、`[[w:]]` = 波浪线；前端 `MarkupText` 渲染
- 页级状态表 `paper_pages`（source=TEXT/IMAGE、status、text、image_key、attempt），试卷状态 `practice_papers.recognition_status`：`PENDING → PROCESSING → NEEDS_REVIEW → EXTRACTING → READY`
- 逐页判定：PDF 有可信文字层就零成本直接用；抽不到/乱码/短页无题号才渲染成 JPEG 调视觉模型
- 视觉客户端独立：`LlmProviderRegistry.getDefaultVisionChatClient()`，独立缓存键 `:vision`、独立默认项 `app.ai.default-vision-provider`（默认 `dashscope-vl` / `qwen3.8-flash`），**不挂 SafeGuard／Memory／Tools**
- 所有模型客户端都设置 **callTimeout**（`app.ai.chat-request-timeout` 默认 5m、`app.ai.vision-request-timeout` 默认 2m），并把 SDK 的 `maxRetries` 设为 0，重试统一交给 `StructuredOutputInvoker`。只设 readTimeout 不够：HTTP/2 连接靠 PING 保活时 socket 不空闲，服务端迟迟不返回响应头会让调用永久挂住；SDK 内部再重试还会把"单次超时"成倍放大
- 识别只做"图片 → 保留版式文本"；切题仍走 `PaperQuestionExtractionService` 与默认文本模型
- 切题前置两步确定性规整（`PaperQuestionExtractionService`）：给整段无题号的大题补一个行首题号（如「一、看拼音写词语」「七、作文」），再把行首题号按出现顺序重排为全卷 1..N——否则每个大题内部重新编号的卷子会被去重成 1、2 两题
- 题号 → 页码不按数字映射（很多卷子每大题重新编号），而是用 `PageTextMerger.PageLocator` 按题干在合并文本中的位置定位，结果写入 `InterviewQuestionDTO.sourcePageFrom/To`
- 异步任务 `paper:recognition:stream`，与切题同构的条件领取、心跳、fencing token 与卡死恢复
- 页图存私有 S3（`papers/{paperId}/pages/{n}-{random}.jpg`），通过 `GET /api/papers/{id}/pages/{n}/image` 按归属鉴权读取

## 五、依赖与构建上的两个硬约束

1. **Spring AI 必须 ≥ 2.0.1**：2.0.0 的 `OpenAiChatModel$ChunkMerger` 用「分片是否带 id」判断工具调用是否为新调用，
   DashScope / DeepSeek 这类「续传分片不带 id」的厂商会抛 `NoSuchElementException`；2.0.1 改为按 tool call `index` 合并。
2. **编译必须带 `-parameters`**（已写在 `app/build.gradle`）：Spring AI 的 `@Tool` / `@ToolParam` 依赖参数名生成工具 schema，
   关掉后模型看到的入参会退化成 `arg0`。

## 六、本地启动

```bash
# 1. 依赖容器（PostgreSQL+pgvector / Redis / RustFS）
docker compose -f docker-compose.dev.yml up -d

# 2. 后端（必须在项目根目录启动，bootRun 会读取根目录 .env）
./gradlew :app:bootRun          # 默认 8080

# 3. 前端
cd frontend && pnpm install && pnpm run dev   # 默认 3000（可用 VITE_DEV_PORT 覆盖）
```

两个必踩的坑（README 也有记录，这里再强调）：

- 本机开着 HTTP 代理（v2rayN 等）时，JVM 会把 `localhost:9000` 的 S3 请求也发给代理，导致启动报
  「检查存储桶失败: Service Unavailable (503)」。给后端进程加 `NO_PROXY=localhost,127.0.0.1` 即可。
- 仓库路径含中文或空格时，Gradle **测试进程**会因类路径编码问题抛 `ClassNotFoundException`（编译不受影响）。
  跑测试前把仓库复制到纯 ASCII 路径（例如 `C:\work\smart_quiz_platform`）再执行。

## 八、数据与迁移

主要表（均已重命名为教育语义）：`practice_papers`（试卷/材料）、`paper_analyses`（切题摘要）、
`practice_sessions`（练习会话，含 `paper_json` 层级树）、`practice_answers`（逐题作答）、
`knowledge_bases` / `kb_categories` / `knowledge_base_questions`、`rag_chat_sessions` / `rag_chat_messages` /
`rag_query_traces`、`vector_store`、`oral_practice_*`、`study_plans`、`llm_provider_config` 等。

迁移注意：

1. **不兼容老数据**：`paper_json` 只认树结构；开发库可以直接重建（`DROP DATABASE` + `FLUSHDB`）。
2. **改过 `V1__init_schema.sql` 会触发 Flyway 校验和失败**。开发库的常规做法：手工把结构改到位（或用新 V1 重建），
   再把 `flyway_schema_history.checksum` 更新为启动日志里的 `Resolved locally` 值（等价于 `flyway repair`）。
3. **不要在应用运行时 `FLUSHDB`**：Redis Stream 的消费组会被一起删掉，消费者会刷 `NOGROUP`。

## 九、工程约定（摘自 `AGENTS.md`，务必遵守）

- 分层 `Controller → Service → Repository`；`@Transactional` 只放 Service 且范围最小
- 业务异常统一 `BusinessException(ErrorCode.XXX, "描述")`；对外响应统一 `Result<T>`，禁止返回 Entity
- 请求体用不可变 `record`；Entity→DTO 优先 MapStruct；构造器注入 + `@RequiredArgsConstructor`
- **LLM / S3 / 外部 HTTP 不得放在数据库事务内**
- 取模型统一 `LlmProviderRegistry.getChatClientOrDefault(provider)`；结构化输出统一 `StructuredOutputInvoker`
- Prompt 模板放 `app/src/main/resources/prompts/*.st`（StringTemplate）
- 限流用可重复 `@RateLimit`；线程池不要用 `Executors.newXxxThreadPool()`
- 代码 2 空格缩进、无通配符导入、日志用 SLF4J 占位符且异常放最后一个参数

## 十、已知坑清单（都踩过，别再踩）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 测试抛 `ClassNotFoundException`，但编译正常 | 仓库路径含中文/空格 | 复制到 ASCII 路径再跑测试 |
| 启动报 503「检查存储桶失败」 | JVM 把 localhost 请求走了代理 | 加 `NO_PROXY=localhost,127.0.0.1` |
| 启动失败：Flyway 校验和不匹配 | 改过 `V1__init_schema.sql` | 修 `flyway_schema_history.checksum`（见 8.2） |
| Redis 刷 `NOGROUP` | 应用运行时执行了 `FLUSHDB` | 重启应用重建消费组 |
| 前端 `listen EACCES 0.0.0.0:5173` | Windows/Hyper-V 把 5141–5240 保留成系统端口段，绑定直接拒绝 | 默认端口已改为 3000；用 `netsh interface ipv4 show excludedportrange protocol=tcp` 查看本机保留段 |
| IDEA 启动报 `Unable to start embedded Tomcat` | 多半是 `APP_AUTH_JWT_SECRET` 没注入（IDEA 不读 `.env`），其次才是 8080 被占 | Run Configuration 里补 `APP_AUTH_JWT_SECRET` / `APP_AUTH_COOKIE_SECURE=false` / `NO_PROXY`，或用 EnvFile 插件指向 `.env`；完整 `Caused by` 若为 `Port 8080 was already in use` 则先释放端口 |
| 识别停在第 N 页、状态一直 PROCESSING | 视觉请求卡在 HTTP/2 等响应头，且历史上没有 callTimeout | 已加 `app.ai.vision-request-timeout`（默认 2m）；重启后卡住页会失败并继续后面的页，可在预览页单独重试 |
| 工具入参变成 `arg0` | 编译没开 `-parameters` | 已在 `app/build.gradle` 固定 |
| 仓库根目录出现几百 MB 的 `java_pid*.hprof` | JVM 被强杀时生成堆转储 | 已在 `.gitignore` 忽略，可手动删除释放空间 |
| `git add` 报 `index.lock` 已存在 | git 进程异常退出留下 0 字节锁 | 确认无 git 进程后删 `.git/index.lock` |
