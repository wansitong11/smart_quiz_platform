## 3. 阶段三：Skills → 语文 / 数学 / 英语学科体系

这是痕迹最重、也最有改造价值的部分。`app/src/main/resources/skills/` 下 11 个方向全是计算机内容，其中 `ali-backend`、`bytedance-backend`、`java-backend-tencent` 更是明显的面试题库标记，必须整体替换。

### 3.1 设计原则

- **一个学科 = 一个 skill 目录**（`skills/{subjectId}/`），目录名即 skillId
- **一个知识板块 = `categories[]` 的一项**，它的五个字段（`key` / `label` / `priority` / `ref` / `shared`）就是知识点标签体系
- 参考资料统一放 `skills/_shared/references/`，用 `shared: true` 跨学科共享
- `priority` 语义映射：`CORE` → 高频必考，`NORMAL` → 常规考点，`ALWAYS_ONE` → 每次必出（如写作）

### 3.2 两个必须遵守的技术约束

改内容前先记住这两条，否则写出来的文件不被识别、或内容被静默截断：

1. **`ref` 路径只能用小写字母、数字、点、下划线、斜杠**（源码里的正则 `[a-zA-Z0-9._/-]+`）。**中文文件名会被直接丢弃**，资料只能用英文名。
2. **单个资料文件超过 3000 字符会被截断**（评估阶段上限 6000，多文件合计上限 12000）。所以资料要写成高密度知识点大纲，不是教科书正文，单文件控制在 2500 字符以内。

另外，`_shared` 目录被加载器显式跳过，不作为学科出现，只放共享资料。

### 3.3 学科与知识板块设计

按高考三主科（语文 / 数学 / 英语）设计，学段通过新增目录扩展（后续要加初中，直接复制三个目录改名即可）。

**语文（`skills/chinese/`）**

| category key | label | priority |
| --- | --- | --- |
| `MODERN_READING` | 现代文阅读 | CORE |
| `ANCIENT_POETRY` | 古诗文阅读 | CORE |
| `LANGUAGE_USAGE` | 语言文字运用 | CORE |
| `CLASSICS` | 名篇名句与整本书阅读 | NORMAL |
| `WRITING` | 写作 | ALWAYS_ONE |

**数学（`skills/math/`）**

| category key | label | priority |
| --- | --- | --- |
| `ALGEBRA_BASICS` | 集合、不等式与向量 | NORMAL |
| `FUNCTIONS_CALCULUS` | 函数与导数 | CORE |
| `SEQUENCES` | 数列 | CORE |
| `TRIGONOMETRY` | 三角函数与解三角形 | CORE |
| `GEOMETRY` | 立体几何与解析几何 | CORE |
| `PROBABILITY_STATISTICS` | 概率与统计 | NORMAL |

**英语（`skills/english/`）**

| category key | label | priority |
| --- | --- | --- |
| `GRAMMAR` | 语法与语法填空 | CORE |
| `VOCABULARY` | 词汇与词义辨析 | NORMAL |
| `CLOZE` | 完形填空 | CORE |
| `READING` | 阅读理解 | CORE |
| `WRITING` | 书面表达 | ALWAYS_ONE |

每个学科目录下需要两个文件，格式不能变：

- `SKILL.md`：YAML front matter 必须含 `name` 与 `description`，正文整段作为 persona 注入 Prompt
- `skill.meta.yml`：`displayName` + `display`（`icon` / `gradient` / `iconBg` / `iconColor`）+ `categories`

- [ ] **知识点标签体系**：章节树 + 知识点编码，题目挂载知识点（见 3.3）

- [ ] **学情看板**：知识点掌握度雷达图（前端已有 `RadarChart.tsx` 可直接复用）、正确率趋势、薄弱知识点 Top N
- [ ] **个性化推题**：按掌握度低 + 久未复习的知识点排序抽题；**复用现有抽题容量硬校验逻辑**（方向 → 知识点，难度不变）

### P1 — 有余力再做

- [ ] **批量批改任务**：复用 `AbstractStreamProducer` / `AbstractStreamConsumer`，实现"一个班的作业并发批改 + 单份失败重试 + 幂等 + 进度查询"
- [ ] **成绩单 / 学情报告 PDF**：复用 `PdfExportService`，替换模板
- [ ] **学习计划日历**：复用 `study_plans` 表与日历组件，做每日任务与打卡提醒
- [ ] **AI 答疑追问**：学生问"这题为什么错"，用 RAG 检索课程资料 + 关联知识点

### P2 — 差异化，可选

## 9. 执行顺序建议

按「能尽快跑起来看效果」排序，前四步做完产品形态就立住了：

1. 阶段一（品牌），半天内可完成，风险最低
2. 阶段三（Skills → 学科知识点），这是教育味最浓的一步，改完整个平台气质就变了
3. 阶段七 P0（知识点 + 错题 + 掌握度 + 推题），核心增量价值
4. 阶段四（Prompt），与阶段三配套
5. 阶段二（包名 + 表名），工作量大但机械，建议用脚本批量替换后逐个人工确认
6. 阶段五、六（前端与测试），跟着前面走
7. 阶段八（验证）

## 10. 面试讲述建议

项目名已经换成「智能刷题平台」，面试时不要念名字，直接讲问题：

- **异步批改流水线**：批量作业 → Redis Stream 拆任务 → 限流控制并发 → 单份失败重试不阻塞整批 → attempt 代次防旧消费者写终态 → 卡死任务自动恢复
- **掌握度与推题**：为什么用带时间衰减的加权正确率而不是 IRT（样本量要求、复杂度取舍），推题排序策略怎么定
- **RAG 答疑质量**：有评估数据集和基线报告，可以讲召回率、查询改写、TopK 与阈值调优的量化过程
- **限流**：Redis Lua 脚本 + 可重复注解，Global / IP / User 三维度

重要：**只讲你真正跑通过、能说出具体数字的部分**。仓库里的代码量（后端约 2.4 万行）是底气，但面试官会挑细节深挖，讲不透的模块不如不讲。
