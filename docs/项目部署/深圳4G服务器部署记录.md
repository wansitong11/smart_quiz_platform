## 五、已修复的部署坑

### 1. OSS 必须使用 virtual-hosted style

阿里云 OSS 的 S3 兼容接口不接受 path-style：

```text
SecondLevelDomainForbidden: Please use virtual hosted style to access.
```

因此新增 `app.storage.path-style` 配置：

- RustFS：`APP_STORAGE_PATH_STYLE=true`
- 阿里云 OSS：`APP_STORAGE_PATH_STYLE=false`

深圳生产配置当前为 `false`，并已通过真实 Put / Get / Delete 和分片上传探测。

### 2. Docker Hub 无法直连

新服务器访问 `registry-1.docker.io` 超时。已在 `/etc/docker/daemon.json` 增加：

```json
"registry-mirrors": [
  "https://docker.1panel.live",
  "https://docker.m.daocloud.io"
]
```

原有日志轮转、`live-restore`、`userland-proxy` 配置均保留。

### 3. `.dockerignore` 会误删后端 jar

根目录 `.dockerignore` 原先的 `**/build` 会让 `app/build/libs/app.jar` 不进入构建上下文，服务器构建时报：

```text
"/app/build/libs/app.jar": not found
```

已改为只排除 Gradle 中间目录和 `frontend/build`，保留 `app/build/libs/app.jar`。

### 4. RustFS 变量即使不启用也会被 Compose 解析

OSS 模式不启动 RustFS，但 Compose 仍会解析该服务。`RUSTFS_RPC_SECRET` 已改为非强制默认值。

### 5. Redis 容器上限与 maxmemory 冲突

4G 覆盖文件给 Redis 的容器上限是 `384m`，已将 `REDIS_MAXMEMORY` 调整为 `256mb`，避免容器内先 OOM。

### 6. 后端重建后前端 Nginx 仍缓存旧容器 IP

后端容器重建后 IP 会变化，前端 Nginx 只在启动时解析一次 `app`，会出现首页 200、接口 502 的现象。处理方式：

```bash
docker restart smart-quiz-frontend
```

后续凡是单独重建 `app`，都要重启或 reload `frontend`，确认 `/api/auth/me` 不再返回 502。
