## 1. 架构与流量路径

```
浏览器 ──443──> gateway(nginx，唯一对外，TLS 终止)
                  └─> frontend(nginx：静态资源 + /api、/ws 反代)
                        └─> app(Spring Boot 8080)
                              ├─> postgres(pgvector)
                              ├─> redis(限流 + Redis Stream 队列)
                              └─> rustfs(S3 对象存储)
                certbot(每 12h 尝试续期)
```

三个必须知道的细节：

1. **只有 gateway 发布端口**。app / frontend / postgres / redis / rustfs 都在 compose 内网 `internal` 里，
   postgres/redis/rustfs 额外绑了 `127.0.0.1` 端口，只为开 SSH 隧道用，公网访问不到。
2. **真实客户端 IP 只在请求头里**。gateway 和 frontend 两层 nginx 都追加 `X-Forwarded-For`，
   app 里 `request.getRemoteAddr()` 拿到的是网关容器 IP（`172.19.0.x`），所以注册配额等逻辑读的是
   `X-Forwarded-For` 第一段（`ClientIpResolver`）。
3. **Docker 必须关掉 userland-proxy**（`/etc/docker/daemon.json` 里 `"userland-proxy": false`）。
   否则连请求头里的来源 IP 都会变成网桥地址 `172.19.0.1`，「同 IP 24 小时最多注册 3 个」会退化成全站配额。

## 2. 前置条件

| 项 | 要求 | 说明 |
| --- | --- | --- |
| 服务器 | 2 核 / 2 GB 起，40 GB 盘 | 1 GB 机器跑不动（7 个容器 + JVM） |
| 系统 | Ubuntu 24.04 LTS | 文档命令按 apt 写；Debian 系基本通用 |
| Docker | Docker Engine 29.x + Compose v2 | 当前线上 `29.9.0` / `v5.6.0` |
| 域名 | 一个 A 记录指向服务器 IP | 证书签发前必须先解析生效 |
| AI Key | 阿里云百炼（DashScope）API Key | `AI_BAILIAN_API_KEY`，缺了应用起不来 |
| 本地环境 | JDK 25、Node 20+、pnpm 10、Docker | 构建在本地做，**不在服务器上编译** |

代码仓库：`https://github.com/wansitong11/smart_quiz_platform.git`（分支 `main`）。构建机器上先 `git clone` 再按 §6.1 出产物。

> **不要在服务器上跑 `./gradlew` 或 `pnpm build`**：后端编译要 2~3 GB 内存，
> 2 GB 的机器必然 OOM；前端构建也会把小机器压到换页卡死。服务器只做「复制产物进镜像」。

## 3. 服务器一次性初始化（新机器才需要）

以下命令都以有 sudo 权限的普通用户（线上是 `admin`）执行。

### 3.1 目录

```bash
sudo mkdir -p /opt/smart-quiz/{app/build/libs,frontend,docker/postgres,deploy/server,deploy/nginx/templates,certs,logs,backup/postgres}
sudo chown -R "$USER":"$USER" /opt/smart-quiz
```

### 3.2 swap（2 GB 内存必须加）

```bash
sudo fallocate -l 2G /swapfile
sudo chmod 600 /swapfile
sudo mkswap /swapfile
sudo swapon /swapfile
grep -q '^/swapfile' /etc/fstab || echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
swapon --show     # 期望看到 /swapfile 2G
```

### 3.3 内核参数：让 swap 真正参与换页

```bash
sudo tee /etc/sysctl.d/99-smart-quiz.conf >/dev/null <<'EOF'
vm.swappiness = 60
EOF
sudo sysctl --system >/dev/null
cat /proc/sys/vm/swappiness     # 必须是 60
```

> 为什么必须复核：这台机器上另有 `/etc/sysctl.d/99-swap.conf` 写着 `vm.swappiness=10`，
> 靠后加载的文件会覆盖前面的。`sysctl --system` 之后再 `cat` 一次，确认最终值是 60。

### 3.4 关掉 kdump，把 256 MB 还给系统

kdump 会通过 `crashkernel` 预留内存；2 GB 的机器被它吃掉 256 MB 后只剩 1.58 GB，
是 2026-10-15 整机 OOM 的直接诱因。

```bash
sudo systemctl disable --now kdump-tools 2>/dev/null || true
# 幂等：已经带了 crashkernel=0 就不要重复追加
grep -q 'crashkernel=0' /etc/default/grub || \
  sudo sed -i 's/^GRUB_CMDLINE_LINUX="\(.*\)"$/GRUB_CMDLINE_LINUX="\1 crashkernel=0"/' /etc/default/grub
grep '^GRUB_CMDLINE_LINUX=' /etc/default/grub   # 确认里面有 crashkernel=0
sudo update-grub
```

`crashkernel=0` **要重启才生效**。重启后确认：

```bash
grep -o 'crashkernel=[^ ]*' /proc/cmdline   # crashkernel=0
grep MemTotal /proc/meminfo                 # 约 1913952 kB（≈1.87 GB）
systemctl is-active kdump-tools             # inactive
```

### 3.5 Docker 配置

```bash
sudo tee /etc/docker/daemon.json >/dev/null <<'EOF'
{
  "log-driver": "json-file",
  "log-opts": { "max-size": "30m", "max-file": "3" },
  "live-restore": true,
  "userland-proxy": false
}
EOF
sudo systemctl restart docker
cat /etc/docker/daemon.json | grep -q '"userland-proxy": false' && echo 'userland-proxy: off'
```

| 配置 | 作用 |
| --- | --- |
| `log-opts` | 单容器日志最多 3×30 MB，避免日志吃满盘 |
| `live-restore` | docker 重启/升级时容器不跟着停 |
| `userland-proxy: false` | 保留真实来源 IP（见 §1 第 3 点），也少一个代理进程 |

### 3.6 云防火墙（阿里云控制台）

轻量应用服务器的防火墙只放行：**22（限制来源 IP 更好）、80、443**。
`5432 / 6379 / 9001` 绝不能放行——它们只绑在回环上，需要时用 SSH 隧道。

> 线上 `ufw` 是 `inactive`，iptables 默认 ACCEPT，也就是说**安全边界完全依赖阿里云控制台的防火墙**。
> 换机器/换云厂商时，这一步不能漏。

## 4. 服务器上到底放哪些文件

服务器**不克隆整个仓库**（避免 245 MB 的 jar、`.git`、构建缓存占盘，也避免误在服务器上编译）。
只同步这 10 个文件/目录：

```
/opt/smart-quiz/
├── docker-compose.prod.yml                  # 主编排
├── docker/postgres/init.sql                 # 首次建库时 CREATE EXTENSION vector
├── deploy/
│   ├── docker-compose.server.yml            # 低内存覆盖（内存上限、Dockerfile、回环端口）
│   ├── env.prod                             # 所有密钥与环境变量（600 权限，永不入库）
│   ├── health-check.sh                      # 巡检脚本
│   ├── server/Dockerfile.app                # 只 COPY 预构建 jar 的运行时镜像
│   └── nginx/templates/smart-quiz.conf.template   # 边缘网关配置（含证书路径、反代、超时）
├── app/build/libs/app.jar                   # 后端产物（本地构建后传上来并改名）
└── frontend/
    ├── dist/                                # 前端产物（本地 pnpm build 的整个目录）
    ├── Dockerfile                           # nginx:alpine + COPY dist
    └── nginx.conf                           # 静态资源 + /api、/ws 反代
```

`deploy/certbot/`、`certs/`、`backup/`、`logs/` 由运维过程生成，不属于代码。

## 5. 配置 `deploy/env.prod`

### 5.1 生成

```bash
cp deploy/env.prod.example deploy/env.prod
chmod 600 deploy/env.prod
```

### 5.2 必填项（缺一个容器就起不来）

编排里带 `${VAR:?…}` 的变量是**强制**的，缺失会在 `docker compose up` 阶段直接报错。

| 变量 | 线上当前值 | 说明 |
| --- | --- | --- |
| `DOMAIN` | `quiz.stonev2ray.top` | 只写主机名，不带协议 |
| `POSTGRES_PASSWORD` | *(随机)* | ≥24 位随机串 |
| `APP_STORAGE_ACCESS_KEY` / `APP_STORAGE_SECRET_KEY` | *(随机)* | RustFS 的 S3 凭证 |
| `RUSTFS_RPC_SECRET` | *(随机)* | RustFS 集群内部密钥 |
| `AI_BAILIAN_API_KEY` | *(真实 Key)* | 百炼控制台申请，注意设额度告警 |
| `APP_AI_CONFIG_ENCRYPTION_KEY` | *(随机)* | 加密运行时 Provider 配置里的 Key |
| `APP_AUTH_JWT_SECRET` | *(随机，≥32 字节)* | Access Token 的 HS256 签名密钥 |
| `CORS_ALLOWED_ORIGINS` | `https://quiz.stonev2ray.top` | 必须与浏览器地址完全一致 |

随机值生成：

```bash
openssl rand -base64 36 | tr -d '/+=' | head -c 40
```

### 5.3 建议项（除标注"待调整"外，线上就是这个值）

| 变量 | 值 | 理由 |
| --- | --- | --- |
| `TZ` | `Asia/Shanghai` | 日志与业务时间统一 |
| `POSTGRES_DB` / `POSTGRES_USER` | `smart-quiz` / `postgres` | 与 `application.yml` 默认一致 |
| `REDIS_MAXMEMORY` | `64mb`（**现网 96mb，待调整，见 §13**） | **必须小于 redis 容器的 `mem_limit: 80m`**，否则还没到 maxmemory 就被 cgroup 杀掉 |
| `REDIS_DATABASE` | `0` | |
| `APP_STORAGE_BUCKET` | `smart-quiz` | 应用启动时自动创建 |
| `APP_STORAGE_REGION` | `us-east-1` | RustFS 对 region 不敏感，填个合法值即可 |
| `RUSTFS_CONSOLE_ENABLE` | `false` | 生产关控制台；临时排查再改 `true` 并开隧道 |
| `AI_MODEL` | `qwen3.5-flash` | 默认模型，可在页面里给单个 Provider 覆盖 |
| `APP_AUTH_JWT_ISSUER` | `https://quiz.stonev2ray.top` | URL 形态，换值等于让所有人重新登录 |
| `APP_AUTH_BOOTSTRAP_ADMIN_USERNAME` | `admin` | 只在 `users` 表为空时创建一次 |
| `APP_AUTH_BOOTSTRAP_ADMIN_PASSWORD` | *(首次部署时设定)* | 同上，**之后改它不会改已有密码** |
| `APP_AUTH_REGISTRATION_ENABLED` | `true` | 自助注册开关；只给少数人用时设 `false` |
| `APP_INTERVIEW_FOLLOW_UP_COUNT` / `APP_INTERVIEW_EVALUATION_BATCH_SIZE` | `1` / `8` | 业务参数 |
| `JAVA_TOOL_OPTIONS` | 留空 | **不要填**，让 `deploy/docker-compose.server.yml` 里的低内存参数生效（填了会覆盖掉 `-Xmx448m` 那套） |

### 5.4 三个"填错会出事"的坑

1. **`APP_AI_CONFIG_ENCRYPTION_KEY` / `APP_AUTH_JWT_SECRET` 部署后不要改**
   - 换加密 Key：数据库里已存的 Provider API Key 全部解不开；
   - 换 JWT Secret：所有人被强制重新登录（可接受，但要知道）。
2. **`APP_AUTH_BOOTSTRAP_ADMIN_PASSWORD` 只在首次初始化生效**
   `AuthDataInitializer` 的判断是「`users` 表为空才建管理员」。已有账号时改这个值**不会**改密码。
   忘了管理员密码的复位办法见《运维速查.md》§9。
3. **`CORS_ALLOWED_ORIGINS` 必须和浏览器地址一模一样**
   少了 `https://` 或换了域名，登录接口本身能用，但 WebSocket/跨域场景会被拒。

### 5.5 低内存内存配额（`deploy/docker-compose.server.yml`）

| 容器 | 上限 | 说明 |
| --- | --- | --- |
| app | 832m | JVM：`-Xmx448m -XX:MaxMetaspaceSize=192m -XX:MaxDirectMemorySize=48m`（合计 688m，留 ~140m 给 JVM 自身/线程栈） |
| postgres | 224m | `shared_buffers=64MB`、`max_connections=30`、`work_mem=2MB` |
| rustfs | 176m | 峰值常贴上限，但 `memory.stat` 里 `anon` 只有 ~50m，其余是可回收页缓存 |
| redis | 80m | 配套 `REDIS_MAXMEMORY=64mb`、`noeviction` |
| frontend | 48m | |
| gateway | 48m | |
| certbot | 32m | |
| **合计** | **1440m** | 机器 1.87 GB，留 ~400 MB 给系统与页缓存 |

> 这套数字是 2026-10-15 整机 OOM（容器上限之和 1700 MB > 实际可用 1613 MB）之后重排的。
> **调整任何一项前，先保证"总和 < 整机 `MemTotal` − 400 MB"**，否则会重演宿主机 OOM。

## 6. 首次部署：从零到可访问

### 6.1 本地构建产物

在仓库根目录（Windows PowerShell；Linux/macOS 把 `.\gradlew.bat` 换成 `./gradlew`）：

```powershell
# 后端：JDK 25 由 Gradle toolchain 自动获取，产物是 app-0.0.1-SNAPSHOT.jar
.\gradlew.bat :app:bootJar -x test

# Dockerfile 固定读 app/build/libs/app.jar，先复制成这个名字
Copy-Item app/build/libs/app-0.0.1-SNAPSHOT.jar app/build/libs/app.jar -Force

# 前端：不要设置 VITE_API_BASE_URL（留空 = 同源相对路径，最省事也最安全）
cd frontend
pnpm install --frozen-lockfile
pnpm run build
cd ..
```

检查：`app/build/libs/app.jar` 约 235 MB；`frontend/dist/index.html` 存在且引用了 `assets/index-*.js`。

### 6.2 上传产物

```powershell
scp app/build/libs/app.jar hk:/opt/smart-quiz/app/build/libs/app.jar
scp -r frontend/dist hk:/opt/smart-quiz/frontend/
```

（`hk` 是本机 `~/.ssh/config` 里配了代理的别名；没有别名就用 `admin@8.210.200.94`。
国内直连该 IP 不通，必须走代理。）

首次部署还要把「§4 清单」里的编排/配置/脚本文件传上去。

### 6.3 服务器上构建镜像（只复制产物，几十秒）

```bash
cd /opt/smart-quiz

# 必须 legacy builder：这台机器上 BuildKit 偶发 "forwarding Ping" / 导出层极慢
DOCKER_BUILDKIT=0 docker build -f deploy/server/Dockerfile.app -t smart-quiz-app:local .
DOCKER_BUILDKIT=0 docker build -f frontend/Dockerfile -t smart-quiz-frontend:local frontend/

# 校验镜像入口没被写坏
docker inspect smart-quiz-app:local --format '{{json .Config.Entrypoint}}'
# 期望：["java","-jar","app.jar"]
```

### 6.4 证书签发前：先只起「不需要 80/443」的服务

首次签证书用 standalone 模式，需要**独占 80 端口**，所以先不要把 gateway 拉起来：

```bash
cd /opt/smart-quiz
docker compose -f docker-compose.prod.yml -f deploy/docker-compose.server.yml \
  --env-file deploy/env.prod up -d postgres redis rustfs app frontend
```

### 6.5 首次签发证书

```bash
cd /opt/smart-quiz
docker run --rm -p 80:80 \
  -v "$PWD/deploy/certbot/conf:/etc/letsencrypt" \
  -v "$PWD/deploy/certbot/www:/var/www/certbot" \
  certbot/certbot certonly --standalone -d quiz.stonev2ray.top \
  --agree-tos -m 你的邮箱@example.com --no-eff-email
```

成功标志：出现 `Congratulations!`，且 `sudo ls deploy/certbot/conf/live/<域名>/` 里有 `fullchain.pem`、`privkey.pem`。

### 6.6 起全量

```bash
docker compose -f docker-compose.prod.yml -f deploy/docker-compose.server.yml \
  --env-file deploy/env.prod up -d
docker ps --format '{{.Names}}\t{{.Status}}'
```

期望 7 个容器全部 `Up`，其中 app / postgres / redis / rustfs 带 `(healthy)`。

### 6.7 验收（每条都要过）

```bash
R='--resolve quiz.stonev2ray.top:443:127.0.0.1'; B=https://quiz.stonev2ray.top

curl -s -o /dev/null -w 'site=%{http_code} %{time_total}s\n' -k $R $B/      # site=200
curl -s -k $R $B/api/auth/me    # {"code":12002,"message":"登录状态无效，请重新登录"} = 后端活着且鉴权生效
docker exec smart-quiz-app ls -l /app/app.jar                               # 时间是你刚传的
docker exec smart-quiz-postgres psql -U postgres -d smart-quiz -c "select version, success from flyway_schema_history order by installed_rank desc limit 1;"
docker stats --no-stream --format '{{.Name}} {{.MemUsage}}'
/opt/smart-quiz/deploy/health-check.sh && echo 'health-check silent ok'      # 无输出 = 正常
```

登录一次（管理员账号在 §5.3），再打开任意业务页面确认能取到数据。

## 7. 日常版本更新（最常用）

### 7.1 标准流程

**本地**（构建 + 上传）：

```powershell
.\gradlew.bat :app:bootJar -x test
Copy-Item app/build/libs/app-0.0.1-SNAPSHOT.jar app/build/libs/app.jar -Force
cd frontend; pnpm run build; cd ..

scp app/build/libs/app.jar hk:/opt/smart-quiz/app/build/libs/app.jar
scp -r frontend/dist hk:/opt/smart-quiz/frontend/
```

**服务器**（备份旧镜像 → 重建 → 重启 → 验收）：

```bash
cd /opt/smart-quiz

# 1) 给当前镜像打个回滚标签（同一个 tag 覆盖前先留一份）
docker tag smart-quiz-app:local smart-quiz-app:prev 2>/dev/null || true
docker tag smart-quiz-frontend:local smart-quiz-frontend:prev 2>/dev/null || true

# 2) 重建（不是 --build，避免 compose 去跑 app/Dockerfile 的 Gradle 多阶段构建）
DOCKER_BUILDKIT=0 docker build -f deploy/server/Dockerfile.app -t smart-quiz-app:local .
DOCKER_BUILDKIT=0 docker build -f frontend/Dockerfile -t smart-quiz-frontend:local frontend/

# 3) 只重建这两个容器
docker compose -f docker-compose.prod.yml -f deploy/docker-compose.server.yml \
  --env-file deploy/env.prod up -d app frontend

# 4) 验收
docker ps --format '{{.Names}}\t{{.Status}}'
curl -s -o /dev/null -w '%{http_code}\n' -k --resolve quiz.stonev2ray.top:443:127.0.0.1 https://quiz.stonev2ray.top/
```

> **不要用 `docker compose up -d --build`**：主编排里 app 的默认 build 是 `app/Dockerfile`
> （容器内跑 Gradle 多阶段构建），在 2 GB 机器上必然 OOM。低内存覆盖文件虽然把它换成了
> `deploy/server/Dockerfile.app`，但显式 `docker build` 更容易看清在哪一步失败。

### 7.2 只改前端

```powershell
cd frontend; pnpm run build; cd ..
scp -r frontend/dist hk:/opt/smart-quiz/frontend/
```

```bash
cd /opt/smart-quiz
docker tag smart-quiz-frontend:local smart-quiz-frontend:prev 2>/dev/null || true
DOCKER_BUILDKIT=0 docker build -f frontend/Dockerfile -t smart-quiz-frontend:local frontend/
docker compose -f docker-compose.prod.yml -f deploy/docker-compose.server.yml \
  --env-file deploy/env.prod up -d frontend
```

容器名和镜像 tag 不变，但 `up -d` 会发现镜像 ID 变了，自动重建前端容器。

### 7.3 只改配置（`env.prod` / compose / nginx 模板）

```bash
cd /opt/smart-quiz
vim deploy/env.prod                                     # 或从本地 scp 覆盖
docker compose -f docker-compose.prod.yml -f deploy/docker-compose.server.yml \
  --env-file deploy/env.prod up -d                      # 环境变量变化会自动重建容器

# 只改了 nginx 模板时，重启网关即可（gateway 用 envsubst 在启动时渲染模板）
docker compose -f docker-compose.prod.yml -f deploy/docker-compose.server.yml \
  --env-file deploy/env.prod up -d --force-recreate gateway
```

### 7.4 只改数据库结构

**只允许新增** `app/src/main/resources/db/migration/V<新版本>__说明.sql`，
不要改历史迁移文件（Flyway 会校验和不匹配，应用直接起不来）。
新 jar 启动时自动执行迁移；迁移前先备份（见 §9）。

## 8. 回滚

```bash
cd /opt/smart-quiz

# 把上一版镜像改回当前 tag，再强制重建两个容器
docker tag smart-quiz-app:prev smart-quiz-app:local
docker tag smart-quiz-frontend:prev smart-quiz-frontend:local
docker compose -f docker-compose.prod.yml -f deploy/docker-compose.server.yml \
  --env-file deploy/env.prod up -d --force-recreate app frontend
```

> 前提是发布前执行了 §7.1 第 1 步的 `docker tag …:prev`。
> 数据库迁移**不会**自动回滚：如果新版本带了破坏性迁移，回滚镜像前要先从备份恢复数据。

## 10. 巡检与告警

`deploy/health-check.sh` 由 cron 每 5 分钟跑一次，检查四项：宿主机内存压力（PSI）、
各容器内存占上限、postgres 是否又重建集群、1 分钟 load。正常时**静默退出**。

安装（线上已装）：

```bash
chmod +x /opt/smart-quiz/deploy/health-check.sh
( crontab -l 2>/dev/null; echo "*/5 * * * * /opt/smart-quiz/deploy/health-check.sh >> /opt/smart-quiz/logs/health-check.log 2>&1" ) | crontab -
# 证书续期后让网关加载新证书（续期在 30 天前就会发生，每天 reload 一次足够）
```

脚本自己会读这个文件，不用改 cron。**线上目前没配，只写日志**。

```bash
tail -f /opt/smart-quiz/logs/health-check.log     # 正常时是空文件
```

## 11. 故障排查

| 现象 | 先查什么 | 处理 |
| --- | --- | --- |
| 改完代码没生效 | `docker exec smart-quiz-app ls -l /app/app.jar` | jar 没传上来或镜像没重建 |
| 页面 502 | `docker ps`、`docker logs --tail 100 smart-quiz-app` | app 没起来；看启动日志里的 Flyway/DB 报错 |
| 页面 200 但接口全 401 | 是否 https、Cookie 是否被丢 | `APP_AUTH_COOKIE_SECURE=true` 时 http 访问必然丢 Refresh Cookie |
| 部署后整机很卡 | `free -h`、`docker stats`、`cat /proc/pressure/memory` | 容器吃满上限 → 按 §5.5 的规则重新分配，别只调大总和 |
| 某个容器反复重启 | `docker inspect -f '{{.State.OOMKilled}}' 容器名` | 是 OOM 就调该容器上限，并从别处让出内存 |
| postgres 频繁 `all server processes terminated` | `docker logs smart-quiz-postgres | grep -c "all server processes terminated"` | 历史问题：客户端硬断连接 + 内存吃紧；巡检脚本会记录次数 |
| 证书过期 | `docker exec smart-quiz-certbot certbot renew --dry-run --no-random-sleep-on-renew -v` | 见下方说明 |
| 上传大文件失败 | 两层 nginx：gateway `60m`、frontend `50M`；后端 multipart `50MB` | 实际上限由最小的那个决定（当前 50 MB）；要调大就三处一起改，并留意内存 |

**证书续期自检**（线上实测通过，约 15 秒）：

```bash
docker exec smart-quiz-certbot certbot renew --dry-run --no-random-sleep-on-renew -v
# 期望结尾：Congratulations, all simulated renewals succeeded
```

> 注意两点：① 不加 `--no-random-sleep-on-renew` 时 certbot 会随机等待最多 8 分钟，看起来像卡死；
> ② 续期配置里 `authenticator = standalone`，但容器命令行用 `--webroot` 覆盖它，
> 依赖网关把 `/.well-known/acme-challenge/` 映射到 `deploy/certbot/www`（模板里已配好）。

## 12. 交给 AI 执行的清单

把本节连同 §0、§4、§5.5 一起交给 AI 即可。**按顺序执行，每步都有判定条件。**

**环境事实（不要自行假设）**

- 服务器 `8.210.200.94`，用户名 `admin`，部署目录 `/opt/smart-quiz`（不是 git 仓库）。
- compose 命令固定为：
  `docker compose -f docker-compose.prod.yml -f deploy/docker-compose.server.yml --env-file deploy/env.prod <动作>`
- 容器名固定 `smart-quiz-*`；compose 项目名 `smart-quiz-prod`；数据卷前缀同名。
- 端口：公网只开 22/80/443；5432/6379/9001 只听 127.0.0.1。
- 机器 2 核 / 1.87 GB 可用内存，容器上限之和 1440 MB（§5.5）。

**执行步骤**

1. **确认产物**：本地 `app/build/libs/app.jar` 存在且是刚构建的；`frontend/dist/index.html` 存在。
2. **上传**：`scp` 到 §4 指定的位置。
3. **备份旧镜像**：服务器上 `docker tag …:local …:prev`（app、frontend 各一次）。
4. **构建镜像**：两条 `DOCKER_BUILDKIT=0 docker build`；`docker inspect` 校验 app 镜像 Entrypoint 是
   `["java","-jar","app.jar"]`。
5. **滚动重启**：`up -d app frontend`；`docker ps` 里 app 必须变成 `(healthy)`（首次启动约 60~120 秒）。
6. **验收**：§6.7 的六条命令全部符合期望；`health-check.sh` 无输出。
7. **失败即回滚**：执行 §8，然后报告失败步骤与日志片段（`docker logs --tail 100 smart-quiz-app`）。

**禁止事项（踩过坑）**

- ❌ 在服务器上跑 `./gradlew`、`pnpm install`、`pnpm build`、`docker compose up --build`（2 GB 机器会 OOM）。
- ❌ `docker compose down -v`（会删数据卷，业务数据全丢）。
- ❌ 修改 `APP_AI_CONFIG_ENCRYPTION_KEY` / `APP_AUTH_JWT_SECRET`（除用户明确要求）。
- ❌ 修改已在线上执行的 Flyway 历史迁移文件。
- ❌ 把容器内存上限之和调到超过「整机可用内存 − 400 MB」。
- ❌ 把 5432/6379/9001 暴露到公网。

## 13. 当前已知的不一致（照本文执行前先看一眼）

1. **`REDIS_MAXMEMORY` 与容器上限不匹配**：线上 `env.prod` 是 `96mb`，而 redis 容器 `mem_limit` 是 `80m`。
   现在 Redis 只占 ~7 MB，暂时无害；但一旦涨到 80 MB，会先被 cgroup 杀掉而不是按 `noeviction` 拒绝写入。
   **建议改成 `64mb`**（本文 §5.3 已按 64mb 写）。
2. **CI 自动发布未启用**：`.github/workflows/deploy.yml` 依赖 ACR 与 `SERVER_*` secrets，
   且 `deploy/deploy-remote.sh` 假设 `/opt/smart-quiz` 是 git 仓库（当前不是）。
   现在的线上发布是**手工路径**（§7）。要启用 CI 需先补齐 secrets、把部署目录改成 git 工作副本，
   或在脚本里加"无 `.git` 时跳过同步"的分支。
3. **地域已核实**：实例元数据返回 `cn-hongkong` / `cn-hongkong-c`，即**阿里云香港**。
   `.github/workflows/deploy.yml` 里"部署到新加坡服务器"的注释是历史遗留——
   新加坡那台是 `47.84.95.219`（只跑代理，与本应用无关）。
4. **`docker-compose.server.yml` 里的镜像 tag 写死为 `:local`**：因此不支持按 commit 打多版本 tag，
   回滚依赖 §7.1 的 `:prev` 标签。要支持版本化发布，把 `image:` 改成 `${APP_IMAGE:-smart-quiz-app:local}` 即可（未实施）。
