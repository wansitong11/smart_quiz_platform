# 运维速查（香港生产环境）

日常只需要记住三件事：`ssh hk` → `sq ps` / `sq logs -f app` / `sq restart app`。

## 0. 环境一览

| 项 | 值 |
| --- | --- |
| 服务器 | 阿里云轻量应用服务器（**香港**），2 核 / 1.6 GiB 内存 / 40 GB 系统盘 |
| Swap | 2 GB（`/swapfile`，`vm.swappiness=10`） |
| 公网 IP | `8.210.200.94` |
| 站点 | https://quiz.stonev2ray.top |
| DNS | Cloudflare，`quiz` A 记录 → 上述 IP，**DNS only（灰云）** |
| 部署目录 | `/opt/smart-quiz` |
| 初始管理员 | 用户名 `admin`，密码在 `deploy/env.prod` 的 `APP_AUTH_BOOTSTRAP_ADMIN_PASSWORD` |
| 旧服务器 | `47.84.95.219`（新加坡，只跑 Xray 代理，与本应用无关，未改动） |

> **国内直连该 IP 不通**（阿里云香港这个 IP 段的路由问题），所以本机 `~/.ssh/config` 的 `hk`
> 别名配了 ProxyCommand，走本机 v2ray 代理（`127.0.0.1:10808`）。
> 依赖脚本：仓库内 `tools/socks-bridge.js`，实际使用的是 `~/.ssh/socks-bridge.js`。
> 如果哪天直连恢复了，把 `~/.ssh/config` 里 `Host hk` 的 `ProxyCommand` 那行删掉即可。

## 1. 架构与容器

```
Internet ──80/443──> [gateway] nginx（TLS 终止、跳转）
                        └─> [frontend] nginx（静态资源 + 反代 /api、/ws）
                              └─> [app] Spring Boot 8080（JWT + RBAC）
                                    ├── [postgres] pgvector
                                    ├── [redis]
                                    └── [rustfs]
                     [certbot] 证书续期
```

| 容器名 | 作用 | 内存上限 | 对外端口 |
| --- | --- | --- | --- |
| `smart-quiz-gateway` | 公网入口、TLS 终止 | 64m | **80 / 443** |
| `smart-quiz-frontend` | 前端静态资源 + 内网反代 | 64m | 无 |
| `smart-quiz-app` | 后端服务 | **900m**（2026-10-14 从 700m 上调，`-Xmx512m` + ParallelGC） | 无 |
| `smart-quiz-postgres` | 数据库（含 pgvector） | 256m | `127.0.0.1:5432` |
| `smart-quiz-redis` | 缓存 + Redis Stream 队列 | 96m | `127.0.0.1:6379` |
| `smart-quiz-rustfs` | 对象存储（试卷 / 资料原件） | 256m | `127.0.0.1:9001`（控制台） |
| `smart-quiz-certbot` | Let's Encrypt 续期 | 64m | 无 |

后三个的端口只绑在 `127.0.0.1`，**公网访问不到**，只用于本机隧道调试。

## 2. 快捷命令（强烈建议先配）

本机：

```bash
ssh hk                              # 登录服务器
ssh -L 15432:127.0.0.1:5432 hk      # 数据库隧道（另开窗口，用完 Ctrl+C）
ssh -L 9001:127.0.0.1:9001 hk       # RustFS 控制台隧道
```

服务器上（登录后执行一次，写入 `~/.bashrc`）：

```bash
echo "alias sq='cd /opt/smart-quiz && docker compose -f docker-compose.prod.yml -f deploy/docker-compose.server.yml --env-file deploy/env.prod'" >> ~/.bashrc
source ~/.bashrc
```

之后所有操作都短了：

```bash
sq ps                        # 容器状态
sq logs -f app               # 后端日志
sq logs --tail 200 gateway   # 网关日志
sq restart app               # 重启单个服务
sq up -d                     # 按当前配置启动 / 应用变更
sq down                      # 停止全部（⚠️ 千万、千万不要加 -v）
```

> `down -v` 会把数据卷一起删掉，等于把数据库和上传的文件全清空。

## 3. 日常检查

```bash
# 容器是否都健康
sq ps

# 内存与 swap（重点看 available 和 swap used）
free -h

# 磁盘
df -h /

# 各容器实际内存占用 vs 上限
docker stats --no-stream --format "{{.Name}}  {{.MemUsage}}"

# 站点自检（在服务器上执行，绕过 DNS）
curl -s -o /dev/null -w "HTTPS %{http_code}\n" -k --resolve quiz.stonev2ray.top:443:127.0.0.1 https://quiz.stonev2ray.top/
```

健康基线（2026-10-14 实测）：7 个容器合计约 850 MB（app 约 630 MB / 上限 900 MB），
主机内存压力 `some avg60` 接近 0，swap 几乎不使用。

### 3.1 自动巡检与告警（2026-10-14 加的）

`deploy/health-check.sh` 由 cron 每 5 分钟跑一次，检查四项：宿主机内存压力（PSI）、各容器内存占上限、
**postgres 是否又重建了集群**、1 分钟 load。正常时静默退出；超阈值时写日志并（可选）推送机器人消息。

```bash
# 日志（正常情况下文件为空）
tail -f /opt/smart-quiz/logs/health-check.log

# 手动跑一次（正常应无输出）
/opt/smart-quiz/deploy/health-check.sh

# 想验证告警链路：把阈值压到 0 再跑
PSI_THRESHOLD=0 LOAD_THRESHOLD=0 MEM_THRESHOLD=0 LOG_FILE=/tmp/hc-test.log \
  /opt/smart-quiz/deploy/health-check.sh && cat /tmp/hc-test.log
```

推送机器人：在 `deploy/env.prod` 里设置 `ALERT_WEBHOOK_URL`（钉钉/飞书/企业微信的群机器人地址），
脚本会自己读这个文件，不用改 cron。阈值可用环境变量覆盖（`PSI_THRESHOLD` / `MEM_THRESHOLD` / `LOAD_THRESHOLD`）。

## 5. 查看数据

> **为什么必须先开隧道**：数据库只绑在服务器的 `127.0.0.1` 上，公网完全不可达——这是有意的安全设计。
> 而 DBeaver 跑在你本机，两者不在同一网络里，所以必须先建一条 SSH 隧道，把本机的 15432
> "接"到服务器的数据库上（`-L` 里的目标地址是以**服务器视角**解析的）。
> 报 `Connection refused` 就是隧道没开，不是密码错。
>
> 原理、开放公网的风险、企业级做法对照，以及后续 6 项可实施的改进，见
> [生产访问与安全演进.md](./生产访问与安全演进.md)。
>
> ⚠️ 当前 GUI 客户端用的是 `postgres` 超级用户，**误执行 UPDATE/DELETE 没有兜底**。
> 建议按该文档的「改进项 3」建一个只读账号给 DBeaver 用。

### 5.1 数据库（PostgreSQL）

**命令行**：

```bash
ssh hk
docker exec -it smart-quiz-postgres psql -U postgres -d smart-quiz
```

常用 SQL：

```sql
\dt                                                     -- 所有表
\d users                                                -- 表结构
select id, username, display_name, status, last_login_at from users;
select id, code, name from roles;
select user_id, token_id, expires_at, revoked_at from refresh_tokens order by id desc limit 5;
select id, original_filename, analysis_status from practice_papers order by id desc limit 10;
select id, name, vector_status from knowledge_bases order by id desc limit 10;
\q
```

一行式（不进交互）：

```bash
docker exec smart-quiz-postgres psql -U postgres -d smart-quiz -c "select count(*) from users;"
```

**GUI 客户端（DBeaver / Navicat）**：

```bash
# 窗口 1：保持隧道不关
ssh -L 15432:127.0.0.1:5432 hk

# 窗口 2：取密码
ssh hk "grep POSTGRES_PASSWORD /opt/smart-quiz/deploy/env.prod"
```

| 连接项 | 值 |
| --- | --- |
| Host | `127.0.0.1` |
| Port | `15432` |
| Database | `smart-quiz` |
| User | `postgres` |
| Password | 上一步取到的值 |

### 5.2 RustFS（对象存储）

存放**上传的试卷原件**（`resumes/`）和**知识库资料**（`knowledgebases/`）。

**浏览器控制台**：

```bash
# 窗口 1：保持隧道不关
ssh -L 9001:127.0.0.1:9001 hk

# 窗口 2：取访问密钥
ssh hk "grep -E 'APP_STORAGE_ACCESS_KEY|APP_STORAGE_SECRET_KEY' /opt/smart-quiz/deploy/env.prod"
```

浏览器打开 **http://127.0.0.1:9001/rustfs/console/**（注意路径，根路径 `/` 会返回 403，那是 S3 API 的正常响应）。

**命令行（mc）**：

```bash
ssh hk
cd /opt/smart-quiz
AK=$(grep '^APP_STORAGE_ACCESS_KEY=' deploy/env.prod | cut -d= -f2)
SK=$(grep '^APP_STORAGE_SECRET_KEY=' deploy/env.prod | cut -d= -f2)
docker run --rm --network smart-quiz-prod_internal minio/mc \
  sh -c "mc alias set rs http://rustfs:9000 $AK $SK && mc ls -r rs/smart-quiz | head -30"
```

**磁盘卷**（只能看，别改）：

```bash
sudo ls -la /var/lib/docker/volumes/smart-quiz-prod_rustfs_data/_data
```

RustFS 有自己的对象布局，目录名是哈希过的，手工改动会导致对象损坏。

### 5.3 Redis

## 6. 发版流程

**前提**：这台服务器只有 1.6 GB 内存，**不要在服务器上构建**，必须在本地编译好再传。

```powershell
# ① 本地构建（在仓库根目录）
.\gradlew.bat :app:bootJar
cd frontend; pnpm run build; cd ..

# ② 传产物
scp app/build/libs/app-0.0.1-SNAPSHOT.jar hk:/opt/smart-quiz/app/build/libs/app.jar
scp -r frontend/dist hk:/opt/smart-quiz/frontend/

# ③ 服务器重建并重启（只会重建 app / frontend 两个镜像）
ssh hk "cd /opt/smart-quiz && docker compose -f docker-compose.prod.yml -f deploy/docker-compose.server.yml --env-file deploy/env.prod up -d --build"
```

改了编排或配置（`docker-compose.prod.yml`、`deploy/docker-compose.server.yml`、`deploy/nginx/templates/*`）时，同样要先把对应文件传到服务器再执行第 ③ 步。

**只改前端时，别用第 ③ 步整包发布**（它会连后端一起检查；重建前端只要一条）：

```powershell
scp -r frontend/dist hk:/opt/smart-quiz/frontend/
ssh hk "cd /opt/smart-quiz && docker compose -f docker-compose.prod.yml -f deploy/docker-compose.server.yml --env-file deploy/env.prod up -d --build frontend"
```

前端的构建上下文已经收窄到 `frontend/`（约 6MB，见 `frontend/Dockerfile`），几十秒就能重建完，
不会再把整包 235MB 的 jar 传一遍、也不会把 1.6G 的机器压出「健康检查误判」。
留意 `docker compose up --build` 会顺带检查依赖服务，机器正忙时可能因 postgres 健康检查超时而失败——
遇到就等负载回落再执行一次（或只 `up -d frontend`，镜像已经在时更快）。

**回滚**：镜像 tag 是 `smart-quiz-app:local`，没有版本历史。要回滚就重新传上一版的 jar / dist 再执行第 ③ 步。

**数据库结构变更**：只允许新增 `V<n>__xxx.sql` 迁移脚本，不要改历史迁移文件（会触发 Flyway 校验和不匹配）。发布前先备份。

## 7. 备份与恢复

```bash
ssh hk
sudo mkdir -p /opt/smart-quiz/backup/postgres

# 数据库全量备份（自定义格式，带压缩）
docker exec smart-quiz-postgres pg_dump -U postgres -Fc -d smart-quiz \
  > /opt/smart-quiz/backup/postgres/smart-quiz-$(date +%F).dump

# 对象存储卷备份
docker run --rm -v smart-quiz-prod_rustfs_data:/data:ro -v /opt/smart-quiz/backup:/backup alpine \
  tar czf /backup/rustfs-$(date +%F).tar.gz -C /data .
```

恢复：

```bash
# 数据库（先备份现有数据！）
docker exec -i smart-quiz-postgres pg_restore -U postgres -d smart-quiz --clean --if-exists \
  < /opt/smart-quiz/backup/postgres/smart-quiz-2026-10-11.dump

# 对象存储（先停 app，避免读写冲突）
sq stop app
docker run --rm -v smart-quiz-prod_rustfs_data:/data -v /opt/smart-quiz/backup:/backup alpine \
  sh -c 'rm -rf /data/* && tar xzf /backup/rustfs-2026-10-11.tar.gz -C /data'
sq start app
```

## 8. HTTPS 证书

证书由 `smart-quiz-certbot` 容器管理，每 12 小时尝试续期；续期后由 crontab 每天 03:30 重载网关。

```bash
# 查看证书有效期
docker exec smart-quiz-gateway ls -l /etc/letsencrypt/live/quiz.stonev2ray.top/
echo | openssl s_client -connect 127.0.0.1:443 -servername quiz.stonev2ray.top 2>/dev/null | openssl x509 -noout -dates

# 手工强制续期（一般不需要）
# 注意 --entrypoint：certbot 服务的默认 entrypoint 是续期循环脚本，必须覆盖掉
sq run --rm --entrypoint certbot certbot renew --webroot -w /var/www/certbot --force-renewal
sq exec gateway nginx -s reload

# 查看续期定时任务
crontab -l
```

## 9. 故障排查

| 现象 | 可能原因 | 处理 |
| --- | --- | --- |
| 浏览器打不开站点 | 国内到该 IP 段路由不通 | 先确认不是本机网络问题：用手机 4G 试；仍不行就在 Cloudflare 把 `quiz` 记录改成 **Proxied（橙云）** |
| 页面能开但接口 502 | 后端没起来 | `sq ps` 看 app 状态；`sq logs --tail 100 app` |
| 登录报"用户名或密码错误" | 密码错，或账号被禁用 | 用 admin 登录后在「账号管理」里重置 |
| 登录后立刻被踢回登录页 | Refresh Token Cookie 失效 | 确认访问的是 `https://`（http 下 Secure Cookie 会被丢弃） |
| 上传后一直"待向量化" | Redis Stream 消费异常 | `docker logs smart-quiz-app \| grep -i vectorize`；重启 app |
| 某个容器反复重启 | 触到 `mem_limit` 被 OOM 杀死 | `docker inspect smart-quiz-app \| grep -i oom`；把 `deploy/docker-compose.server.yml` 里对应的 `mem_limit` 调大 |
| 站点变慢 | 内存吃紧开始换页 | `free -h` 看 swap used；`vmstat 1 10` 看 si/so 是否持续非零 |
| 磁盘快满 | 日志/镜像/备份堆积 | `docker system df`；`docker image prune`；清理旧备份 |

排查内存相关的死机：

```bash
dmesg -T | grep -i -E 'oom|killed'      # 有没有进程被 OOM Killer 杀掉
vmstat 1 10                              # si/so 持续非零 = 内存不够
```

## 11. 服务重启与开机自启
